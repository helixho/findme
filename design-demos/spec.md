# FindMe 个人理解与持续对话 · 设计输入

## 当前定位与第一阶段目标（2026-10-30）

整体愿景是赛博分身；用户通过对话、学习、导入资料和后续反馈持续建设对自己的理解。界面既要让用户读懂当前认识，也要让这份认识进入开导、建议、诚实的挑战和下一次交流。需求依据见 [Overview](../docs/overview.md) 和 [BA](../docs/ba.md)，第一阶段范围及验收见 [阶段目标](../docs/delivery/phase-1-personal-understanding.md)。

- 当前认识按整体、专题及具体判断组织，保持来源、情境、反例、未知和变化原因可展开；综合交付不能由聊天记录代替。
- 可以从已有理解继续对话，也可以无历史直接开始。用户请求支持、建议或质疑时获得针对当前处境的回应，不要求每次先完成问答或生成报告。
- 新经历、学习回应和纠正需要显式反馈保存及处理结果；更新后的认识要在下一次相关回答中生效。原文、自述、理论主张和模型解释的区别通过内容表达清楚，不要求用户学习后台术语。
- 有来源的学术与方法知识按需要辅助问题理解；用户可以看到为什么与自己有关、有什么依据和局限。
- 首页按使用状态决定优先呈现（[ADR D30](../docs/adr.md#d30-日常交流优先的默认体验)）：有未完的讨论时先继续那件事及卡在哪里；刚完成首次梳理时邀请检查有范围的初步认识；普通回访时可直接说一件当前在意的事，或查看近期有意义的认识变化。整体认识在「当前认识」中保持可独立阅读。
- 沿用 B 方向及已确认的三入口，具体页面职责见 [信息架构](information-architecture.md)。不新增“蒸馏 Skill”或特定 Agent 的必经操作。
- 展示阶段的真实覆盖与能力。下述既有原型仍为虚构演示，不代表 HTML、截图、代码或后台已实现这些目标；正式页落地情况见[原型与正式页差异](formal-vs-prototype.md)。

## 既有阅读与纠正原型范围

- 用户已确认（原型阶段）：先看整体认识；核心阅读与纠正；品牌也重新考虑。日常默认体验已由 D30 改为按使用状态决定首页，本原型的内容顺序仍适用于主动阅读当前认识。
- 对象：个人使用的统一 Web App；手机优先，桌面适配，不做管理后台。
- 内容顺序：整体认识 → 专题 → 判断的解释、支持与反例、范围和未知 → 纠正 → 修订前后。
- 三版共用虚构案例：在自主安排、有明确目标的工作中投入；多人协作、职责不清时迟疑。既不推定普遍能力，也不把相关性画成因果。
- 纠正演示：从“协作时倾向退后”收窄为“职责不清时暂缓表达”；使用固定示例生成演示结果。自由输入只显示为待核验，不假装推理成功。
- 全部页面常驻“虚构示例”标识，无私人原话，无模型或服务请求。
- 三版尺寸统一：桌面 1440×1000；手机 375×812，首屏与整页截图；核心交互状态另截图。
- 产物：六格缩略图、三套单文件 HTML、截图、比较入口及简短说明。
- 设计原则：认识有上下文且可修订，因此布局必须容得下依据、未知和版本差异。
