# Account cloud runtime wiring

单节点自托管（网页、API、后台处理、PostgreSQL 与本地原档；服务器拉取源码并构建）见 [standalone/README.md](standalone/README.md)。下文保留既有 Cloudflare 运行组合，不作为单节点部署前置条件。

Account mode is the single runtime source (ADR D23 in `docs/adr.md`); source configuration does not establish live enablement. A temporary synthetic-account preview was exercised and has since expired and been removed; its verified scope is recorded in `docs/execution/c-series-activation.md`. The steps below govern production enablement.

仓库仅保留 `apps/app` 浏览器客户端；手机 H5 与桌面共用构建。`wrangler.app.jsonc` 继续托管 `apps/app/dist`；后端 `wrangler.jsonc` 移除旧 Web 资产绑定，仅处理既有 API、health 与 internal 队列路径，其他路径返回 404 且不创建数据库连接。独立客户端退役不删除后端、数据库或 migration。此次没有部署，线上旧页面不能据此记为已退役，实际切换仍须单独验证；依据见 [ADR D25](../docs/adr.md#d25-直接退役两个独立客户端统一使用-appsapp-浏览器入口)。

1. Follow [migration and compatibility](../docs/delivery/phase-1-migration.md): inspect the actual target journal, apply automatic migrations in journal order, including 0012 archive creation/exact-legacy adoption, then separately apply account access policy and role membership (migration does not enable RLS; the old supplemental archive DDL is not a normal fresh-install step). Local and historical isolated results do not establish current production migration state; read execution evidence and query the actual target when operating.
2. The explicit `packages/db/access/account-runtime.sql` defines the runtime/auth/identity group roles and Core RLS. It is intentionally outside the automatic migration journal because it changes access to existing Core tables. Do not grant all three roles to one shared login.
3. Configure separate runtime, identity and authentication database credentials. None may be SUPERUSER, BYPASSRLS or own protected tables. Hyperdrive query caching must be disabled for account-private versioned reads; use transaction-scoped connections.
4. Configure Better Auth base URL, secure secret and trusted origins. Registration is disabled until explicitly enabled, and enabling it requires a transactional mail delivery adapter. The interactive `owner-account:create` command can bind a new login to the already existing `findme-runtime/owner` self scope without sending mail; it does not create a new personal scope. It has not been run for a production account. Credential tables are not part of personal exports.
5. Existing Cloudflare Worker supports explicit `FINDME_ACCOUNT_MODE=1`, `HYPERDRIVE_AUTH`, `HYPERDRIVE_IDENTITY`, optional `FINDME_BLOBS` R2 and the existing queue binding. Node supports read/save plus an explicitly configured HTTPS queue dispatcher. Do not keep a MacBook process as the inference dependency.
6. Build the same App with `VITE_APP_AUTH_MODE=account` only when validation is authorized. Existing private/static entry remains available when this flag is absent. Same-site API/cookie origins are preferred; trusted-origin configuration is not an excuse to share credentials across unrelated sites.
7. Inference defaults off, profile and framework budgets default zero. Queue reads cannot invent authorization. A user explicitly confirms each diagnostic task's total cap; saved responses and ordinary reads never enqueue inference.
8. Keep prior deployments and migration snapshots. App/config rollback is separate from destructive data rollback; do not disable RLS while serving multiple accounts. Excluded sources can be restored for requalification; deleted originals are not reconstructed by the application.

No live credentials are included. Isolated migrations, account sessions, RLS and basic hosted reads/writes were verified within the recorded scope. The local App browser harness is described in the [test plan](../docs/delivery/phase-1-test-plan.md); it does not validate deployed entry/import parity/retirement. Real email delivery, deployed browser flows, paid queue/provider behavior, object round-trips and complete erasure still require validation. Any future isolated environment must be cleaned up by its exact resource inventory, never by production names.
