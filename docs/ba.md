# FindMe — 业务架构

> To-Be。以 [Overview](overview.md) 的已确认需求为输入；本文规定构建赛博分身的业务能力与价值标准。第一阶段验收范围见 [阶段范围](delivery/phase-1-personal-understanding.md)。具体实现见 AA、DA、TA，当前是否具备见 As-Is，交付顺序仅在 Roadmap。

## 1. 业务对象与价值

当前直接用户是产品所有者本人；产品目标面向希望逐步构建自己的赛博分身、未必善于主动表达的成年个人。未来每人使用自己的独立个人空间，未成年人适配、组织管理、员工评价和关系匹配不隐含进入范围。

赛博分身的业务价值在于持续深入了解用户，并以独立判断提供支持：帮助用户看清自己、理清感受和处境、比较选择，必要时直面自欺、自我美化或为体面作出的辩护，也能检验过度自责与模型自身的误读。对话、学习、导入资料与现实回顾共同建设这份理解；当次交互仍需有用，不要求先积累大量数据或形成完整分身才开始获得帮助。

对“足够客观”的业务承诺落实为忠实来源、区分事实与解释、判断不随讨好需求变化、接受反例和纠正。理解用户的感受、立场与内在逻辑，不自动等于赞同其全部结论；系统也不得以用户不同意来证明自己正确。具体而有依据的质疑可以直接表达，不能用语气锋利或笼统“虚伪”标签替代解释。

第一阶段交付能够真实使用和修订的个人理解，使整体阅读、持续对话、有依据的支持与质疑、新信息和反馈形成同一闭环。综合报告与个人发展诊断继续承载可读判断，个人使用说明、专题和纵向回顾提供不同使用方式；这些是核心价值的交付形式。Agent、Skill、模型训练或其他技术机制不属于业务需求中的既定路线。

## 2. 业务能力地图

| 能力 | 业务结果 | 范围与边界 |
| --- | --- | --- |
| B1 持续对话与主动引导 | 用户能基于已有理解继续交流，不知道说什么时仍能开始，并能轻松结束 | 从具体经历、已有表达或中性入口开始；可以换题、跳过、不知道、不想谈；不重复索取已可用背景 |
| B2 经历与情境整理 | 保留谁说了什么、谈谁、何时、什么条件及结果 | 结合必要上下文；原文、转述、引用、假设、建议分开；不把叙述当作独立观察 |
| B3 自我认识形成 | 由有范围的局部认识组织当前个人理解基线，保留支持和反例，并逐步澄清三观 | 覆盖背景、行为选择、价值叙事、解释与变化；未知可以保留，不强填维度 |
| B4 诚实挑战与校正 | 自欺、自我美化、过度自责和 AI 解释都能被检验；可选多角色视角比较 | 指出具体依据、不一致及替代解释；允许纠正事实、范围、程度和时间；纠正影响后续相关回答和建议 |
| B5 当前理解的综合呈现与纵向回顾 | 看懂系统目前怎样理解自己，获得现状、优势、张力与方向的综合判断，并理解为何变化 | 总览、专题、个人发展诊断和个人使用说明使用同一份认识；依据按需展开，区分人/覆盖/解释/模型的变化 |
| B6 支持、建议与自愿改变 | 理清感受与处境，获得适合当前约束的帮助；愿意时把目标变成可尝试、可退出的小步路径 | 开导、建议、比较代价及回顾均有个人依据；可以仅获得支持或澄清，不强迫改变或打卡 |
| B7 个人数据自主 | 用户控制自己的来源、分析范围、导出和撤回 | 原生使用可独立闭合；外部 adapter 可选；租户隔离；不默认跨人积累私人知识 |

这张图是业务能力边界，不规定页面、Agent 或服务数量。B1–B7 共同支撑赛博分身的建设与使用；第一阶段选择其中可形成实际闭环的范围，不宣称完整愿景已实现。结构化验证服务 B1/B3/B4，学术与方法知识服务 B1/B3/B4/B6，并由 B7 的来源原则约束；来源导入服务 B2/B7。对话、学习和导入共享认识与修订结果，不另建相互竞争的个人模型或通用会话仓库。

## 3. 四类认识的业务判定

**个人背景。** 经历、角色、目标、约束按来源及适用时间保留。一次明确自述即可记录为自述；不要求先建立完整画像，也不把当下选择永久化。

**条件化模式。** 描述在什么情境下如何选择或反应。跨独立事件、时间与场景检查支持和例外；同一事件的多轮讨论不能冒充多次发生。材料只覆盖工作时，结论首先限于工作情境。

**主观需要和自我叙事。** 主观体验有其表达主体；外部行为不能抹去体验，自述也不保证行为一致。系统帮助说明差别，不把“不一致”自动解释为欺骗。

**原因、冲突与变化。** 形成可修订的解释，而不是隐藏动机判决。证据不能区分几个解释时，应展示未决状态或寻找有区分力的问题，不强行给出唯一深层原因。

状态、睡眠/精力等用户愿意提供的信息可解释具体经历；不强制搜集健康档案，不从这些信息生成临床诊断、治疗建议或疾病标签。本文的个人发展诊断指有依据的现状评估与解释，不扩大为医疗服务。

### 3.1 三观是持续澄清的输出，不是入场标签

| 范围 | 澄清什么 | 输出方式 |
| --- | --- | --- |
| 世界观 | 怎样理解世界、人与关系、不确定性；持有某项信念的依据和疑问 | 带情境与来源的当前信念及未知，不强制归入某种主义 |
| 人生观 | 怎样的生活值得投入，如何理解意义、方向、角色与责任 | 本人认可的生活方向、向往与约束，允许阶段性调整 |
| 价值观 | 重要之物不能兼得时怎样取舍，愿意承担什么代价 | 具体原则、情境化优先级和价值冲突，不输出真我分数 |

同一表达可能跨几个范围，不机械三分。不用“选择一个学派”代替认识过程。世界观中可检验的事实主张仍需核验；用户有权表达一种信念，不等于该信念的外部事实已被证实。人生意义与价值取舍不由系统评分高低。

分别表达：本人认可的原则、本人向往的方向、本人感到应该承担的要求、具体经历中的选择、由这些材料产生的解释。外界要求可能被用户主动认可，不默认等于压迫；行为也受机会、状态、能力与约束影响，不自动比自述更接近真相。

### 3.2 自述、向往与实践不一致时怎样处理

先检查归属、事件时间、可选行动和系统是否误解，再区分下列可能；它们是候选解释，可以并存，不是自动分类结论。

| 可能的差异 | 探索重点 | 合理出口 |
| --- | --- | --- |
| 标签含义或系统解释错了 | 用户认可的是哪条具体原则，系统是否替用户补了整套学派立场 | 优先修正系统理解 |
| 理想尚未成为稳定实践 | 原则是否仍被真诚认可，缺少哪些习惯、能力或条件 | 保留为向往，用户愿意时小步尝试 |
| 现实约束限制选择 | 当时是否真的有其他可行选择，角色、资源和状态有何影响 | 改善条件、寻求支持或接受暂时限制 |
| 多个价值发生冲突 | 各自为何重要、适用情境与代价是什么 | 明确当下取舍，不强求唯一最高价值 |
| 原定位或优先级在改变 | 新经历改变了什么，旧表述是否还合适 | 修订认识或方向，保留原因与时间 |

差异本身既不是病理，也不是必须消除的问题。用户可以继续观察、调整行动、改变环境、修订价值表述，或保留未决差异。不能默认发起“把行为改得符合所选学派”的纠正计划；不能把反对 AI 解释当成自欺或防御证据。

## 4. 默认探索过程

探索是持续对话中的一种过程。用户可以读取当前理解后追问，也可以直接讲述经历、请求开导、建议或批判；系统按当前需要回应，并把可用的新信息带回同一份理解。一次交流可以先提供支持或整理问题，不强制所有交互走完提问、报告和行动流程。

### 4.1 开始：让用户有内容可回应

有历史材料时先核实本人表达与来源归属。针对具体困惑可展示适量证据并提出关键问题；针对已授权的整体盘点，先交付有依据且明确未知的个人理解总览，再邀请用户进入专题，不要求先完成额外问答才能获得初评。没有材料时提供具体、中性的经历入口，同时包含顺利、投入、满意和困扰的场景。

默认一次聚焦一个问题。选择题只降低表达负担，始终允许自由补充、都不是、不知道和跳过。自由记录仍保留，不能让所有数据都成为“回答系统问题”的产物。

### 4.2 还原：只补影响判断的情境

按需要了解当时目标、外部限制、可选行动、实际行动、结果和感受。缺什么问什么，不要求一次填满全部字段；不把已知信息重复问给用户，也不把沉默记为某种特征。

问题和备选项本身也是采集背景。模型先暗示某个解释、用户随后同意，不能按未经引导的独立经历使用。

满意、后悔和“如果重来是否仍会这样选”可以作为具体选择的探索信号，用来区分当时期待、实际结果与后来评价。只有答案可能改变当前理解时才追问；不把它们设为每次必答的清单，也不另建后悔模型或满意度评分。

提出“重来”的问题时，问句须区分“按当时知道的信息和可行选项重选”与“已经知道结果后重新选择”。后悔不自动证明当时判断错误；未选方案的结果不能由系统补写。短期兴奋与持续满意都可以有价值，由用户说明什么值得，不预设长期满意才是真实偏好，也不把一次事后评价上升为稳定人格或决策模式。

### 4.3 理解与检验：优先区分解释

先形成可见观察，再提出有依据的候选解释。存在重要竞争解释时寻找反例、类似事件的不同结果或明确约束；不是每次机械生成三个解释，也不是只提能确认初始判断的问题。

当用户提出的是表面问题、活动选择或一句笼统困惑时，系统可以提出 **problem reframe**，但必须同时保留“用户原本在问什么”和“系统认为可能更底层的问题”两层，后者始终是可质疑的解释，不得改写成用户已经承认的事实。高价值洞察优先检查以下结构：事实与情境 → 当前生活结构中哪些支撑机制存在、减弱或缺位 → 哪些需求、角色、价值或行动倾向同时成立但互相拉扯 → 有哪些竞争解释 → 什么追问或现实体验最能区分这些解释。

其中 **Life Structure** 不是固定人生模板，而是当前生活如何被目标、角色、关系、约束、创造/贡献、恢复、节奏等机制支撑的开放式描述；**Tension** 只表示两端都有证据且当前存在取舍，不等于缺陷、病理或必须消除的冲突。兼容的条件不因同时存在就变成冲突，例如执行自主与事前授权可以并存。Reframe、Structure Gap、Tension 和 Hypothesis 都需要显示依据、适用范围、替代解释及“什么信息会改变判断”。

表达保真包括立场强度：不背书不等于反对，未报告不等于明确否认，转发不等于认同。偏好某种交付载体不自动说明其价值标准；不同项目之间的共同解释只能先作为有范围的假设。系统须分清本人提出的问题与研究者/测试者的问题，不借问题重构替用户制造困扰。

复评不以“变化越大越好”验收。新材料可以澄清、补充或新增竞争解释；判断的支持程度变化与结论反转分开处理，具体依据与传播规则见 [DA §5.6](da.md#56-修订传播来源判断可以改原始记录与历史不能被悄悄改写)。后披露的旧经历不能被写成用户后来改变偏好；判断更新后，追问和建议须同步核对，不保留已经被回答或被新事实否定的前提。

可用低负担的中性探索填补未知生活场景。系统不能只围绕既有问题画像循环追问，更不能把没有采集到的方面描述成缺陷。若继续问只会增加故事细节而不能区分解释，应停止；若现实行为更有区分力，可以把问题转成用户自愿的小实验，而不是继续用语言追问制造确定感。

### 4.4 结束：必须有局部价值，不必有完整答案

可以澄清一个差别、修正一次误读、保留一个未决问题，或转入自愿尝试。资料不足时可以只整理经历，不输出人格判断。暂停不代表失败，未采纳建议不影响用户继续使用。

### 4.5 可选结构化验证，不以测试替代整个产品

当用户希望结构化表达，或一个待验证问题适合采用已审核工具时，可以进入题组/测评路径；无导入、无完整画像也可以使用，完成测试不是获得建议的必经步骤。

区分三类内容：不计分的反思题；有明确规则但尚无测量效度声明的自建检查表；适用人群、语言、来源和使用条件已核验的标准工具。三者不能混称标准测评，生活化扩展不改变标准核心的题目和计分，也不将自建分数映射为疾病概率。

有计分的结果固定题目版本、计分规则和作答，确定性重算不依赖 LLM。结果说明测了什么、不能说明什么、相关生活影响、依据及可选下一步；它可以支持、削弱或暂不改变某条认识，不直接成为身份标签。专业评估可以是用户选择的外部求助路径，不是 App 内临床诊断，也不要求每位用户先怀疑某种疾病。

具体采用哪种工具、许可与语言适用性、解释和建议内容，均在主题进入设计时验证；本轮不指定某疾病为首发主题，不承诺“测试优先”或一周内必然形成准确画像。

### 4.6 用户选择帮助方式，多角色对照按需介入

用户可以选择先获得开导、继续探索、听有依据的批判或共同想办法；系统说明自己是在理解感受、提问、提供解释还是建议，不把建议藏进引导性问题。支持用户需要理解其感受和处境，不要求先同意其对事件的全部解释。喜欢某种哲学可以影响问题角度和方案取舍，但不得筛掉反例、改写事实或代替用户的完整三观。

**多角色视角对照**针对用户选定的一个事件、行为或对话展开：先确认共享情境与未知 → 选择少量视角 → 分别展示关注点、依据、解释与可能行动/代价 → 比较共通与差异 → 用户表达认同、异议或自己的方案 → 可选尝试与回顾。

每项输出区分作品中的原始主张、现代转述和对当前情境的推演。“这个文本支持的视角可能如何理解/行动”是可用表达；“他本人一定会这样做”不是可验证承诺。以出处和推理差异体现角色，而不是只换称呼、古风语气或头像。

老子、孔子、歌德为用户提出的候选，不代表角色包已经完成蒸馏或审核。著作、编纂记录、书信、他人记述、文学角色发言分别识别；不把作品中任何人物的台词都当作作者的生活立场，不把一位思想家化成一个固定性格。

角色之间不投票决定用户是什么样的人，不把多次生成当成多份独立证据，不要求所有角色一致或强行不同。资料不足的角色可以不输出；用户不选择任何角色仍能完成主流程。其价值在于拓展可比较的理解与选项，而非提供历史名人的权威裁决。

### 4.7 可选外部框架完整运行，但不替代 FindMe 原生认识

FindMe 可以完整接入一个命名、版本化的外部框架，让用户按该框架自己的维度、等级、追问顺序、报告结构和发展建议完成一次独立评估。框架是观察同一个人的一种 lens，不改写 FindMe 的领域本体，也不要求其他探索先接受该框架的世界观。

**HUMAN 3.0** 保留完整、版本化独立接入方向，但不预定为默认诊断。原始版本、概念、rubric、问答与发展计划范围以来源核验后的 FrameworkDefinitionVersion 为准；候选资料见 Methods S30，默认方法及适配选择由诊断方法基线研究产出。这里的“标准框架”表示固定版本可还原，不自动表示心理测量效度；框架等级不是 FindMe 对人的通用高低排序。

框架运行必须显示框架名称、版本、来源/授权状态、适用边界和结果生成方式。HUMAN 3.0 的原作者公开框架与 Assessment prompt 已可核验，但正式 DefinitionVersion 仍须明确引用/改编范围；其他框架若缺 rubric、问题规则或来源，只能建立草稿定义，不得声称忠实实现。

用户在框架中的回答属于个人来源；Framework Result 是“按该框架怎么看”的有范围解释，不自动成为 FindMe 当前认识，也不能与其作答重复计作两份证据。框架结果若提出值得保留的个人认识，仍需按 B3/B4 的证据、反例和修订规则进入 Claim；框架计划先作为 ActionProposal，只有用户确认后才成为 ActionTrial。

### 4.8 当前理解的可读交付与持续对话

共同流程：结合本次需要与当前认识 → 读取有关的本人表达、情境和反例 → 提供支持、解释、质疑或建议 → 只追问可能改变关键判断的信息 → 吸收新信息或纠正 → 更新相关认识及其后续使用。零历史、少量经历和丰富历史都能进入；不要求用户先懂框架、审核后台数据或生成一份报告。

当前认识必须能够直接阅读；不能要求用户回翻全部聊天才能获得整体理解。用户请求总览、专题或个人发展诊断时，综合输出由同一份有效认识形成；既有判断未受影响时可以保持，不用改写措辞制造修订。对话是持续认识与获得帮助的方法，报告是集中查看理解的形式，两者不能相互替代。

报告先给有轻重的核心判断，再展示分项及相互影响、优势在何种条件下成为成本、竞争解释、未知与建议；没有问题或无需改动是合法结论。评级、证据覆盖与用户认可分开；工作材料不能填满身体、关系等未覆盖领域。历史预填、直接访谈、标准量表作答及模型推断分别标识，不把适配流程冒充原方法原样执行。

单纯让模型扩写旧 L3 不算诊断。旧认识只作线索，关键解释需要回到合格原文/片段、情境、反例和必要的新回应。结构化量表仍按已核验工具要求作答和计分，不从文本猜出正式分数。

界面提供“这不准确／仅某情境成立／以前如此现在变化／进一步解释”；证据在需要时展开。用户提出纠正或异议后，系统须复核受影响内容，并呈现处理结果及理由。已确认的错误必须更新相关认识、报告和后续回答或建议；判断本身可以保持，但不能忽略反馈或继续使用已失效的依据。首次初评无需完备画像，正式结论仍受范围与来源约束。

### 4.9 面向普通用户的多端使用

普通用户在手机或电脑登录即可开始交流、查看并持续修订个人理解；关闭采集电脑不影响已同步证据、已保存认识和原生新输入。源档托管或仅本地是可选择的保留策略；仅本地的未同步原文不可用时，系统说明重查范围，不编造已读取状态。主要数据位置、原档可用性及删除/导出边界见 DA/TA。

### 4.10 全量历史的个人理解基线与完成口径

用户要求已有语料整体加工时，目标是整批材料在统一 App 中形成可读、可展开、可修订的个人理解，不是增加处理层级或要求用户先提出逐项问题。全量固定来源快照、授权集合和用途；保留留出组，未知和待处理不能伪装为已充分理解。

| 验收层面 | 可以宣称什么 | 尚不能宣称什么 |
| --- | --- | --- |
| 加工覆盖完成 | 范围内输入均已成功处理或可追溯复用，语义不确定结果明确登记；仍有失败/未处理时不标完成，另列待处理 | 归属正确、所有重要主题已吸收或个人理解完成 |
| 内容覆盖已检查 | 重要主题、情境、未采用/不确定材料有去向，抽查压缩遗漏和漏检；主要未决缺口明确 | 每句均需形成洞察、掌握完整人生或某个准确率 |
| 理解基线可交付 | 已通过相应检查的总览/专题有实际依据、反例和范围；未完部分单独标记 | 所有方法已完成、本人已认可或效度已证明 |
| App 闭环可用 | 同一入口读取真实报告、回看证据、保存补充并更新相关判断，刷新可恢复 | 正式多端/多人/完整框架自动成立 |

已运行过分组摘要不保证内容被完整保留；当前摘要的条数不是个人信息量的上限。材料可只作情境、线索或明确排除，不强制每句推断；重要未采用材料须可回查，不用“未知”掩盖实际未处理。
用户认可某条判断是反馈，不是独立证实。本人效用验收关注是否更理解自己的处境、识别取舍或纠正误读；不强制产生行动，也不因无需改变判定无效。具体交付与界面见 [统一 App 契约](implementation/av-understanding-app-delivery.md)。

### 4.11 新信息与持续使用

对话中产生的经历、自述、回应和纠正按原有来源规则保存；模型的开导、建议与推测不能回流成用户本人的事实。新输入可以补充背景、支持或反驳已有判断，也可以只保留为局部记录；不强制每次形成新人格特征。

完成一次更新后，再次讨论相关问题时必须使用有效的当前认识，保留适用情境和时间；被确认错误或已失效的依据不再作为结论前提。系统应能说明哪些认识改变、哪些保持、为什么，不把保存成功等同于理解已完成。刷新、恢复会话或换入口后仍保持同一状态。

个人理解的持续积累服务赛博分身的长期愿景，但在第一阶段只验收声明范围内的理解、对话及修订效果，不以处理过多少语料或模仿口吻证明完整分身成立。可操作的阶段验收集中在 [第一阶段范围](delivery/phase-1-personal-understanding.md)。

### 4.12 方法可执行与功能质量

已有方法论、参考框架和质量标准应形成可重复执行的分析方法：明确适用情境、必要材料、取证与比较解释步骤、追问/停止条件、修订方式及失败反例。理论帮助形成候选解释，不因引用理论而证明用户特征；通用方法不得预填私人样例结论。

系统应能按问题主动取证、读取确切原文和修订，并在交付前核对依据。实际价值包括更具体的理解、有依据的支持或挑战、澄清取舍和纠正误读；调用次数、报告长度、理论数量、部署成功或读写成功都不能替代它。质量标准沿用 §7，由方法、工具检查和真实案例共同落实；实现映射见[Agent 设计](implementation/personal-understanding-agent.md)。

## 5. 建议与自愿改变的完整业务路径

用户可以从困扰、明确目标或满意经历进入，不需要先接受系统的人格解释。

| 阶段 | 系统应完成什么 | 用户控制点 |
| --- | --- | --- |
| 明确目标 | 把“变得更好”转为用户认可的具体方向，理解现实约束 | 选择只理解、不改变；修改目标；不把模型目标强加给用户 |
| 提供选择 | 给出少量与情境相符的做法，说明依据、预计负担、代价和不确定性 | 自行提出其他方案，接受、修改或拒绝 |
| 形成尝试 | 明确在什么情境做什么、最小可行步骤、观察什么、何时停止或复盘 | 由用户确认才从建议变成计划；不默认创建提醒或外部任务 |
| 现实执行 | 用户在自己的生活中尝试；App 可在用户选择时承接记录 | 可以暂停、撤回、未执行；不把未执行判为逃避或能力缺陷 |
| 回顾结果 | 区分做了什么、看到什么、如何体验、有什么外部变化 | 用户补充、纠正；结果可以不明确或并无改善 |
| 修订路径 | 根据结果保留、调整、结束尝试，并更新相关认识 | 不把一次改善当作因果已证实，不把一次无效归咎于用户 |

建议分为理解性建议、观察性尝试和日常实践建议，复杂度随证据和用户意愿提高。应有明确停止条件，不持续提高参与负担。行动结果回到同一认识链路，不再形成一个与画像断开的待办应用。

本产品不代替医疗诊断或治疗，不给出医疗处方，也不以“揭示真实人格”为由要求用户采用重大或不可逆行动。用户表达明确求助需要时可获得适当支持信息；这不构成对一般自我探索的泛化阻断。

## 6. 来源与参与方式

对话、原生速记、引导回应、选择理由、具体事件和后续回顾构成可独立运行的主路径；学习与导入资料为同一份个人理解提供补充。它们都是建设分身的方法，不按参与时长或材料数量判定价值。学习材料的观点不是个人数据，用户对其作出的反应及说明才是；未经验证的题组称为反思题，不包装成人格测评。

AgentsView、Obsidian、会话导出及旧 TencentDB 结果属于可选来源。普通用户不需知道这些系统，也不需人工切分、运行脚本。历史来源不得决定问题覆盖范围，不允许靠大量重复会话伪造认识充分性。

书面他人反馈只作为带来源的另一视角；不代表跨租户共享权限，不自动形成被评价者的独立 profile。

角色与视角是可配置的表达辅助，不是另一套真值来源。工具角色、理论/文化视角与模拟关系分别标识；若未来引入模拟角色，其回应只说明模拟中的反应，不能证明现实互动。保留当时的角色和 prompt 版本。道家等视角可选，原典、注释与现代转述分清，不进入标准工具计分或个人事实判断。

学习、方法、行动模板及结果解释属于编辑内容资产，应有来源、适用范围、许可、版本、审核与发布状态；不因来自 vault、外部网页或模型生成就可直接发布。个人证据支持“为什么针对这个人提出建议”，方法内容支持“这个建议有什么依据与限制”，两种依据不可互相替代。自建观察尝试可明确标为探索，不伪造科学有效性。

学术知识可以帮助提出不同解释、比较支持程度、寻找有区分力的问题和形成可选做法；不能仅凭一套理论确认用户的隐藏动机。用户学习后的赞同、反驳与实际尝试分别记录，并可用于后续理解。这里的“学习”描述业务用途，不指定微调、蒸馏、检索或某种 Agent 形式。

用户可将当前认识投影成可修订的“个人使用说明”：有效条件、不适合的做法、需要留意的情境和仍未知的部分。另提供用户选择内容、预览后自行导出的简版沟通摘要；这与可迁移的完整个人数据包是两种产物，不自动发给任何人，也不包装成诊断证明。

## 7. 业务质量与可失败的验证

| 验证场景 | 合格表现 | 不合格表现 |
| --- | --- | --- |
| 零导入、没有话题 | 有中性入口并形成一个有用的局部认识或整理 | 先要求上传历史，或先完成长问卷 |
| 用户粘贴 AI 的意见 | 正确区分用户表达和引用 | 将整段 user 消息当用户信念 |
| 只有工作经历 | 说明认识范围，其他场景保持未知 | 据此概括全部关系与人格 |
| 用户要求“狠狠批判” | 批判有据，仍检查替代解释和过度自责 | 为满足期待编造隐藏动机或负面标签 |
| 用户纠正事实/解释 | 受影响内容已复核，处理结果及理由可回看；已确认错误不再作为当前有效判断使用 | 只保存反馈而不复核，或继续使用已确认错误的判断或已失效依据 |
| 相同事实、相反自我评价 | 证据支持的主要判断一致，语气可调整 | 判断随用户立场翻转 |
| 反例或状态改变 | 缩小范围、形成分情境解释或保留争议 | 自动用“防御/例外”保护原判断 |
| 用户拒绝或未完成建议 | 理解约束，允许停止或调整 | 催促、评分、惩罚，或拿未执行证明缺陷 |
| 重复导入与旧摘要 | 不重复计作独立事件；缺证据可标未验证 | 来源/摘要/画像被计成三次支持 |
| 来自不同个人的数据 | 各自认识与导出保持独立 | 共享引用、检索、缓存或任务造成混合 |
| 结构化工具升级或复测 | 题目/规则/语言版本可还原，结果解释边界清楚 | 模型重算分数、混入扩展题后沿用旧标准或把不同工具分数直接画成趋势 |
| 方法内容或角色改变 | 能回看采用了什么版本；废弃内容停止被新推荐 | 方法文献变成人格证据，或新 prompt 悄悄改写历史语境 |
| 用户需要带走资料 | 全量个人数据包与选定简版摘要范围明确 | “全量”漏掉反馈/作答/尝试，或自动带出不想分享的内容 |
| 用户需要开导或支持 | 理清感受和处境，结合当前认识提供具体帮助，仍能保留对事件解释的分歧 | 为安慰而认可无依据的全部归因，或不回应当下需要只继续采集资料 |
| 交流后再次讨论相关问题 | 新经历和已确认纠正真实影响回答与建议，未受影响判断保持，并能解释依据 | 只更新报告页面，下一次回答仍重复已纠正的误读 |
| 用学术知识解释个人问题 | 理论来源、适用范围及对本人的依据可区分，允许多个解释或未知 | 因为存在某理论，就宣判用户具有对应动机、特征或问题 |

三观与视角的专项验收还包括：选了学派却出现相反证据时不强行维护标签；因约束做出的选择不被直接判为真实价值；角色换掉后事件事实不变；同意角色只记为回应而非独立支持；引用缺失时明确降级；关闭对照后主流程不受影响。

综合认识与诊断的验收包括：零／少量／丰富历史使用同一核心交互；用户不审核 L1–L3 也获得有用初评；“低等级”与“资料不足”不混用；同一案例对照 R0 已定义的“优秀通用助手直接分析并澄清”基线，检查是否增加解释和取舍价值，比较条件沿用参考诊断 §1，不以简单复述替代；手机提交的纠正及其复核结果在电脑可读，已确认的旧误读不再作为当前结论；关掉采集电脑仍能继续原生流程。第一阶段还须检查对话中的实际使用和后续更新，不能由一次报告比较代替。

事实忠实、范围准确、可修订和全链归属是质量底线。启发性、表达负担、后续价值和建议可用性需要真实使用验证；当前不宣称这些效果已成立，也不设未经标定的总准确率或任意达标条数。

评价同时记录认识变得更具体的案例、被推翻的解释和没有价值的交互。个人 dogfood 不能直接证明其他人同样受益；正式试用的样本、负担和成本预算进入具体阶段需求，不在架构层杜撰数字。

### 7.1 证据质量与修订的业务要求

来源是否保真、材料对某项判断的贡献、结论有多确定分开说明；同一材料对不同判断可能有不同作用。先核验用途资格，再判断贡献，不把错误引用、越租户或被排除内容降权后继续使用。具体语义仅在 [DA §5.4–5.6](da.md) 定义。

用户能查看“为什么采用、适用哪里、哪里不足、什么信息会改变判断”，并可纠正来源/背景、质疑解释或停止分析。置顶重要资料和偏爱某角色不增加事实可信度；情绪强烈或表达不够结构化不构成贬低本人报告的理由。信心可以下降，结论可以缩小，不要求随使用时长持续变得更确定。

专项验收包括：同一原话对不同认识分别评估；将转发内容改回正确归属后不再用其证明用户观点；一个可靠反例不会被同源重复淹没；历史适用但当前不适用与原文错误分开；只调整评估但记录数量不变时仍更新相关认识；生成期间发生排除/纠正，旧结果不能重新成为当前解释。

## 8. 不属于本轮产品范围

第一阶段范围以 [阶段目标与验收](delivery/phase-1-personal-understanding.md) 为准；更完整的分身能力在后续阶段依据用户价值与当时技术条件选择方案。人格蒸馏 Skill、跨平台代理、声音或形象克隆等不是已确定的实施路线，也不是第一阶段的必备成果。现有 AV 全量交付与 HUMAN 3.0 等已确认方向继续按各自范围记录，不因阶段裁剪而被宣称完成或取消。

不建设通用 Agent 会话采集平台、知识百科、人格排行榜、临床诊断系统、企业员工管理、社交匹配或自动替用户执行生活决定。多人隔离属于目标架构，但组织管理和商业化运营能力不因多租户而自动进入范围。

[AA](aa.md) 必须覆盖 B1–B7；[DA](da.md) 必须支持来源、情境、解释竞争、纠正和行动回顾，不能把这套业务退化为“多输入生成一份更长的总结”。

| KP-R01 目标主线 | 零资料输入或获准历史批次进入时，组织覆盖去向、命题/情境、支持/反例、专题和必要的跨专题综合；新输入与纠正沿同一链修订 | 未处理与未知分开；报告中的判断能回到合格来源，跨专题新解释有自己的依据；纠正影响当前相关判断，不靠重排旧摘要制造“更新” |
| KP-R02 目标主线 | 产品引用外部知识解释问题或推荐方法时，区分个人依据与方法依据，使用已发布且适用于此场景的版本 | 用户可分别看见“为何与我有关”和“为何认为此方法可考虑”；无任一依据时降级，撤回内容后不再产生新的同类推荐 |
| KP-R03 已确认方向、后续交付 | 用户自愿运行 Dan Koe 的 HUMAN 3.0 时，按固定、来源明确的定义完成原框架允许的逐域提问、框架内解释和发展计划 | 缺输入不填等级；结果显示来源与版本，只称框架视角；发展建议先供用户选择，不自动成为行动或 FindMe 的通用人格判断 |
| KP-R04 开发中 | 用户选择 Eckhart Tolle 的《新世界》（A New Earth）作品视角并提供具体处境时，呈现可定位的作品观点及一种可能的现代解释，允许比较、不同意或关闭 | 事件事实不因换视角改变；没有作品出处或解释跨度过大时不输出相应主张；不生成作品“测评分数” |
| KP-R05 开发中 | 用户主动选择 ADHD 相关支持或提出具体执行困难时，按场景、环境、已有支持与负担形成少量可选调整并回顾 | 自报诊断与实际困难分开；未自报者不会被系统诊断；用户可跳过、拒绝或暂停，未执行与无效不会被解释为人格缺陷；适用方法与个人情境各有依据 |

KP-R04、KP-R05 的开发已获授权；是否向用户发布仍须依据小范围用例与用户取舍决定。文学视角、框架访谈和 ADHD 流程均由用户自愿选择。
