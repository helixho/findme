# FindMe — 产品与架构总览

> 目标基线，按 2026-10-30 的用户澄清更新。本文定义产品方向与文档入口，区分整体愿景、第一阶段目标和已实现事实。实现证据见 [As-Is](as-is.md)，阶段范围见 [第一阶段](delivery/phase-1-personal-understanding.md)，推进顺序见 [Roadmap](roadmap.md)。

## 1. 产品命题

FindMe 以构建个人的**赛博分身**为整体愿景。用户期待的理想状态是“另一个硅基分身”：持续深入理解自己的经历、现实处境、价值取舍与思考方式，保持足够客观、独立的判断，能够开导、建议，指出自欺、自我美化和为了体面作出的辩护，并结合学术知识帮助自己理解、思考与选择。

“像我”体现为对个人背景、价值与内在逻辑的深入理解和连续积累；独立判断则要求系统能够审视用户当下的解释，也能够审视自己的误读。用户所说的“没有感情”落实为判断不被面子、讨好、维护既有立场或即时情绪牵动，同时仍要理解人的感受。足够客观是需要通过事实忠实、反例响应和纠正效果验证的质量目标，不是由 AI 身份自动成立的事实，也不承诺读懂一切隐秘动机或发现唯一、永久的真我。

**对话、主动探索、学习、导入语料及现实反馈，都是构建并持续修订分身的方法。** 方法在形成长期理解的同时，应当带来当下可用的帮助。自我认识、支持、诚实的挑战与自愿改变是核心价值；画像、个人使用说明、综合报告和个人发展诊断是呈现或使用这种理解的方式。这里的“诊断”指有范围的个人发展评估与解释，保留综合判断的交付责任，不作为产品最终目的。

第一阶段先交付可阅读、可对话、可纠正、能接受新信息并真实更新的个人理解。用户能直接看到系统目前怎样理解自己、围绕它继续交流、获得有依据的支持或质疑，并让补充和纠正影响后续回答。无需先理解或审核 L1–L3，也不把更多数据、更长报告或更像用户口吻当作成功标准。具体完成条件见 [第一阶段范围](delivery/phase-1-personal-understanding.md)；该阶段不宣称完整赛博分身已经形成。

Agent、人格蒸馏 Skill 或其他技术形态仅为可能的实现候选。需求以期望能力、体验与结果描述，具体方案在相关阶段依据当时技术能力、效果和成本评估；当前不规定“先蒸馏再由 Agent 执行”的必经路线。本人内测先验证本人价值，不把所有者的设备、历史数据量或工作方式当作普通用户的前提。

### 对外说明

FindMe 的愿景是成为你的赛博分身：长期了解你，又能独立审视与你有关的问题，帮助你更诚实、完整地认识自己。它通过对话、经历、学习和已有资料，逐步理解你在意什么、怎样作选择、身处怎样的现实条件；在你需要时提供开导和建议，也能有依据地质疑你的自我解释。你可以反驳、补充和纠正，它对你的理解应随之复核与更新。

第一阶段从可用的个人理解与持续对话开始。你可以先读当前的整体认识，也可以从一段经历或一个容易回应的问题开始，无需先准备大量资料、选择人格标签或擅长写日记。系统结合有来源的学术与方法知识，帮助你澄清行为模式、世界观、人生观和价值取舍；报告、专题和个人使用说明让这些认识便于回看。你可以继续理解、作出选择、尝试改变或暂时不变。当前阶段的能力和限制按实际实现说明，不将愿景当作已经实现的分身。

## 2. 已确认的需求与边界

- 当前首先服务产品所有者本人；未来的多用户是每个人独立认识自己的个人多租户，不是管理者评估他人，不做组织、员工管理或关系匹配。
- 持续理解要能够被使用：对话、当前认识、建议与质疑使用同一份可修订理解；纠正及新经历影响后续相关交互，而不只改变展示文案。
- 支持与诚实挑战同属核心价值。有依据时可以直指自欺、自我美化或为体面作出的辩护，同时检查过度自责、情境约束与模型误读；不能把用户不同意本身当作自欺的证据。
- 学术与方法知识用于扩展解释、问题和可选路径；个人判断仍须落回本人材料、处境与反馈。用户对知识的回应可形成个人来源，知识主张本身不直接证明用户具有某特征。
- 主动引导是核心能力。不能假设用户喜欢分享、能自由选题，或愿意持续写日记、完成长问卷。
- Agents sessions history 是重要但片面的输入。零历史导入也必须获得局部价值；电脑导出、离线预处理、Obsidian 或任何外部知识库不是普通使用前提。
- 批判性反馈同时检验自我辩护、自我否定和模型自身的解释；直接不等于羞辱，刺耳不等于真实，不同意不等于防御。
- 产品可以建议和支持用户尝试改变；用户选择目标、接受或拒绝建议、暂停或退出。认识尚不完整不妨碍提出明确限定、低负担的日常建议。
- 正式产品沿用账号制云端服务的现有设计，手机与电脑使用同一份权威数据和当前认识；无需 AV、CLI 或电脑常开。以 `apps/app` 为唯一浏览器客户端，手机 H5 与桌面使用同一套 React 19 + Vite 代码，无需原生安装包；独立 Web/小程序客户端按 [ADR D25](adr.md#d25-直接退役两个独立客户端统一使用-appsapp-浏览器入口) 退役。Android 原生包装已退役。桌面采集、本地计算、自托管是可选增强，不是本轮分发前提。该近期设计不预定未来分身的技术形态。
- 三观澄清是重要输出：世界观、人生观、价值观的认识可修订；喜欢某学派仅为自述、向往或探索偏好，不预先决定系统会发现怎样的用户。
- 支持针对事件、行为或对话主动开启多角色视角对照；这些是来自可回溯著作及受审核解释资产的思想视角，与构建用户本人赛博分身的目标分开，不宣称历史人物复活或用多数投票裁决用户。
- 产品与架构基线已建立，目标 Core 与 App 已进入实现及自用验证；具体完成情况见 As-Is，剩余阶段见 Roadmap。本文不将目标能力当作已完成，也不自动授权实际导入、迁移或部署。

## 3. 希望认识什么

| 希望认识什么 | 合理的产物 | 不能直接跨过去的推断 |
| --- | --- | --- |
| 我的经历、角色、目标和约束 | 有时间和来源的个人背景 | 当前角色不等于永久身份 |
| 我如何行动、选择和反应 | “在什么情境下，我通常怎样” | 一种情境的表现不等于普遍性格 |
| 我在意什么、如何理解自己 | 我的自述、价值取舍、自我叙事 | 自述不等于行为一定如此；行为也不能否定主观感受 |
| 我的模式为什么出现、是否在变化 | 有支持、有反例、可修正的解释 | 一个连贯的故事不等于原因已经查明 |

时间、情境和当时状态贯穿四类认识，不另设一套强制人格标签。本人报告的经历首先是本人报告；原文可核对，不能据此宣称现实事件已被独立证实。第三方只作为事件中的参与者，不自动建立第三方人格档案。

## 4. 产品主线与输入位置

主线是持续形成、使用和修订对用户的理解，逐步支撑赛博分身的目标能力。它同时支持两种入口：零/少量资料从具体问题或经历开始；已有丰富历史则先在已授权范围形成个人理解基线，再进入专题与关键追问，不要求用户先知道该问什么。两条路径共享情境、证据、解释、反例、纠正与自愿回顾；局部问答服务整体认识，但不能替代用户要求的全量盘点。

已有 AV 的内容覆盖、情境组织、个人理解总览/专题、旧判断校正及同一 App 内真实修订继续作为已确认交付保留，具体见 [整体理解与统一 App 交付](implementation/av-understanding-app-delivery.md)。第一阶段复用其中合格成果，并贯通原生对话、新经历、知识辅助及后续更新；阶段的有界可用覆盖与 AV 全量义务分别记录，不能用局部结果宣称全量已完成。全量始终以声明的来源快照为边界，不等于完整掌握整个人。

原生记录、引导回应、学习反馈、历史会话、旧洞察均可参与，但语义不同。历史摘要不冒充原文，用户认可不等于独立证实，模型此前输出不自我充当证据。知识材料提供视角和问题，不能直接充当用户特征的证据。

持续对话既是获得即时帮助的方式，也是形成认识和校正认识的过程。每次交互按其实际内容处理：表达可记录为表达，事件可补充情境，有依据时再形成或修订判断；不强制每轮对话生成新人格结论。学习包括补充有来源的方法知识，以及吸收用户回应和后续经历，不能将其直接等同于模型训练或某种蒸馏技术。

核心业务对所有输入使用统一的来源、归属、时间、证据与修订规则。可选 adapter 只承担外部格式适配和授权接入；核心不识别 vault 路径、特定 Agent 目录或某家数据库的层级命名。

可选的结构化验证、确定性计分和可配置学习/行动内容继续保留，不把产品缩成纯聊天。反思题与经过适用性核验的标准工具分开；需要计分时由固定规则执行，LLM 只解释。HUMAN 3.0 等外部发展框架可以作为命名、版本化的可选 lens 完整运行，但其等级和结论保持框架内语义，不替换 FindMe 原生认识，也不自动等同于标准心理测评。学习材料、方法建议另有内容来源与审核发布链，不能用个人故事代替方法依据，也不能用方法文献证明某个人一定如此。

工具角色与理论/文化视角可帮助表达，道家视角可作为其中一种自愿选择，不影响非选择者的完整使用。角色、提问和内容版本保留来源；模拟情境不自动等于真实生活表现。固定五目的地、目标配色等旧体验决定留待相关设计阶段复核，不作为当前业务/数据架构的前提。

### 三条信息线如何进入同一闭环

**个人证据**用于回答“对这个人的判断依据是什么”；**方法与理论内容**用于回答“怎样探索或尝试、依据与局限是什么”；**角色视角资产**用于回答“借另一种思想视角还能看见什么”。角色资产复用内容来源与发布链，不是第三套个人真值库。

个人材料 → 还原经历与情境 → 观察与候选解释 → 反例/纠正 → 当前认识与三观澄清 → 用户自愿选择 → 后续经历与回顾 → 修订认识。方法支撑探索与尝试；多角色对照是可关闭的旁路，既可帮助提问，也可帮助比较选择，不是每次必经关卡。

“我想借助的视角”“我目前认同的原则”“我向往的生活”和“实践中观察到的取舍”分开。用户认同某段角色回应只构成当次受到提示后的表达，不能反向证明该角色对用户的解释成立。

### 综合认识交付与方法论基线

用户阅读当前整体认识或请求个人发展诊断时，交付“核心判断 → 分项评估与相互影响 → 关键解释/替代解释 → 优先澄清或可选行动”。持续对话可直接支持、提问或建议，不要求每次先生成报告；综合认识仍须能够单独阅读，不能以聊天记录代替。每项判断可展开证据并纠正，资料不足的领域保持未知，不把证据稀少视为发展等级低。“蜜兔式分析”用于问题重构、情境、张力和竞争解释，不要求每次找到隐藏根因。

方法论研究按问题覆盖、方法谱系和同案例比较收口，形成方法论地图、方法组合决策、参考诊断与输入契约。既有研究按 R0 研究结论 的方法地图与局限复用；研究建议不等于真人效度已经通过。HUMAN 3.0 完整独立接入保留为可验收的框架交付，不能由原生摘要、单次历史适配或目录占位替代。原生基线可以先读，框架报告按自己的实际协议输入和完成度呈现。

## 5. 本轮采用的架构设计

以下是为满足需求采用的设计基线，不等于效果已经验证。

**业务架构先行。** BA 定义价值、能力、业务过程和验收；AA 定义支撑能力的应用职责、交互和契约；DA 定义对象、关系、来源与生命周期。AA 与 DA 互相校验，TA 再响应技术要求，不从页面或现有表结构倒推产品。

**轻量领域本体。** 在 DA 明确定义人、经历、情境、证据、认识、提问、纠正与尝试之间的语义；不默认引入通用人格本体、图数据库、RDF/OWL 引擎或大规模知识图谱。概念不等于物理表，逻辑关系不等于独立服务。

**本体与认识形成策略分层。** 本体回答“系统能表达什么”；Epistemic Policy 回答“在什么条件下可以继续问、形成观察/解释、扩大或收窄范围、保留未知或停止”。能确定执行的资格、版本、预算、重复与发布约束由规则/代码负责，LLM 只处理难以预先枚举的语义比较。Prompt 是受版本管理的实现资产，不是规则真源；质量依靠可追溯血缘与固定评测集，而不是生成长度或模型自报 confidence。

**可修订的认识核心。** 存在依据、范围、争议和版本的认识是建设分身的长期资产；画像、摘要、报告与趋势是可重建视图，对话及建议也消费同一份当前认识。来源质量、证据对具体判断的作用及认识置信度分别评估和修订；原始记录不静默覆盖，校正影响后续使用，不以一个总分代替真实性。旧 L1/L2/L3、八维网格和深析格式仅作为现有实现或兼容来源，不再定义目标架构。未来如何把个人理解用于更完整的分身能力，留待相应阶段选型和验证。

**个人多租户与多端。** 每个租户对应自己的独立数据空间和自我模型；账号是登录身份，不是人格类型。结构化业务数据以云端主数据库为真源，原始大档案可按授权托管或仅保留本地，证据可用性分别标识；设备缓存和索引不是第二份人格。语义见 DA，存储和运行边界见 TA。实际向第二个人开放前必须完成全链隔离验证。

### 理论如何分工，而不是混成一套人格算法

| 设计问题 | 主要参考 | 在产品中的职责 |
| --- | --- | --- |
| 怎样获得可信认识 | 证据核对、反例、可修订探究、条件化观察 | 约束判断依据和适用范围，不把摘要当真值 |
| 怎样让人愿意探索并自主选择 | 教练合作原则、MI/EPE、共同决策 | 组织提问、反馈和信息补充，不替用户确定目标 |
| 怎样理解反应并尝试改变 | 心理学与行为研究中的有限方法 | 提供经过来源筛选的候选做法，不声称软件实现完整治疗 |
| 怎样避免把一切归因于个人 | 角色、资源与社会情境视角 | 把关系、机会和现实约束纳入解释 |
| 怎样澄清什么值得追求 | 价值研究、哲学反思与来源化角色视角 | 帮助比较意义和取舍，不替用户决定唯一正确的人生 |

以上是 FindMe 对已有理论的职责化组织，不是已获验证的新统一心理理论；具体方法的范围和证据见 方法研究。

## 6. 产品成立条件

必须验证三个问题：没有历史导入时是否有局部价值；纠正和新经历是否真实改善理解及后续帮助；历史资产是否增加可核验的认识或减少重复说明。对话、学习和导入都按这类价值判断，不以积累量或过程完整替代结果。语言感染力、用户赞同、生成长度、调用次数不能证明分身已经形成。

第一阶段验证可用的个人理解与持续对话，为愿景积累证据。没有增益时，调整引导、判断方法或来源处理；不以愿景为理由扩大数据加工和用户投入。验证场景与退出条件由 BA、[第一阶段范围](delivery/phase-1-personal-understanding.md)和 Roadmap 定义，不在此设伪精确的“人格准确率”。

### 第一阶段对 H1–H3 的观察

H1–H3 延续既有价值假设，并按当前阶段覆盖零历史入口、已有资料阅读、持续对话与修订后的再次使用。旧 [owner-entry-v1](delivery/owner-entry-v1.md) 的 G1 基线仅覆盖已通过专题的首次阅读与纠正，是历史范围，不代表当前扩展范围已经通过验收。本人记录具体收获、误读或无效交互；系统保留对应依据、版本和处理结果。本人反馈与工程运行证据分别判断，没有亲历结果之前仍为待验证假设。

| 假设 | 第一阶段可观察的问题与方法 | 结论的边界 |
| --- | --- | --- |
| H1 引导让不善主动表达者获得局部价值 | 在无历史入口和已有认识入口分别检查：是否容易开始、能否澄清一个具体问题、是否可以自然结束；记录卡住、放弃和重复说明，不以轮次或字数代替效果 | 本人无历史路径的体验只能证明该路径对本人本次可用，不能推定陌生用户普遍受益 |
| H2 持续使用带来认识修订与可用帮助 | 对照补充或纠正前后的同一判断、依据与后续相关回答，检查支持、质疑或建议是否真实使用新认识；本人说明是否消除误读、帮助理解或仍无价值 | 一次可用修订不能证明长期收益、全面了解本人或完整分身能力；工程通过与本人认可分开 |
| H3 历史资料有额外价值 | 在声明的导入范围内，指出具体哪项历史依据带来新认识或减少重复说明；记录无增益、错误归属和仍须重述的实例，并能回到来源 | 只评价本次可用材料，不将合格专题等同于 AV 全量完成，也不推定其他资料或其他用户均受益 |
