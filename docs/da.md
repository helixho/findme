# FindMe — 数据架构与领域本体

> To-Be。本文是目标语义、关系和数据生命周期的唯一正文，不是当前 schema。现有表结构见 [As-Is](as-is.md)；技术落地见 [TA](ta.md)。本轮不生成 migration、不导入数据、不修改模型提示词。

## 1. 决策：启用轻量领域本体，不启用重型语义平台

“启用本体”在本项目中的含义是：对领域概念给出统一定义，对概念之间的关系规定语义和约束，使原生输入、导入、检索、解释、纠正与行动回顾表达同一件事。它不意味着创建一套覆盖所有人格/心理理论的分类系统，也不意味着所有概念各建一张表。

本体首先描述“关于一个人的认识是怎样形成和被修正的”，而不是宣布“一个人的本质由哪些固定标签组成”。四类认识范围来自 [Overview](overview.md)，不从八维网格或某个测评体系推导对象。

赛博分身的长期基础是有来源、情境、时间和修订关系的个人理解。对话、学习反馈、语料导入与实际经历都可以改变这份理解；开导、建议、质疑、总览与报告使用同一组当前认识。第一阶段以[可使用、可修订的个人理解](delivery/phase-1-personal-understanding.md)为交付范围，不创建一套与 Claim/ClaimRevision 并行的“分身人格库”。

Agent、人格蒸馏 Skill 或未来其他形式都可以是个人理解的使用方式，尚未选定。任何未来的摘要、配置或模型适配产物都需要明确其个人来源、适用范围与依据版本，能够受到后续纠正影响；不能凭“更像本人”把表达相似度当作认识正确性的证明。该语义要求不预定其存储格式或生成技术。

首个实现可以用现有关系数据库、类型化字段、关系表和受校验 JSONB 承载。RDF/OWL、图数据库、推理引擎和跨产品实体图谱不是本轮要求；只有实际查询、语义互操作或校验需求无法合理满足时再评估。

W3C OWL 2 将本体描述为概念、属性、个体及其关系的形式化表示；W3C PROV-DM 区分实体、加工活动、责任主体以及衍生、引用和修订。本文借鉴这些语义区分，不声称实现了 OWL 或 PROV 标准，也不把来源关系视为认识正确性的证明。参考见文末。

### 1.1 本体层与认识论层分开

本体层定义 FindMe 允许表达哪些对象、关系、状态与版本；认识论层定义系统如何使用当前个人理解回应用户、何时继续问或停止、何时形成有限认识及修订。两者相关但不能混为一套 Prompt：一个合法对象存在，不代表它足以支持某条 Claim；一个结构完整的模型输出，也不代表认识已经成立。

认识论层以版本化 **Epistemic Policy** 表达最小规则：先检查权限、归属、用途资格与版本；再判断当前不确定性是否值得打扰用户；最后对模型候选执行引用、范围、重复、状态和发布条件校验。能确定执行的规则由程序处理，LLM 只承担需要语义比较、替代解释与自然语言表述的部分。策略版本变化属于系统判断规则变化，不得伪装成用户本人发生了变化。

## 2. 本体必须能回答的问题

1. 这句话是谁产生的、谈谁、是原话还是引用/转述/模型输出？
2. 某条认识在什么情境、时间和状态下成立，哪些方面还不知道？
3. 哪些片段支持、挑战或仅提供背景；同一事件的多个表达是否被重复计数？
4. 历史洞察来自哪些旧资料；原文不可用时，哪些证据声明必须降级？
5. 用户纠正后，哪些认识、视图、任务需要更新；能否说明修订前后及原因？
6. 某个行动是建议、已接受、实际做过，还是结果尚不明确；是否改变相关认识？
7. 两个个人的证据、任务、缓存、导出能否保持严格独立？
8. 一条模型判断是否最终回到合格的来源，还是只在模型摘要之间循环引用？
9. 某项三观表述是用户认可、向往、感到应该如此，还是来自实践的观察/系统解释？选择视角是否被误认成真实人格？
10. 多个角色是否在解释同一个情境版本，各自依据哪些文本，哪些只是现代推演？用户回应是否被错误计作独立支持？
11. 本次 Ask / Stop / Claim 发布是在什么 Epistemic Policy、Prompt、Model 与输入指纹下产生；规则变化还是用户变化导致了结果差异？
12. 哪些判断是程序可确定执行的硬约束，哪些只是模型提出的语义候选；后置校验失败时是否会阻止候选成为当前认识？
13. 一次支持、建议或质疑使用了哪些当前个人认识与学术/方法内容；后续纠正是否会影响下一次回应？
14. 一项“学习”记录表示接触材料、表达认同、形成新理解还是实际尝试；是否被错误当成已具有某种价值观或行为？

不能回答这些问题的“标签加 JSON 摘要”不是本项目要求的本体实现。

## 3. 核心概念

| 概念 | 定义与语义边界 |
| --- | --- |
| Account | 登录身份及认证关联。不是人格、组织或被评价对象 |
| Tenant | 一个个人的独立数据空间与权限边界；目标是一人自用一个租户，不设组织层级 |
| SubjectProfile | 该租户认识自己的主体。目标阶段每租户一个本人主体；模型身份与登录 provider 解耦，不支持建他人 profile |
| SourceRecord | 不改写的输入来源单元或版本，可以是原生回应、速记、外部原文、历史衍生材料。其内容存在不意味着叙述的现实事件已被证实 |
| EvidenceSpan | 在明确来源版本上的片段定位，记录角色、归属、引用范围和摘录核对状态；片段本身不自动“支持”任何结论 |
| ExperienceEvent | 从一个或多个片段组织出的经历/选择/互动，包含发生范围、目标、限制、行动与结果；属于可纠正的事件表述，不是不可更改的事实 |
| ContextState | 某时段、某场景的状态与约束，可来自自述、观察或解释，必须标明依据；未知不补值 |
| Claim / ClaimRevision | 一条有明确语义及范围的认识与其版本，可为自述、观察或解释；有生命周期、证据状态、反例及修订原因 |
| EvidenceLink | 某个片段或来源认识版本与某个 ClaimRevision 之间的限定关系，区分支持、挑战、情境；使用资格、贡献及其评估可版本化修订，不赋予材料永久权重，见 §5.4–5.6 |
| ExplorationSession / QuestionRecord | 持续对话中的一次探索及所展示的问题、备选项/素材、提问意图与回应关联；普通回应可没有 QuestionRecord，双方作者和引导背景分别保留 |
| FeedbackRevision | 用户对事实、解释、范围、程度、时间或呈现的反馈及后续处理；认可不等于真值，异议不等于事实已被证伪 |
| Goal | 用户认可的理解或改变目标，带约束与可调整状态，不由模型私自确定 |
| ActionProposal / ActionTrial / ActionOutcome | 候选建议、经用户接受的尝试及实际结果，三者必须区分；未执行和无结论是合法状态 |
| ProfileView | 当前个人理解或某时点的可重建展示快照，引用明确的 ClaimRevision、范围与缺口；服务阅读与对话上下文，不是新的个人证据 |
| KnowledgeMaterial | 已发布学习/反思内容的使用视图，对应 ContentCard/ContentRelease 而非另一份事实源；用户反应另作为 SourceRecord |
| AssessmentDefinitionVersion / ScoringRuleVersion | 工具/题组定义、题目、语言、适用条件、许可与确定性计分版本；反思题可无计分规则 |
| AssessmentAttempt / AssessmentResult | 私人作答及由固定版本规则产生的结果，保留缺失/未完成/不计分状态；与个人解释分开 |
| FrameworkDefinitionVersion | 一个外部解释/发展框架的完整可运行版本：身份、来源/许可、维度、等级、rubric、提问协议、结果结构、计划协议、适用边界与发布状态；不是 FindMe 原生人格本体 |
| FrameworkRun / FrameworkResult | 本租户在某个固定 FrameworkDefinitionVersion 下的运行与结果；保留作答来源、维度结果、评估模式、未知和计划候选，整体保持 framework-scoped |
| DiagnosticRun / DiagnosticReportRevision | 按需进行的一次个人发展诊断及其报告版本：本次问题、输入模式、实际方法/框架版本、EvidenceSet、提问、分项/综合判断、建议、缺口、反馈及复评理由。它是个人理解的一种综合交付，普通对话无需先创建诊断运行；可复用 GenerationRecord/既有会话能力，不是第二套个人真值或综合人格总分 |
| SourceAvailability / RetentionPolicy | 原始档案托管、仅本地或不可用，必要摘录/上下文的已同步范围、校验与保留/删除约束；可用性不等于使用授权，保存位置不决定证据质量 |
| LifeStructureView / TensionView | 从当前 Claim/KnowledgeGap 投影出的开放式生活结构与张力视图；不拥有独立事实，也不要求预设固定人生维度 |
| ContentSource / ContentSourceVersion / ContentEvidenceChunk | 编辑内容的来源、版本和可定位片段；不是私人 SourceRecord/EvidenceSpan 的共享替代物 |
| ContentClaim / ContentCard / ContentRelease | 方法或知识主张、产品呈现与已审核发布集合；ContentClaim 不等于关于用户的 Claim |
| RoleDefinitionVersion / ActionTemplateVersion | 角色/理论视角与行动模板的可还原版本，保留来源和适用条件；使用它不构成真实行为或效果证据 |
| EpistemicPolicyVersion | 认识形成与探索决策的版本化策略：定义确定性 gate、LLM 允许承担的语义判断、后置 validator、停止/发布边界与评测版本。它不是人格理论，也不要求单独建表或通用规则引擎 |
| GenerationRecord | 处理活动的输入版本、输出、Epistemic Policy、模型/规则/prompt/validator 版本、输入指纹与时间；仅保留复核所需信息，不保存模型隐藏推理或在普通日志复制私人正文 |

概念层保留完整职责；物理实现可以合并低复杂度对象。新增概念必须服务上面的业务问题，不能因为“图谱应该丰富”而扩张。

### 3.1 个人证据与编辑内容是两条不同谱系

个人谱系描述“为什么对这个人形成这条认识”；编辑谱系描述“所引用的方法、理论或解释内容有什么来源和限制”。编辑谱系为 ContentSource → ContentSourceVersion → ContentEvidenceChunk → ContentClaim → ContentCard → ContentRelease；内容从候选/草稿经过审核进入发布，停用或撤回阻止新的推荐。

个人 Claim 与 ContentClaim 不合并。ActionProposal 可同时引用个人 Goal/经历/认识，以及方法 ContentClaim/发布版本；这只能说明建议依据，不证明该方法必然对这个人有效。自建观察性尝试可以标为探索，不伪造外部研究依据。知识库位置只是来源元数据，不参与发布授权或核心依赖。

公共内容不需要建立租户才能复用，但私人回应、测评结果、行动和反馈必须独立。面向公共素材的审核不是要求每条私人表达先经人工审核；小规模实现可使用版本化内容文件和明确发布清单，不以完整内容平台为前置条件。

“学习”分别保留两类语义：学术或方法知识成为可用内容，需要自己的出处与适用条件；用户阅读后的回应、认识变化与实践反馈成为个人 SourceRecord。接触、喜欢或认可某个理论不能直接证明其解释适用于本人，也不能将其全部观点写入个人价值观。相关内容版本和呈现刺激可由既有 QuestionRecord/GenerationRecord 关联，无需新增独立学习人格层。

### 3.2 测评、框架、角色与尝试保持版本

AssessmentAttempt 固定工具/题目/计分版本和用户作答；AssessmentResult 是确定性产物，不由 LLM 补齐缺答或编出分数。标准核心、生活化扩展、自建检查和不计分反思分别标识。复测不直接比较不同工具或未经确认可比的版本，分数不是疾病概率或总体人格准确率。

FrameworkRun 与 AssessmentAttempt 分开：外部框架可以包含 adaptive questioning、等级 rubric、综合解释与发展计划，不必假装成量表。FrameworkDefinitionVersion 必须声明 evaluation_mode = deterministic | semantic_rubric | none。确定性规则仍由程序执行；semantic rubric 只能在框架明确允许且 rubric 固定时由模型生成候选，并保留所用证据、理由与处理版本。

HUMAN 3.0 在当前设计中属于 Framework，而不是已确认的标准心理测评。其原始公开结构为 Mind / Body / Spirit / Vocation、Level 1.0–3.0 与 Phase，并进一步使用 Lifestyle Archetype、Metatype、Channels 等框架内概念；原作者公开 Assessment prompt 的实际输出区间为 30 天、90 天、6–12 个月，须与页面宣传段区分，见 R01。所有这些语义只在对应 FrameworkDefinitionVersion 内解释；Level 3.0 不自动成为 FindMe 的通用人格等级，不同框架的 level 也不能直接比较。公开来源可核验概念与 prompt，但内容复制、衍生发布和许可边界仍需在发布 DefinitionVersion 前确认。

AssessmentResult 或 FrameworkResult 都与生成它们的作答共享血缘，不独立重复计证。若其中的候选判断需要进入原生个人认识，仍需回到 Claim/ClaimRevision 的证据与范围规则；错误计分、框架定义更正或来源排除均应使相关结果/解释待复核，不能篡改旧作答。

QuestionRecord/SourceRecord 保存角色类别、具体 RoleDefinitionVersion、实际 prompt 版本及必要上下文；版本引用必须可解析到当时内容。模拟角色标明模拟场景，不能作为现实人际行为的直接证据。ActionTrial 固定用户接受时的建议和 ActionTemplateVersion，未执行与未观察到结果分别记录。

### 3.3 三观、价值差异与视角对照的语义

三观不是三张人格表，也不创建一个“真实价值观”字段。沿用 Claim/ClaimRevision，用受校验的语义分面表达 worldview（世界理解）、life_orientation（生活方向）、values（价值取舍）；同一表述允许多范围。自述、观察、解释等认识类型保持不变。

另区分本人认可的原则、向往、感到的要求、实践中观察到的选择及其推断来源。这些分面不互相覆盖：看到一次行为只能记录选择或候选模式，不能直接替换本人的价值声明；接纳一个原则也不能回写过去行为。感到的要求可来自他人或本人，两者均可能被自主认同。

世界观的“用户表达相信 P”与“P 在外部世界中为真”是不同论断。前者可由原话支持，后者仍需相应事实来源；对价值偏好的认可则不是外部真值判断。个人表达、事实核验、价值取舍不可放入同一个真假字段。

OrientationView 是 ProfileView 的三观呈现方式，不是另一份真源。价值差异作为有来源的比较/解释，关联声明、事件、约束、时间与替代解释；允许 unknown/contested，不计算道德、自欺或价值一致性总分。

PerspectivePreference 保存用户想借助的视角、可选自定义原则、作用范围及修改时间。选择记录可以成为“用户表达喜欢某视角”的证据，但其内容不能预置到当前三观；偏好与认识版本独立演进。

RoleDefinitionVersion 扩展为可回溯的视角资产：来源范围及版本、被解释对象（作者/作品中角色/学派须区分）、文本可支持的主张、必要限定及争议、现代情境推演规则、不能推断的事项、发布状态和回归样例。role skill 可以是这份声明式资产的一种封装，不是任意执行代码或修改个人事实的授权，也不预定本人赛博分身必须采用 Skill。

PerspectiveComparison 是本租户的生成记录/会话产物，可用 GenerationRecord 的受校验子类型承载，关联同一个事件或会话材料包、输入指纹、角色版本、文本依据、现代推演与用户回应。不要求立刻增加物理表或角色租户。

个人证据链解释“用户经历了/表达了什么”；角色来源链解释“该思想视角的文本根据是什么”。生成的角色回应既不是历史人物真实行为，也不是用户原始经历。其后用户的认同、反驳或选择保存为受到该内容提示的回应，不能洗成未经引导的独立发现。

### 3.4 外部框架与洞察分析不是平行真值库

FrameworkDefinitionVersion 是公共方法资产，FrameworkRun / FrameworkResult 是私人运行产物。框架结果回答“按这个版本的框架怎样解释当前材料”，不回答“FindMe 已经证明这个人就是这样”。框架定义变化与用户变化必须分开；旧结果仍可回看当时版本，但失去适用性或来源后不得继续冒充当前有效框架结果。

Insight Analysis Profile 是 Epistemic Policy / GenerationRecord 的一种受校验处理 profile，不新增 InsightFact、TensionFact 或第二套画像表。它的可解释输出可包含 presented_problem、problem_reframe、life_structure_gap、tension、candidate_hypothesis、alternative_explanations、discriminating_question 和 experiment_candidate；这些字段记录“对用户可见的分析结构”，不是模型隐藏 chain-of-thought。

持久化仍遵循现有语义：有足够依据且通过 validator 的 reframe、tension 或 hypothesis 成为 Claim/ClaimRevision；尚不能区分的替代解释成为 KnowledgeGap；现实验证建议成为 ActionProposal；LifeStructureView/TensionView 只投影这些当前对象。一个 tension 至少要能分别定位两端依据和共同适用范围，否则只能标为候选或未知。

Life Structure 不预置“健康/事业/家庭”等固定人生清单；它描述当前生活实际由哪些目标、角色、关系、约束、贡献/创造、恢复、节奏等机制支撑。某机制缺位只有在当前问题中有依据和解释价值时才形成 gap，未采集到不能等同于用户缺陷。

方法 Skill 是版本化的方法资产：引用来源、适用条件、操作步骤、产物规则与反例；不是个人 Claim，也不代替 FrameworkDefinitionVersion 或计分规则。方法蒸馏保留参考来源和采用/改写边界，不把满意样例中的私人结论转为通用规则。

Agent 运行记录按 GenerationRecord/现有任务元数据扩展，关联实际使用的 context、skill/reference、tool contract、harness、policy、model 与 validator 版本及来源/修订指纹。版本须可还原实际内容；不把每个版本名新增成独立领域表。会话和压缩摘要属于派生执行状态，不能重复计证；来源失效及删除传播同样覆盖其中的私人派生文字，恢复不能绕过资格复核。

### 3.5 诊断运行与报告版本

报告呈现特定时点、问题和范围下的综合理解；报告生成完毕不等于赛博分身已经形成，用户也无需每次生成报告才使用个人理解。

诊断分别固定所用方法/框架定义版本、访谈或历史预填适配协议、用户本次问题、输入覆盖与证据资格版本。输入模式至少区分零历史引导、少量事件、历史辅助访谈；每项判断保留实际来源，框架适配不冒充原协议原样执行。

报告包含核心判断、分项结果、相互影响、优势/限制、竞争解释、未知、验证问题及可选建议；框架等级与证据充分性是两个字段语义。各判断引用 ClaimRevision / FrameworkResult / AssessmentResult 或具体 EvidenceSet 版本；个性化解释仍须可追到合格个人证据。报告和由报告生成的摘要不成为自身独立支持。

运行进度、报告新旧/证据状态和用户态度分别保存：可有初评、等待补问、暂停、生成中和结束，结束不表示所有领域充分或本人已认可。来源、语境、方法或处理版本变化产生待复核/新报告，并说明是资料、本人状态还是解释方式改变。

历史报告保留当时版本关系；当前读取需实时应用排除、撤回与删除约束，不能为了可回放永久保留已禁止展示的正文。用户认可无需成为发布初评的前提，也不作为判断已获独立证实的证据。

### 3.6 覆盖记录、主题与个人理解基线

CoverageRecord 是对明确输入集合的加工和去向说明，可复用 GenerationRecord 的受校验元数据；至少可区分成功/复用/失败/未处理，以及个人证据/背景/排除/不确定/暂未形成认识等语义去向。两类状态不互相替代：未处理不是已经检查后的未知。覆盖分母与源版本固定，holdout 和允许用途独立标记。
TopicCoverage 是按主题组织的可重建视图：关联材料、候选经历/情境、当前认识、反例、未知、未采用原因及复核状态。同一材料可关联多主题，但源身份和独立性不能随主题重复；主题命名及合并是可修订解释，不构成固定人格本体。
个人理解基线不是新增真值库。它通过 ProfileView/DiagnosticReportRevision 组合特定版本的专题认识、跨主题解释、框架结果和覆盖说明；持续对话按本次需要使用其中的当前认识及依据。总览省略的细节仍由专题或源记录承接，不能从展示省略推定内容已无价值。
跨会话情境沿用 ExperienceEvent/ContextState，发生时间、披露时间、角色、约束与实际结果分开。会话相同、项目相同或文本相似不自动决定事件身份；关联未知时不增加独立支持，用户更正后更新相关主题映射及报告。
旧基线与新规则分别有版本，代码更新不会自动修改既有语义。对旧观点的保持、澄清、改类或撤回记录明确映射和理由；未重评的受影响结果不作为当前有效认识。分析/来源排除约束覆盖索引、专题、总览与历史展示，不只约束一次问答。
物理结构先复用既有来源、认识、报告和任务存储，以上概念不要求各建一张表；本机 JSON/JSONL 仅为受控交换/回放，不成为云端平行模型。业务完成口径见 BA §4.10。

### 3.7 输出分类与需要持久保存的信息

Overview的四类认识是阅读提纲，不是互斥人格维度或统一评分表。生活领域、认识内容、分析作用是三个独立角度：一条认识允许跨领域，在不同报告中承担不同分析作用，不因此复制成多条事实。

| 分类 | 语义与初始范围 | 保存边界 |
| --- | --- | --- |
| 生活领域 | 认知与情绪、身体与恢复、关系与归属、工作与创造、价值与意义、生活条件与资源 | 可多选、可扩展的覆盖/检索分类，不是六项评分；无资料标未知而非低水平。分类版本与依据可回溯 |
| 认识内容 | 背景/角色、目标、状态、行为模式、价值/偏好、自我叙事、能力/资源、约束、解释 | 单个可独立支持/修订的命题；现有Claim及相关对象优先承担。建议/计划/结果仍分属Action对象，不把它们都变成个人特征 |
| 分析作用 | 实际问题、重构、资源/限制、张力、解释/替代解释、反例、未知、下一验证 | 属于特定问题与分析版本中的引用角色；有依据的解释可指向ClaimRevision，未决解释关联Gap，建议关联ActionProposal，不新建平行画像 |

身体/恢复是本人身体状态，不能因材料使用“系统健康”等隐喻归入；人与AI的协作不自动证明现实人际关系质量；短期任务目标不等于人生方向。

**本人交互偏好**（提问形式、表达篇幅、信息呈现位置等）是“价值/偏好”类认识的一种，只来自本人明确表达或反馈，绑定来源并可修订；它规定后续对话怎样进行，每次任务装配上下文时使用，不作为人格特征的证据。健康相关信息区分本人报告的诊断、本人自我判断和系统解释三种来源性质，前两者按自述保存，系统解释不升级为诊断。不同框架可映射这些领域，但映射不宣称概念等价。

持久信息须能回答以下问题，物理字段与表在实现时选择，不按每一维新建一张表：

- **主体、内容与依据**：稳定主体/认识身份、内容类型、自述/观察/解释、来源版本与定位、支持/挑战/背景及独立事件组。标题、译文、摘要和用户认可均不增加独立证据。
- **情境与时间**：适用项目/角色/场景、事件或状态有效时间、精度与未知、采集时间分别表达；保留原文范围，不能把创建修订的时间当作人发生变化的时间。
- **关系**：证据→认识沿用EvidenceLink；认识→认识可表达限定、支持/挑战、竞争解释及跨域影响。绑定具体修订、范围与关系依据；“可能影响”不冒充已证明因果。关系本身可更正、失效，不只更新文本。
- **覆盖**：本次允许且实际使用的来源、选择/省略及原因、未处理与分析后未知分开。覆盖缺口不是人的缺陷。
- **本人反馈**：目标对象及确切版本、反馈原话、反馈用途分别保存。认可事实、认同解释、觉得有启发、建议有用、提出异议不能折叠为一个赞踩或真值；先保留本人表达，不臆测认可维度。不要求每次填评价问卷。
- **框架投影**：框架/定义版本、原协议或适配模式、实际输入集合、各域缺口、结果及其依据；等级、阶段、类型与数值仅在该框架内解释。框架结果与作答同源，不自动增加个人证据或覆盖原生认识。

主题归类不是认识去重键；同一命题跨领域只保留一个身份，新增独立事件可补充依据。身份、范围与命题不同者不能为去重强行合并。分析角色与生活领域可以变化，须区分分类/方法变化、证据变化和本人变化。

输出组合、框架取舍及已有/待补映射见[个人理解输出设计](implementation/personal-understanding-output.md)，既有发布、失效与租户契约继续适用。

## 4. 关系、基数与硬约束

| 关系 | 语义与约束 |
| --- | --- |
| belongs_to | 每项私人来源、认识、互动、尝试、任务及派生物归属于一个 Tenant；跨私人租户连接拒绝 |
| about_subject | 认识的对象明确为本租户本人；记录可包含第三方，第三方只作事件参与者。未知/混合归属不得默认全部属于本人 |
| span_of | EvidenceSpan 指向一个不可变 SourceRecord 版本及定位；原文缺失时不能伪造字符偏移或原文核验状态 |
| describes / has_context | 多个片段可描述同一 ExperienceEvent，一个事件可有多个状态/约束；同一来源也可支持多个事件，关联可修订 |
| supports / challenges / contextualizes | EvidenceLink 连接证据与特定 ClaimRevision，带适用范围与核验说明；提供情境不等于支持因果判断 |
| derived_from / quoted_from | 描述内容血缘或引用来源，不描述证据强度；原文、摘要、再摘要不能计作三份独立证据 |
| revises / supersedes | 新版本修订或替代旧版本；保留理由、时间与依赖。被修订内容不在后续检索中伪装成当前有效认识 |
| elicited_by | 回应与提问/素材关联；用户认同系统暗示不自动构成独立反例或支持 |
| responds_to / reviews | 反馈指向确切版本；结果回顾指向确切尝试，并可反馈到新的经历和认识 |
| proposes_for / accepted_as | 建议服务某个 Goal，只有用户接受才产生 ActionTrial；模型推荐不等于用户授权 |
| projects | ProfileView 投影一组认识版本和覆盖范围，不成为那些认识的循环证据 |
| assesses_under / reports_on | DiagnosticRun 固定方法与输入协议，DiagnosticReportRevision 引用特定认识/框架/量表结果及个人证据版本；报告中多次出现同一依据仍只有一条来源血缘 |
| computed_from / uses_definition | AssessmentResult 回指本租户作答和固定规则版本；公共定义可共享，结果/作答不可跨私人租户 |
| runs_under / interpreted_by | FrameworkRun/FrameworkResult 固定指向一个 FrameworkDefinitionVersion；定义可共享，运行、回答和结果属于私人租户；框架结果不是独立支持证据 |
| uses_content / generated_under | 建议/解释/引导保留内容发布、方法主张、Epistemic Policy、框架/角色/prompt/model/validator 版本与输入指纹；内容或生成血缘不等于个人事实的 supports |
| released_in | ContentCard 属于明确审核发布集合；撤回影响新使用，不能擦除历史使用过哪个版本的事实 |
| viewed_through / compares_under | PerspectiveComparison 指向相同情境包与各角色版本，角色只改变解释视角，不改变输入事实 |
| prefers / endorses / aspires_to | 分别记录想借助的视角、认可的原则与向往；不可从其中一项自动推出其余项或实际行为 |

每个 Claim 可有多个版本，只有被明确选为当前且未排除的版本参与当前认识；竞争解释可以并存，不以“只能一个 current”消除不同假设。版本替代用于同一认识的修订，不强行合并不同情境或不同解释。

内容血缘应可遍历到来源端；需要依赖链的解释不允许通过环形成自证。用户当前认可旧洞察，可新增一条“用户认可该解释”的自述，但不得据此独立证实旧洞察中的历史事件或深层原因。

## 5. 时间与语义状态

### 5.1 时间不混用

分别表达发生时间/时间区间、用户报告时间、系统接收时间和认识生成时间；认识另有适用时间范围。缺失发生时间保持未知或区间不确定，不使用导入时间代替。记录时区、时间精度与解析来源，避免给模糊回忆伪造精确日期。

对修订至少保留“当时认为何时成立”和“系统何时得知/修改”。这是逻辑上的双时间需求，不强制采购时态数据库，也不要求所有字段都有完整双时态实现。

对过去选择的当前满意/后悔评价，区分所评价的事件时间与评价发生时间。“如果重来”的回答属于带信息条件的反事实自述，不是实际发生的替代事件，不能增加独立经历数，也不能证明未选方案的结果。

### 5.2 来源、认识状态和用户态度分开

认识至少区分来源方式（原生/导入/模型产生）、断言依据（可见文本/本人报告/外部报告/解释）和类型（自述/观察/解释）。可见文本中的沟通行为，与文本里报告的现实行为不是同一种观察。

生命周期可采用 candidate、current、superseded、withdrawn；证据状态另采用 unverified、supported、contested、insufficient、invalidated。current 只表示当前使用，不等于真；supported 也不等于普遍成立或原因已证明。

用户态度单独保存为认可、部分认可、异议、补背景、当前已变或风格偏好。模型置信度如保留，仅是生成元数据；未经标定不得展示为人格准确率或取代证据检查。

系统对自我美化、为体面作辩护、回避或过度自责的分析，保持为有具体依据、情境及替代解释的候选或已支持认识，不新增“虚伪人格”“自欺指数”等永久标签。语气直接、用户感到刺耳或认可系统，都不能单独证明这种解释成立；反驳不能自动成为该解释的新增支持。

用户对某个判断的确信程度也是来源信息，与用户是否认可系统解释、系统对 Claim 的证据充分度分别处理。保留用户原话、判断对象、表达时间和适用范围；未说明时保持未知，不从语气强烈、重复表达或系统 confidence 反推本人有多确信。

“定论／工作假设／直觉”描述判断状态或依据方式，不构成高、中、低确信的固定阶梯；直觉也可能被本人强烈确信。这些表述不是必填分类或新增评分。综合与修订应保留“我目前倾向”“只是直觉”等限定，不把暂定看法改写为确定事实。

命题与立场分开保存。reported、endorsed、not_endorsed、opposed、unknown 不构成可任意升降的强度序列；归属排除不等于反对该观点，未自述不等于否认，讨论某种交付形式不等于接受相应价值假设。模型抽取的立场仍需来源与判定版本，不能无声覆盖原始表达。

自述型 Claim 的充分依据可以证明“用户表达过自己确信某事”，不能因此证明该事本身成立；用户确信不自动提高事实或原因解释的置信度。这些信息可先由原始来源及 Claim 文本表达，不因语义区分就要求新增实体或数据库字段。

### 5.3 充分性按认识判断

明确自述可以记录为自述；稳定模式检查独立事件、情境与时间；原因解释检查替代解释和反例。没有通用的最低会话数、固定每维条数或“300 条足够”的规则。

保留来源分布、独立事件覆盖、时间范围、已询问/未询问场景与已知缺口。覆盖描述是样本说明，不是覆盖一个人全貌的百分比。大量相同工作会话不能挤掉更少但不同情境的证据。

### 5.4 来源质量、证据权重与认识置信度分层评估

三者不是一个分数，也不是给用户或来源作者评“可信人格”。先检查材料在当前用途下能否使用，再判断它对某个具体认识有什么作用；权重与判断、情境、时间和版本相关。

| 评估对象 | 应评估的内容 | 记录位置与修订方式 |
| --- | --- | --- |
| 来源/片段质量 | 作者与引用归属、原文/转写保真、上下文完整度、时间精度、来源可核对状态 | SourceRecord/EvidenceSpan 的版本化评估注记；原始载荷不覆写，校正结果有来源映射 |
| 某条证据与某版认识的关系 | 使用资格、支持/挑战/仅作情境、直接程度、适用范围、同源/相关事件组及贡献强度 | EvidenceLink 的版本化关系评估；更换所评估的 ClaimRevision 时重新判断，不继承永久权重 |
| 当前认识的置信说明 | 本轮支持与反例、独立事件覆盖、状态/情境、竞争解释、仍未知什么及什么会改变判断 | ClaimRevision 的评估依据和状态；允许缩小范围、保留争议、暂停使用或产生新版本 |

同一原话“我喜欢道家”可以直接支持“用户表达过这个偏好”，却不能充分支持“实际取舍始终遵循无为”。原文保真高，不代表从中推导出的原因可信；当下感受的自述不因情绪强烈而降级，但不能据此确认他人的动机。过去资料可可靠地说明过去，未必适用于现在，不统一按年龄衰减或把新材料默认当成真值。

评估注记至少说明：评估对象及版本、用途/所关联认识、结果及未知项、依据和理由、评估主体（规则/模型/用户校正或人工复核）、评估方法/规则版本、评估时间，以及被替代的评估。可复用现有受校验元数据和 GenerationRecord，不要求新增评分服务或一概念一张表。用户报告、程序可核对结果与模型判断分别标明。

### 5.5 先检查使用资格，再计算贡献，不用总分抵消硬约束

先执行租户/权限与分析使用范围检查；编辑/角色内容另检查发布与撤回状态。已排除或异租户材料不进入当前分析。来源归属不清、引用误认、片段失真时，不得靠“低权重”继续用来证明本人持有某观点；允许在权限许可且明确标注的情况下作为背景或待确认线索。缺原文的旧结论沿用未验证历史认识规则，不伪造已核验片段。

合格关系的作用综合考虑直接性、完整情境、时间/范围适用性、独立性及反例。支持和挑战分开保留，不压成一个相抵后的净分。同源原文、抽取、摘要和角色回应不能重复计证；独立性尚不清楚则记录未知，不假定独立。不同事件也可能受同一提示或情境影响，应保留相关性说明。

一个可靠反例可使“总是/所有场景都如此”的说法收窄，不能被重复支持淹没；对于“较常出现”的观察则需复核频率与场景，不机械用一个反例抹去全部支持。认同某个价值与实践不同，不能通过固定设定“行为高于自述”来裁定真我。

检索排序、用户标记的重要程度、证据贡献和认识置信度四者分开。置顶某事件只影响关注顺序，不能增加其证明力；角色偏好不提高角色观点的事实权威。用户可以指出错误、补充背景、质疑评估或排除材料，但不通过手工分数把一个解释升级为已验证。

首版优先使用明确状态、限定范围与可读理由；需排序时可使用有规则版本的内部等级或启发式分值。未知不编码成确定的零或默认中值。模型自报 confidence、检索相似度及启发式权重不得直接解释为正确概率；未经对应任务/人群/语义的标定，不向用户显示“人格准确率”。不预先给出无依据的乘法公式、来源等级表或统一衰减常数。

### 5.6 修订传播：来源判断可以改，原始记录与历史不能被悄悄改写

“原始载荷保留”不等于解释性 metadata 永不可更正。转写/解析/作者归属/时间/上下文更正形成新版本或校正注记，保留旧定位映射和原因；硬删除沿用用户明确授权与生命周期规则。不能把纠正后的文本静默冒充当时收到的原文。

标准传播为：接受校正或使用范围变更 → 更新来源/关系评估版本 → 定位依赖的事件及 ClaimRevision → 标为待复核、收窄或撤销不成立关系 → 重评受影响认识 → 更新当前视图、后续对话上下文与相关对照/建议。与变更无关的记录不全量重算。因一条证据失效的认识可能仍有其他支持，不自动全部判假；其他支持须单独检查。

“过去理解错误”与“过去成立、现在改变”分开，后者调整适用时段；用户异议与已核对错误分开；排除/删除权限立即约束读取，不等待语义复核。历史快照保留当时依据和后来失效标识，不能作为当前有效结论继续推荐；涉及撤回展示或删除时还须遵守相应可见性约束。

来源评估、EvidenceLink、规则及认识版本进入 EvidenceSet/缓存指纹与任务校验。旧任务在校正之后返回时，须复核版本与使用资格，不能重新发布已失效解释；数量未变、只有评估或权重改变也要触发相应失效。回滚错误评估也是新的修订，不抹去修改历史。

每项语义复评关联明确的旧命题及范围、新输入和影响种类：保持、澄清、扩展、收窄、削弱、反转或撤回。澄清对象、补充背景、增加替代解释与直接反证分开记录。证据的使用资格、可靠性、独立性或贡献变化，可以支持调整认识的支持程度与置信说明，不要求新材料直接否定旧命题；削弱时须说明哪项支持为何减少。反转旧命题须给出在相应情境下支持相反判断的依据，不因仅有澄清、新增替代解释或模型生成了不同文案就记录为反转。修订理由的存在可程序核验，其依据与修订幅度是否相称仍需语义复核和反例评测。

### 5.7 认识形成策略与决策血缘

Epistemic Policy 不替代领域本体，而是规定“这些对象在什么条件下可以参与一次认识决策”。首版至少分三层：**Deterministic Gate → Semantic Planner / Synthesizer → Deterministic Validator**。Gate 负责租户、用途资格、版本、open-question 状态、问题预算、hard cap、重复请求等可确定规则；模型负责比较候选解释、识别关键不确定性、生成有限表述；Validator 再检查输出是否引用真实 evidence、是否越界扩大 scope、是否违反 Ask/Stop 契约、是否重复已问问题或发布已过期结果。中间的语义层由个人理解 Agent 承担，不规定固定的 Planner/Synthesizer 调用步骤。

探索决策本身也要可追溯。一次 Ask 至少能说明当前有限认识、目标 uncertainty、为什么不同答案可能改变判断、问题内容及问题预算；一次 Stop 至少能说明为什么继续询问主要只会增加细节，或为什么剩余未知更适合未来事件验证。无法指出目标 uncertainty 的问题不得仅因“还能继续聊”而创建。

Ask/Stop 是主动补问的决策，不代表每轮对话只能提问或结束。用户请求开导、解释、建议或继续讨论时，可依据当前理解回应；本轮没有新 Claim 仍可以有用。回应引用的个人认识版本、内容版本和输入可沿用 GenerationRecord/EvidenceSet 记录，系统生成的回应不自动反向充当用户特征的证据。

GenerationRecord 或等价受校验元数据应能还原本次处理所用的 `policy_version / prompt_version / model_route / model_version / validator_version / input_fingerprint` 以及输出状态。这里保存的是可复核决策血缘，不保存模型隐藏 chain-of-thought。相同个人材料在不同策略或模型下得到不同结果时，系统需要先把“处理规则变化”与“用户本人变化”分开，必要时标记受影响认识待复核。

认识质量不由模型自评 confidence 决定。固定评测集应覆盖 Ask/Stop、关键不确定性命中、无价值重复追问、无依据推断、scope 越界、反例处理、证据可追溯和延迟；评测结果属于系统/策略质量，不写成某个用户的个人置信分。

## 6. 多源输入与历史资产

### 6.1 IngestEnvelope 的逻辑内容

服务端确定 tenant 与本人主体；载荷携带来源类型、外部 ID/版本、内容类型、作者/说话角色、谈论对象、时间与精度、原文或衍生内容、出处及上游引用。原文没有时显式声明缺失，不构造假的 raw_record 让外键通过。

原生引导回应也携带 QuestionRecord 关联。第三方引用、模型回复、工具输出可以作为理解情境的材料，但不被认作本人自述。归属无法判断时隔离待确认，不能默认吞入画像。

### 6.2 旧 L2/L3 的复用

旧抽取和旧洞察首先按实际语义映射，不按层级名称硬映射。能够核对片段的，映射到 EvidenceSpan/ClaimRevision；只有结论的，作为带来源的未验证历史认识，可展示和用于提出问题，但不冒充已验证事实。

允许复用足够质量的旧结果，也允许针对缺口重新加工。恢复旧 TencentDB 服务、旧同步脚本或 Obsidian vault 不属于复用前提。历史判断和原文来自同一事件时共享血缘/独立事件标记，防止重复加权。

### 6.3 幂等与上下文

以租户、adapter、外部对象身份和来源版本构建幂等边界，内容摘要辅助去重，不单凭文本相同合并不同时间的真实事件。重复导入不重复触发计证；新版本保留可追溯变化。

user turn、段落和字符数是传输/定位单元，不是唯一业务事件边界。保留必要邻接上下文；模型归纳的事件描述另存为可修订对象，不替换原文。不能把整个会话或每句话机械当成一个独立经历。

Agent 来源需识别 runtime 包装、系统注入、机器任务及粘贴引用；保留来源原貌，在规范化视图标注被排除片段及定位映射，不篡改原文后仍称原始证据。仅有 session_id 和 user 标签不足以证明作者归属，更不足以证明解释成立。

短指令、重复提示、提示词质量或会话时长属于来源侧信号，不直接评个人能力/人格，也不机械“反转解读”为优点。应检查指令对象、前序输出与实际情境；无法区分用户偏好、工具限制和重复沟通原因时保持未知。

## 7. 加工与认识更新

保留来源 → 按需识别归属与片段 → 组织事件/情境 → 生成候选认识 → 核验来源及语义支持 → 发布有范围的当前认识 → 接受反例/纠正/行动结果 → 修订与视图重建。并非每条输入都必须走到“深层洞察”。

来源版本与片段定位不可由 LLM 任意创造；摘录核对、租户一致性、排除状态、版本和依赖关系由程序验证。含义是否支持结论另做语义检查；找不到足够依据时降级或不发布该解释。

画像更新使用包含来源/认识版本、纠正、分析范围和处理版本的集合指纹，不只比较条数。已有重要认识在新材料到来时按相关性复核，而不是每次只读最新窗口重新遗忘全局。

所有修改有明确影响范围：事实纠正影响派生解释；解释异议进入争议状态；风格偏好影响呈现；用户撤回分析授权使相关内容不可再次进入生成。不能用一种“deny”状态代替全部行为。

### 7.1 本体约束下从来源到个人知识

采用“原始来源 → 按本体进行归属/命题/情境映射 → 有来源的实体与关系实例 → 支持/挑战及语义核验 → 可修订的个人认识 → 对话、总览、报告与建议使用”。对话和实际使用中的新信息再进入同一来源及修订链。本体是贯穿映射、检索、核验和修订的共享概念/关系/约束，不是给原文再生成一份摘要的中间文件；知识是有范围和证据状态的认识，不是无条件真相。

区分两种建模职责：认识过程语义（Source/Evidence/Claim、作者/对象/立场、支持/挑战/背景、版本与资格）与生活/工作领域语义（角色、事件、目标、约束、选择、结果和适用情境）。前者避免混淆来源与推断；后者使同一表达能在其真实条件下被理解。实际覆盖在 As-Is 核对，不用一个未定义的“本体使用百分比”表示。

主题 taxonomy 只回答材料在谈什么，不等于构建了角色—事件—目标—约束等领域关系，也不等于支持了某项人格判断。一条来源可以包含多个命题或兼容分面，不强制压入互斥的单一标签。本人报告项目经历可以支持“本人如此报告”的局部认识，不直接证明项目的外部事实；本人评价或要求可按其明确范围使用，不能因对象为 project 整句排除，也不能把所有工作要求升级为稳定偏好。用途资格由具体命题、来源和所支持判断共同确定。

领域关系实例必须有可定位依据、时间/范围与推断标记；不同会话不自动独立、同一项目不自动同一事件。未知对象或指代应先保留来源并在需要时回读，不靠主题类别补造经历。个人知识与外部方法知识分开：前者依个人材料形成；后者提供评估协议、解释视角和适用条件，方法内容不能替代个人证据。

来源级谈论对象只说明材料范围，不自动决定该片段中每个命题或实体的actor/about。本人可以报告项目中的第三方角色，也可以陈述对第三方行为的担心；前者不验证第三方实际履职，后者不等于该行为已发生。关系实例需区分表达者、被指对象和报告/推断方式，避免以单一字段相等代替语义核验。

沿用现有关系结构及受校验字段/JSONB 实现上述逻辑即可；采用本体方法不自动要求 RDF/OWL、图数据库或单独本体服务，也不要求重跑已合格的原文抽取。U2 优先把已有证据按命题和情境连接，再形成专题认识，不以先建设通用本体平台阻塞报告交付。

## 8. 数量、存储与计算边界

分别控制归档保存范围、实际加工范围和单次分析上下文。正式结构化业务数据以服务端主数据库为真源；原文版本、个人证据、情境、认识、诊断、反馈与任务关联可跨端恢复。AV/TencentDB 的 L1–L3 是加工/解释层级，不是三套数据库，也不能将 staging 文件名直接映射为正式事实类型。

原始大档案可授权托管到对象存储，或由用户只保留本地；主库记录对象/外部身份、版本、校验、保留策略和可用状态。采用混合方式时，核心至少保留获准同步的精确摘录、必要上下文和定位；未托管原文不能声称手机可随时回读。临时不可达、用户排除与删除不是同一状态。

选择性加工围绕问题、覆盖缺口、冲突和新增信息；单次生成采用有预算的 EvidenceSet。预算由可用模型和实测质量确定，不以固定字符数定义人的信息价值。重复来源与同一事件不构成独立样本。

建议的逻辑存储组是：身份与租户、来源与证据、经历与情境、认识与修订、探索与反馈、目标与尝试、视图与任务、公共素材。组与概念均不是建表清单；物理设计在具体交付中明确键、索引、约束和 JSONB 的结构化契约。

核心身份、关系、时间、生命周期与归属不藏在不可校验的大段 JSON 中；可变内容使用受版本控制的结构。当前关系数据库优先复用，向量索引只作为可重建检索索引，不作为事实源。设备 SQLite/IndexedDB、文件缓存或客户端本地状态均不拥有独立 current 认识；同步以服务端版本和冲突规则为准。JSON/JSONL 保留为导入/导出与回放格式，不维持另一套正式个人模型。

staging 接入须预览并映射来源/片段/情境/候选，保留原消息标识、偏移、来源版本、同源/留出标记、归属冲突与反馈；新建内部键不抹去外部定位。确定性 L2 会话索引不可自动提升为独立生活事件，L3 自动结果不可提升为本人已确认的 current。优先复用合格抽取，只有缺口、规则变化或纠正才选择性重算。

## 9. 个人租户与数据控制

目标默认一人一租户、一本人主体；认证账号可以关联不同登录方式，但本轮不设计跨账号合并、多人共享同一个人格或身份去重。第三方参与者只是本租户上下文，不能连到另一个用户的私人 profile。

私人源文件、片段及其质量评估、证据关系/贡献评估、认识与三观视图、视角偏好/对照、反馈、作答/测评结果、尝试、生成记录、任务、缓存、向量索引与导出都要有可检查的租户归属。公共 KnowledgeMaterial 使用明确公共域，与私人记录分开，不能把“tenant 为空”当作普遍可访问。公共内容不携带私人生成结果。

展示隐藏、停止分析、撤回来源和硬删除分别定义。分析排除须阻止后续使用；删除须处理来源、衍生物、索引、缓存和待处理任务。历史快照应标失效或移除不可再展示的内容；已经导出的用户副本不能承诺自动追回。备份的清理与保留边界在技术方案和实际操作前明确，不用 append-only 阻止用户可控删除。

导出区分完整个人数据包与用户选定的沟通摘要。前者覆盖已持有的个人来源、作答、结果、认识版本、纠正、尝试和必要血缘/版本信息，并说明未包含的外部原件和许可受限内容；认证密钥不导出。后者可作为一页摘要或个人使用说明投影，由用户预览并自行决定去向，不自动分享，也不创建新的独立证据。

经审核的通用角色来源可复用；私人定制、事件包和角色回应属于本租户，不回流公共角色资产。变更视角偏好不修改原记录与历史认识；角色来源撤回时禁止新使用，并让相关对照/建议可识别其依据已变，不自动宣布用户相应价值错误。

本轮只写设计，不执行这些生命周期动作。文档和测试示例使用合成事件，不包含所有者具体健康情况、真实经历或密钥。
