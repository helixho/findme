# U2 — 命题、情境与个人理解基线

> 适用边界：本机 AV/U2 加工路径已按 [ADR D23](../adr.md#d23-账号模式云端数据库为唯一运行真源其余运行路径冻结或退役) 冻结。以下保留既有加工、恢复和来源语义，供历史核对与显式导入使用；不构成重跑私人材料或恢复旧入口的授权。当前实现见 [As-Is](../as-is.md)。

## 范围和完成条件

在 U1 工程完成的冻结批次、主题映射和复核 overlay 上，形成有范围的专题及整体理解，供 U3 同一 App 消费。U1 库存、原文覆盖、主题索引继续有效；不覆盖旧 L1–L3、不重新全量抽取，不启停服务、迁移生产数据库或实现 U4 评分。
本轮新增的是可追溯的用途修复、领域实例/关系与报告版本，不是新的权威人格库。U1 的工程完成不改写为“已全面理解本人”或本人已接受。

## 输入与用途修复

同时核验原批次、U1 成功版本与 latest-review 的源版本/内容指纹；留出只可计数，不进入语义输入。过期、排除、未知作者及转发正文不得通过复核 overlay 升为本人观点。
U1 的9项局部用途修复、8组兼容分面与主题建议是模型协调意见，不是本人确认。逐项核对原文定位和可用性后保存独立修订：本人报告的项目角色/目标/经历可用于该局部自述，不证明项目客观事实；命令与工作要求可作情境，不自动成为稳定偏好。
混合表达按具体命题拆分，保留原作者、立场、旧类型和修复理由。对相同原句的兼容释义不制造冲突；语义证据不足继续待核查，不能仅靠内容含“我”判为本人事实。

## 全批组织与有界分析

全体开发候选保留去向：专题成员、背景、指代待解、用途待核验或不具个人信息。U1 的初始主题和补充主题都进入映射；专题可合并相邻材料类别，但不是预设人格标签，必须保存合并依据。
每个专题形成有界 EvidenceSet，优先相关性、明确表达、不同情境/时间和限制性材料；保留选择/省略记录。新修复命题的优先位置最多使用约三分之一的原文来源预算，其余继续比较原有个人表达、时间和条件；不因一条材料刚被修复就压过整批其他信息。该约束是检索预算，不是证据强度或效度阈值。不把主题归属当支持度，不把不同会话当独立经历，不宣称所选片段等于全专题语义已穷尽。
资料稀少主题允许只形成自述/线索/未知。输入预算导致未分析必须标未分析，不能混成“分析后不足”；不得用旧五条 L3 作为专题范围或数量上限。

## 轻量本体的实际实例

在被实际选中的原话及必要上下文中识别角色、目标、约束、选择、结果、评价、偏好、当时状态等命题；每个实例固定来源、适用情境/时间及自述或推断标记。
关系只连接已给出的实例，记录依据和范围；同项目、相似文本、相同日期均不自动建立同一事件或因果。原文未报告结果时保持未知，不能把计划写成已经执行。
实例和判断上的 time 是来源表达时间，不是推断出的事件时间：仅有一个共同来源时间时才可使用该时间；引用横跨多个日期时单值为 null，完整日期从证据关系回溯。序列化的字面量“null”、精确空串和“/null/”只表示缺失时间，可在保留原始字节的版本化投影中还原为JSON null；后两种编码使用独立处理版本，已有处理版本按原语义复算，不改变旧审核指纹。任意标签、未知字符串和不存在于原文的日期仍拒绝，不能通配清空。多日期下误选某个实际来源时间也只可规范化为无单值，不得发明日期。规范化保留原始输出、输入指纹和处理版本，叙述中的时间/变化主张仍必须接受语义复核。
来源的 about=project 表示材料情境，不自动决定其中每个领域实体的行为主体。项目自述中的角色可以属于本人或第三方；领域实例必须显式记录 actor/about、保持 report-only，并让语义复核检查具体原文和指代，不能只凭字段相等通过或拒绝。
本体用于语义组织和核验，主题 taxonomy 继续只作索引；不新增图数据库、RDF/OWL服务。个人命题与框架/方法知识不混合。

## 专题、综合与旧认识

专题报告先给核心理解、资源与限制、条件关系、竞争解释及必要追问；同时保存领域实例和关系，不要求每次产生隐藏原因、冲突或行动。通过同一证据集的独立上下文语义复核后，才进入可用候选；引用正确不等于语义正确。显式失败续接时，完整但未通过的审核反馈可作为未验证的改稿线索，最多生成一版同来源修订并进行一次新的独立上下文审核；原报告、错误审核与累计用量保留，新稿不继承旧审计通过状态，也不将错误反馈视为新证据。成功修订的普通读取与 dry-run 必须复用同一审核结果，不因缺少重试开关退回旧失败稿。修订生成或新审核再次失败后，同一修订指纹停止自动尝试；预算不足时保留待执行，不伪造分析后资料不足。审核对象是当前拟接受的决定、命题和关系；先前协调意见、已拒提案和旧审核只是历史背景，若当前候选没有继承，不能当作当前已承诺的事实。当前候选若继承错误仍须拒绝，不能靠标成背景绕过。
总览使用专题作为导航和确切判断引用，任何新增跨专题解释仍须给出本次实际提供的原子证据。覆盖、充分性和临床/人格效度分开；框架未运行时标记未运行，不伪造 HUMAN 3.0 等级。
旧五条 L3 分别核对原命题与支持/反例；记录保持、澄清、改类、收窄、削弱、反转或撤回及理由。旧摘要不是新证据；规则校正不等于用户本人变化。改类可在保持命题的同时把兼容条件从冲突中区分。
基线输出为可供 App 消费的结构化版本和可读报告：总览、专题、上下文关系、证据附录、旧认识处置及明确未决队列。实际 App 接入仍属于 U3，不以 Markdown 冒充统一入口已完成。

## 持久化、成本与恢复

输入只读，结果存于仓库外独立 U2 目录；版本、输入/规则/模型/复核指纹、选材和逐调用 usage 可回放。借鉴现有原子写入、进程锁、来源再检查和缓存，不恢复旧 runtime 或新增服务。
默认 dry-run；显式 live 通过既有 Gateway。整个 U2 执行累计受调用预算约束，失败和重试也计数，不因每专题另起 runner 清零。初始执行预算40次 CLI；经明确授权的续接可在 `--retry-failed` 下选择41–64的累计恢复上限。增加预算必须显式、留账且不得隐式触发，历史尝试保留；仅重跑受影响阶段，规范化可复用的原始输出不增加生成调用。
成功子任务固定结果与校验指纹；输入/用途改变则失效，已接受结果读取无模型调用。部分失败保存已完成专题，不能标整批 ready。实际 usage 未返回为 null；CLI 次数不是底层请求数，输出 token 目标为 advisory，不编造费用。
发布前核对源快照与U1/review版本，过期回包不得成为当前候选。只修复用途不修改原文；本地合成测试不接生产数据库。

## 验收

- U1 输出与原 L1–L3 文件不变，留出不进入 prompt；全部开发候选有主题、背景或未决去向。
- 混合表达可分命题；项目自述保留 report-only 范围；外部引用、未背书和未知不得升级。
- 领域实例、关系端点及逐判断引用全部可回溯，未知不补造；同项目不等于同事件。
- 每个已完成专题有实际输入范围和省略记录，总览可下钻；旧五条逐项有处置，不因重生成文案声称人变了。
- 失败、预算耗尽、来源更正、重复运行和并发不丢记录或重复调用；缓存结果仍经过当前输入核验。
- 工程验证、模型复核和本人效用评价独立记录；U3/U4 状态保持未交付，直到相应链路实际完成。
