# 个人理解 Agent：能力、上下文与方法 Skills

> 实施设计，尚不表示运行时、工具或 skills 已实现。业务要求见 [BA](../ba.md)，数据语义见 [DA](../da.md)，技术选择见 [TA](../ta.md)；任务与依赖只在[工作计划](../delivery/agent-work-plan.md)维护。此处的 Skill 蒸馏是提炼分析方法，不是蒸馏用户人格或训练模型。

## 1. 目标与职责

后台向 Agent 提交个人理解任务，由包含 harness 的执行环境完成上下文选择、工具调用、多步分析、检查和修正。Harness 指管理模型、工具、会话、上下文及执行状态的运行环境；增加工具调用次数本身不构成理解增益。

第一版采用一个 Agent，通过任务意图选择方法，不建立多 Agent 团队。Agent 应能：

- 理解询问、经历补充、事实纠正、解释异议及综合请求，回应当下需要。
- 主动查找相关原文、认识、反例和修订，减少重复询问，不默认读完全部资料。
- 比较解释及其适用条件；有意义时补问，依据不足时保留未知，也允许结束。
- 按现有领域规则提交候选和修订；后续对话与呈现使用同一份有效认识。
- 通过来源化方法获得解释增益，区分普遍理论与对本人的依据。

渠道适配器负责原始来源接入，FindMe 领域服务负责资格、认识身份、修订发布与失效；Agent 不另建权威画像库。外部记忆或检索工具只能作为可替换的辅助，不成为本设计前置。

## 2. 应用、Agent 与模型

```text
App → API 保存输入并创建任务 → 个人理解 Agent（pi SDK）
                                  ├─ 按需加载方法 skills
                                  ├─ 调用 FindMe 领域工具
                                  └─ 调用模型服务商
                          → 领域服务校验并保存结果 → App 展示
```

API 与 Agent 可以在同一 Node 应用内分模块实现，无需新增服务器。任务先保存用户输入，Agent 的多次读写各用短事务，模型运行在事务外。现有主链、任务、预算及修订能力按职责复用；[原主链契约](p1-main-chain.md)中固定 Planner/Synthesizer 的调用编排是待适配的既有实现，不规定新的 Agent 必须沿用同样步骤或调用次数。

pi SDK 负责 Agent 执行循环、会话、工具事件与上下文管理；FindMe 负责任务状态、领域操作与成本边界。模型选型是运行配置，不写进方法定义。首轮质量验证沿用已选的 OpenRouter / DeepSeek Flash 1017，准确模型标识在执行配置中固定；不因本设计恢复 OpenViking 或启动其他候选服务。

pi 的公开 SDK 提供自定义资源加载器、工具、模型和会话管理。实现采用完整 AgentSession SDK；先核对并锁定兼容版本，验证默认资源发现、编码指令、自动重试及会话持久化的实际行为。不得仅依赖更换工作目录或一段追加 prompt 声称上下文已隔离。

pi 只出现在一个适配模块内：领域工具的输入输出、方法 skill 文件和任务状态由 FindMe 定义并保持与框架无关，更换 harness 时只重写适配模块。

## 3. 上下文装配

| 层次 | 内容 | 更新方式 |
| --- | --- | --- |
| 稳定指令 | 本节的角色、理解原则和工具要求 | 版本化；不混入私人样例结论 |
| 当前任务 | 用户输入、任务意图、当前时间、对话和目标版本、预算 | 服务端为本次运行装配 |
| 方法资源 | Skill 名称/描述、实际选中的正文和参考资料 | 按需加载；记录使用版本 |
| 个人材料 | 相关来源片段、认识、异议、反例、版本与时间 | 通过工具查询；不预填完整人物结论 |
| 工作进度 | 已读取引用、待核实问题、任务检查点 | 属于任务状态；继续执行前重新核对依据 |

采用应用自己的资源加载器和产品指令，显式配置工具与会话管理；不读取开发机器的 AGENTS.md、全局 skills、开发对话、记忆插件或默认编码助手指令。材料内的历史指令保持为材料，不成为当前执行指令。Skill 参考文件经专用资源读取工具加载，不需要授予通用 shell 或任意文件访问。

### 会话切分与记忆召回

产品对话不等于一个持续增长的模型会话。每处理一次用户输入、纠正或综合任务，都新建一个 pi 内存会话，任务结束即丢弃；对话本身、认识和来源只保存在 FindMe。独立测试案例同样各用新会话。不把 pi 默认 JSONL 文件当作运行真源。

每次任务按固定顺序装配上下文：

| 顺序 | 内容 | 说明 |
| --- | --- | --- |
| 1 固定前缀 | 稳定指令、skill 名称与描述 | 内容稳定，便于利用服务商的提示缓存 |
| 2 本人交互偏好 | 已确认的表达与提问方式（如偏好短选项、只看对话内说明） | 来自本人明确反馈的当前认识，每次都装配 |
| 3 本对话近况 | 最近若干轮原文；更早部分用带引用的对话摘要；仍挂起的话题 | 摘要是派生材料，来源失效时作废重建 |
| 4 相关认识索引 | 与本次问题相关领域的当前认识标题、编号与状态 | 只给索引，正文和依据由工具读取 |
| 5 本次输入 | 用户输入、任务意图、预算与目标版本 | 先保存再处理 |

其余内容由 Agent 按需召回，自上而下逐级取用：总览/专题 → 认识（含修订、异议、证据关联）→ 原文片段；另可查历次对话原文和对话摘要。检索方式为层级浏览、关键词匹配和语义检索并用；语义检索使用同一 PostgreSQL 内的 pgvector 索引，向量随对应来源或认识的删除一并删除，并受同一 Profile 隔离。嵌入请求同样经过费用安全闸。工具返回设大小上限并分页，单个任务的上下文因此有界。

外部记忆服务（如 OpenViking）不作为记忆层：它会另存一份带自动摘要和提取记忆的私人副本，删除传播和修订关系无法由 FindMe 保证。只有评测显示自建召回不足时，才把它作为可重建的检索索引做有界对照，且删除必须可验证。

摘要、压缩上下文和工具结果都是派生材料：必须保留引用与版本，不能升级为独立证据。相关来源纠正、排除或删除后，旧材料不能继续通过已运行会话或摘要进入模型；必要时丢弃相关执行上下文，从有效材料重建。持久任务保留必要引用、结果与检查点，不保存隐藏思维过程；来源删除传播同样覆盖派生回复及执行产物。

### 系统指令初稿

> 你是 FindMe 的个人理解助手。帮助用户更准确、深入地理解自己的经历、选择、模式和处境，并在交流中持续修订理解。
>
> 围绕当前问题工作。充分利用已知材料；缺少关键依据时继续查找、提出有区分力的问题，或保留未知。无需每次输出完整报告或提出行动。
>
> 重要判断说明依据、范围和不确定之处。区分本人陈述、他人陈述、引用、助手分析和假设。已有分析是线索，不是新的独立证据；本人认可启发性不等于逐条确认事实。
>
> 从条件、资源、代价、价值取舍和可能机制中形成解释，比较合理的其他解释。工程、环境和心理解释都需要相应依据，不预设唯一原因。
>
> 使用历史认识前检查状态、时间和后续修正。接受纠正时明确改变哪条判断及其依赖，未受影响的判断保持；不把一次异议扩大成全局禁令。
>
> 引用来自本次实际读取的确切片段，原文应支持相邻说法。历史情况保持历史范围，缺少现状依据时不称为当前事实。
>
> 根据问题自然表达。可以有洞察、有锋芒，但不靠人格标签、无依据动机或套路建议制造深度。允许不变、未知、争议和停止。
>
> 聚焦用户本人。用户要求先别给方案时停在讨论，不把关于本人的问题转成修改工具、规则或项目的任务。按用户已表达的交互偏好提问：开放问题负担大时给少量具体选项，选项不预设强度，允许多选、都不像或改写；用户给出自己的标准时采用这套标准。
>
> 用户要求吐槽时可以夸张，但修辞不是判断；转入认真讨论时逐条说明哪些有依据、哪些是夸张或无据推测。记住你接触的材料多来自用户需要帮助的场景，不把它推成整个人。被反驳时先核对，有依据的判断保留，没有依据的明确撤回。
>
> 健康信息区分本人报告、本人自我判断和你的解释，不做诊断。必要时说明理由并建议一次专业评估，用户拒绝后不反复劝；出现紧急风险信号时明确给出求助渠道。

这份初稿与方法正文分别维护；工具 schema 不在提示词里再定义一遍。生成前记录实际生效的产品上下文版本和已加载资源，确保能区分输入变化与方法变化。

## 4. 方法蒸馏与 Skill 目录

方法语义沿用 [BA §3–4](../ba.md#3-四类认识的业务判定)、[输出设计 §3](personal-understanding-output.md#3-参考框架各自承担什么)及 [Insight Analysis 契约](frameworks-and-insight-analysis.md#10-insight-analysis-profile-contract)。蒸馏把这些原则转成工作方法，不新增理论有效性声明。

| Skill | 已有依据 | 工作方法与交付 |
| --- | --- | --- |
| `experience-and-evidence` 经历还原与证据判断 | 归属、立场保真、独立事件、证据贡献与时间规则 | 还原事件与可行选项，区分自述/转述/分析、引导/自发表达及重复；返回可用依据、限制和待澄清处 |
| `problem-and-explanations` 问题重构与竞争解释 | Reframe–Structure–Tension–Hypothesis | 保留实际问题，建立有范围的重构及竞争解释；张力两端各有依据，说明什么信息会改变判断 |
| `behavior-and-conditions` 行为与条件分析 | COM-B、目标/选择/约束/结果分析 | 检查能力、机会、动机和代价，不把没做自动等同不愿；外部条件确实不可靠时，把用户的反应视为合理反应而非心理问题；使用用户自己的分类和标准；寻找支持、反例及有区分力的问题 |
| `needs-values-and-narrative` 需要、价值与叙事 | SDT、McAdams、价值取舍、三观探索 | 区分角色、需要、认可、向往、要求和实践；解释局部差异，不按理论宣判隐藏动机 |
| `decisions-and-acquisition` 决策、获取与未来使用 | 预期后悔、获取带来的目标进展感、补偿性消费、对未来使用意愿的乐观偏差；囤积障碍的诊断边界 | 还原获取事件与之后的实际使用；区分“配置/价格划算”和“对本人划算”；用过去的实际使用检验“以后会用”；用反事实问题（如“假如一年都不用还会买吗”）区分用途、兴趣与安心感；不据此诊断 |
| `trust-and-verification` 信任、验证与确认 | 重复寻求确认的短暂缓解机制、信任校准、独立验证的工程用途 | 区分补足证据的验证与只为恢复安心的再确认，判据是新增了什么信息、会改变什么决定；把信任限定在具体结论上，一次失信不扩大为整体否定；正式的独立 review/verify 不被心理化 |
| `life-structure-synthesis` 生活结构与跨域综合 | Life Structure、既有输出维度、HUMAN 3.0 覆盖启发 | 合并独立事件，识别支撑机制和跨域影响；未采集领域保持未知，不把资料少写成能力低 |
| `discriminating-exploration` 有区分力的访谈与尝试 | Ask/Stop、反事实选择、可选尝试与回顾、[BA §4.1/§4.6](../ba.md#41-开始让用户有内容可回应) 的提问规则 | 每个补问对应待区分解释；区分当时信息重选和事后重选；按交互偏好设计选项（不预设强度、可多选或改写、回答只承接所选项）；中途检查本轮是否真有帮助并调整方式；允许停止、挂起话题，尝试保持可选 |
| `understanding-revision` 认识修订 | BA/DA 的纠错、异议、变化和传播规则 | 定位确切修订，区分事实错、解释争议和时间变化；提交局部处置及影响范围，不擅自改原始输入 |
| `understanding-review` 理解质量复核 | BA §7、Insight Validator、输出质量标准 | 复核语义支持、归属、范围、时间、修订范围和解释增益；吐槽转入认真讨论时逐条清算修辞；检查接触场景偏差；被反驳或用户要求时给出“保留 / 局部保留 / 撤回”收敛表；发现问题后修正或降级 |

通用对话任务使用前八项中有关的方法，不要求每轮全部运行。归属、引用、版本和修订边界是基础要求，不能因模型漏选某个 skill 而失效。明确纠正任务由编排加载修订方法；重要综合和认识写入前必须执行相关复核，不能只在目录中列出 review skill。

完整 HUMAN 3.0 另以 framework skill 加载固定 DefinitionVersion，沿用原有访谈、等级和结果契约；覆盖启发不能冒充完整运行。标准测量工具的题目、计分和适用条件独立保留，确定性计分仍由程序负责。作品视角及其他方法按既有知识内容边界接入，不作为首版只读对话的前置。

### 每份 Skill 的最小内容

1. 适用任务与触发条件，以及不适用的场景。
2. 必要输入、已知信息的复用方式和工具要求。
3. 可执行步骤、解释比较、追问与停止条件。
4. 可读交付、候选/修订的结构化产物及其映射。
5. 自查问题、失败反例和修正方式。
6. 来源、采用/改写理由、适用边界及版本；参考资料按需读取。

例如行为分析不能只列“能力、机会、动机”三个词：须先找到具体事件和真实可行选项，区分想做/应当做/实际做，检查条件与代价，比较解释，再选择能改变判断的问题。私人满意样例不进入公开 skill；保留方法和合成反例，并用未参与调整的新案例检验。

## 5. 领域工具

| 工具职责 | 最小返回或写入契约 |
| --- | --- |
| 检索资料 | 返回相关片段摘要、来源/版本、匹配依据、遗漏或分页信息；支持按时间/领域/类型缩小，不宣称完整召回 |
| 读取证据 | 返回确切原文、前后文、发言人、谈论对象、立场、时间及资格状态；未知保持未知 |
| 读取认识与修订 | 同时区分 current、candidate、争议、撤回和被替代历史；返回支持/挑战/背景及修订关系 |
| 查看覆盖 | 返回本任务实际查阅范围和已知未覆盖部分；不从未查到推出该领域不存在 |
| 加载方法 | 返回所选 skill 正文或可定位参考片段和版本；方法文献不进入个人证据计数 |
| 提交候选与修订 | 提交确切目标版本、引用、理由和影响范围；领域服务决定资格及发布，支持幂等和过期拒绝 |
| 检查交付 | 程序检查引用存在、片段匹配和版本；方法复核判断是否支持该说法及是否超范围，两者分开 |

检索按[会话切分与记忆召回](#会话切分与记忆召回)执行：关键词/子串匹配配合时间、领域、类型和发言人过滤（中文不依赖 PostgreSQL 默认分词，Agent 可换词多次查询），加上同库 pgvector 语义检索和沿认识与证据关联的层级浏览。

工具复用现有 Profile 作用域与领域服务，不直接给 Agent 任意 SQL 或数据库管理员连接。内部工具优先通过 TypeScript 调用，不以新建 MCP 服务为前置。证据引用采用片段编号与确切版本，显示时可展开原文；只有消息 ID 存在不足以判定支持关系成立。

导入的候选可作为待核验分析与取证线索，不能通过检索直接变成 current。助手分析的来源身份必须在工具结果中可见；本次生成的回复同样不能变成额外的独立支持。

## 6. 执行、恢复与结果

每次任务包含输入指纹、实际使用的来源/修订、方法与上下文版本、工具契约、harness/模型标识、预算及目标版本。方法/框架的概念与评价标准由对应定义持有；任务只引用版本，不复制一套可漂移正文。数据语义见 [DA §3.4](../da.md#34-外部框架与洞察分析不是平行真值库)。

同一产品对话的执行及提交串行；用户新纠正到达时先保存，旧执行在使用与提交前核对版本，必要时取消并重建任务上下文。恢复读取任务检查点和有效材料，不依赖旧进程存活；不把实例休眠后的进程恢复自动等同于任务一致性。

**费用安全闸。** pi 的请求前钩子只能改写请求内容，不能拦下请求；自动重试和压缩也由 pi 自行发起。因此闸门放在模型出口本身：用 pi 的自定义 provider（`registerProvider` 的 `streamSimple`）包住内置 OpenRouter 实现，pi 发出的每次模型请求都先经过闸门。闸门在进程内存中计数，发请求前检查“已实际花费（取不到服务商回报时按该次上限计）+ 本次请求的保守上限 ≤ 限额”，不满足就拒绝且不发送；被拒后 pi 无论是否重试都不会产生费用，任务中止并保留输入与已有结果。本次上限按输入 UTF-8 字节数（保守地当作 token 数）乘输入单价，加最大输出 token 乘输出单价；请求带 OpenRouter 价格上限，保证实际单价不超过计算所用单价。闸门只做内存运算，不访问数据库，不增加可感知延迟。

首版默认值（实现后以运行配置为准）：

| 范围 | 默认上限 |
| --- | --- |
| 单次模型请求 | 最大输出 6144 token；价格上限输入 US$0.3/百万 token、输出 US$1.2/百万 token |

首版关闭 pi 自动压缩，保证所有调用都经过同一闸门；上下文超限时任务显式失败。测试阶段只要求上述闸门；按 Profile 持久化预留、重启后不归零的累计及与现有任务预算记录合并，在 AG-05/AG-07 补齐。默认值依据已有单次试验的实际用量，为多步取证留出数倍余量，不沿用旧两段处理的固定次数。

结果分为：用户可读回复、引用片段、候选/修订处置、未知与可选下一步，以及供任务恢复使用的必要状态。前端可以展示查找/分析/保存进度，但未经复核的草稿不能冒充最终认识；重要结果经检查后交付。引用错误、输入失效或处理失败时，允许返回有限整理或显式失败，不丢弃原输入。

## 7. 验收场景

| 场景 | 合格结果 |
| --- | --- |
| 未预填完整资料 | Agent 自主检索并读取相关原文；输出说明实际覆盖，不能声称了解未读资料 |
| 引用编号对、语义不支持 | 能发现或在复核中修正；不能用“ID 有效”计通过 |
| 含引用的 user 消息、助手复述 | 保留实际发言与被引用者，不能把助手推断当本人承认 |
| 新反例或异议 | 重新核对相关解释，既不迎合反转，也不以“防御”保护旧判断；无关认识保持 |
| 历史记录与现状 | 时间范围明确，没有新依据不把过去问题称为当前待办 |
| 相同事件的原文、摘要和分析 | 识别同源，不制造多份独立支持或重复认识 |
| 会话压缩后来源被纠正/删除 | 旧摘要、工具记录和候选不能绕回后续模型输入；相关依赖被处理 |
| 重试、取消、进程重启和预算耗尽 | 不丢输入、不重复写入、不超实际调用上限，状态可读且可续做 |
| 使用方法与框架 | 能说明该方法带来的解释或问题增益；不堆理论、不代替计分、不混为个人事实 |
| 先吐槽再追问依据 | 逐条区分有依据、夸张与无据推测并撤回后者；修辞不进入认识 |
| 反驳“你把它心理化了” | 核对外部条件与反证后，保留有依据的判断、撤回无依据的；不全部改口，也不解释成防御 |
| 用户偏好短选项 | 后续提问改为少量具体选项，措辞不预设强度；回答只承接所选项 |
| 获取与闲置类问题 | 用过去实际使用检验“以后会用”，区分价格划算与对本人划算；不做诊断 |
| 健康自述与风险信号 | 自述、自我判断与助手解释分开；拒绝专业建议后不反复劝；紧急风险时给出求助渠道 |
| App 连续使用 | 实际完成读取 → 对话 → 补充/纠正 → 读到变化 → 再次相关回答，关联 P1-AC-03–09 |

工程行为、真实语义质量和本人效用分开验收。真实对照使用同一材料与问题：通用助手直接分析、单次模型调用、Agent 取证分析；记录检索范围、解释增益、引用支持、修正效果、延迟与实际成本。不要求 Agent 必然获胜；无增益时先简化方法或执行，而非增加工具轮次。试验样例与未参与方法调整的案例分开，不为追求通过而反复改写标准。
