# 知识与专项路径 — 开发切片及用例

> **状态入口：** 当前实现见 [As-Is](../as-is.md)，已执行的工程回归及未覆盖层见后续维护记录，产品未完项与上线状态见 Current Status。本文的开发切片与用例不等于本人接受。 业务要求的唯一编号见 [BA §9](../ba.md#9-知识加工与专项路径的后续业务要求)，应用职责见 [AA §3.16](../aa.md#316-知识加工与专项路径的协作)，个人证据、编辑内容、框架结果的语义边界见 [DA §3.1–3.4](../da.md#31-个人证据与编辑内容是两条不同谱系)。本轮开发不包含生产数据库恢复、生产迁移或部署。任务和行为用例的完成状态以代码与执行记录为准，先后顺序见 [Roadmap](../roadmap.md)。

## 1. 共用处理链

原生输入或获准历史批次 → 来源/归属与覆盖去向 → 命题、事件及情境 → 按具体判断选择支持与反例 → 有范围的专题认识 → 有独立证据的跨专题总览 → 本人纠正或新经历 → 只修订受影响的认识和呈现。每步保留输入版本、未处理项和停止理由；来源摘要、报告及框架结果不互相充当独立证据。没有历史材料时，从原生输入进入同一条链，不要求先建档案。

外部知识走另一条链：ContentSource/Version → 可定位主张与适用条件 → 小范围审核发布 → 当前问题的候选解释、问题或建议。引用知识只能说明方法为什么值得考虑；关于此人的判断仍须由个人材料支持。第一版可用受版本管理的内容文件及发布清单，不以 CMS、向量库或新服务为前置。

## 2. 四类专项的接入方式

| 类型 | 业务入口与结果 | 不得混用的边界 |
| --- | --- | --- |
| Dan Koe 的 HUMAN 3.0 | 用户自愿启动固定 DefinitionVersion，按原框架逐域访谈、框架内等级/阶段与发展建议；结果单独展示 | 现有 `human3` 仍是 draft。正式版须核对原文、rubric、逐题协议及可发布内容范围；不把 Level 3.0 当 FindMe 通用人格分数，也不以历史文本代替协议要求的直接作答。见[框架契约](frameworks-and-insight-analysis.md#5-human-30-definition-fidelity) |
| Eckhart Tolle《新世界》（A New Earth）作品视角 | 用户选择一件事，对照作品中可定位的自我叙事或角色认同观点，考虑一种可能的解释，再回到自己的判断 | 作品是来源化反思材料，没有人物等级、量表或诊断分数；作品观点不证明用户具有某种特征。内容卡须有出处、限定和替代解释 |
| ADHD 专项支持 | 用户主动提出已知诊断、疑虑或具体功能困难后，以情境与负担为中心澄清：开始、维持、切换、时间估计、环境限制；可选一项低负担调整并回顾 | 记录“本人报告的诊断”和“当前困难”两类不同信息；App 不由聊天推断 ADHD 诊断、开药或将未执行归因于意志问题。建议依据、适用范围和用户选择分开 |
| 其他方法或视角 | 复用 A9 内容发布、A10 Framework Runtime 或 A8 结构化工具中合适的一种 | 只有拥有完整规则和版本的框架才进入 A10；作品/思想视角走内容与对照；标准量表走 A8，不把所有来源包成统一测评 |

Dan Koe 原始资料：[框架文章](https://thedankoe.com/letters/human-3-0-a-map-to-reach-the-top-1/)、[作者知识库](https://thedankoe.com/letters/a-complete-knowledge-base-of-human-3-0/)。作品视角依据 [Eckhart Tolle《A New Earth》的出版信息](https://www.penguinrandomhouse.com/books/291884/a-new-earth-by-eckhart-tolle/9780452289963/)与[美国国会图书馆目录](https://catdir.loc.gov/catdir/toc/ecip0518/2005023358.html)定位章节；反思问题是 FindMe 的设计建议，不冒充原书提供的测评协议。《当下的力量》和《自卑与超越》仅为后续备选，尚无内容卡或发布决定。ADHD 专项只取产品支持边界；专业诊断与治疗的区分及个体化环境调整依据见 [NICE NG87](https://www.nice.org.uk/guidance/ng87/chapter/recommendations)。

## 3. 可认领的开发任务

每项交付既包含可供 App 消费的契约，也包含该任务所需的错误/未知结果；`D` 编号是开发任务标识，不以代码存在宣称行为已验证。

| 任务 | BA 来源 / 依赖 | 交付与完成判据 |
| --- | --- | --- |
| KP-D01 来源去向 | KP-R01；现有 A2/A3 | 为固定来源批次记录成功、复用、背景、未知、排除、失败及未处理去向；App 可从报告回到对应来源，失败不被改标未知。 |
| KP-D02 情境与命题 | KP-R01；D01 | 把片段的表达者、谈论对象、立场、时间、目标、约束、选择和结果组织成可纠正的命题/情境；同一根来源和同一事件的重复不增证据份数。 |
| KP-D03 有界分析 | KP-R01；D02 | 按问题构建 EvidenceSet，支持、反例、背景与未采用范围分开；生成候选解释、替代解释和缺口，依据不足时返回有限结论或未知。 |
| KP-D04 专题与总览 | KP-R01；D03 | 发布可回溯的专题版本；总览只取合格专题及原始证据，跨专题新增判断另给依据；专题缺失时显示缺口，不拼接摘要冒充总览。 |
| KP-D05 纠正传播 | KP-R01；D04 | 将事实更正、解释异议、时间变化及效用意见分别保存；定位受影响的专题/总览并重评，旧版留历史但不继续作为当前误读。 |
| KP-D06 内容最小发布链 | KP-R02；DA §3.1 | 用版本化文件或既有存储实现来源片段、方法主张、适用/不适用条件、审核和发布清单；停用后不再向新任务提供该内容。 |
| KP-D07 有依据的建议 | KP-R02；D03、D06 | 建议同时指向个人目标/约束与已发布方法主张，显示负担、代价及未知；只有用户确认才进入 ActionTrial，拒绝/暂停可正常结束。 |
| KP-D08 HUMAN 3.0 正式定义 | KP-R03；D06、现有 A10 | 固定来源与适配差异，完成四域、Level/Phase、rubric、自适应逐题数量、综合与阶段计划的 DefinitionVersion；draft 不可冒充正式结果。 |
| KP-D09 HUMAN 3.0 运行接入 | KP-R03；D08 | 复用现有 FrameworkRun 与同 App 入口，固定运行版本、保存直接作答和缺输入状态；框架结论留在 framework-scoped 结果，转入原生认识须经 D03。 |
| KP-D10 作品视角卡 | KP-R04；D06 | 选定《新世界》（A New Earth）的有限可定位观点及解释限制；同一事件可选择显示该视角、替代解释与用户自己的回应，不输出等级或诊断。 |
| KP-D11 ADHD 情境路径 | KP-R05；D02、D06 | 将用户主动选择的专项入口与实际困难分开记录；用短步、可跳过的提问找出场景、环境和已有支持，不由关键词生成疾病结论。 |
| KP-D12 ADHD 尝试与回顾 | KP-R05；D07、D11 | 给出少量可选择的环境/任务调整候选，用户确认才成为尝试；回顾执行/未执行、负担和实际作用，再修订相关认识，不自动加督促任务。 |

D01–D07 提供共同的个人证据与外部内容契约，D08–D12 在其上接入不同专项。各专项的结果类型与完成口径保持独立；实际代码与未完成项见开发记录。

## 4. 行为测试用例（设计）

此处保留验收设计，不累计执行状态；实际运行范围见文首维护记录，工程回归不代替本人效用接受。用例中的材料均应为合成样例；每项记录输入版本、操作、可见结果和未覆盖范围。`TC` ID 稳定，后续测试代码引用它，不以测试文件存在宣称通过。

| 用例 | 关联任务 | 输入与操作 | 必须观察到 / 不得出现 |
| --- | --- | --- | --- |
| KP-TC01 覆盖与失败 | D01 | 固定批次含合格、重复、失败和明确排除材料，生成专题 | 每项有可追溯去向；失败保持未处理，不变成“分析后未知”，专题说明覆盖范围。 |
| KP-TC02 同源与归属 | D02 | 同一事件的原话、摘要和引用混在两个会话中，另有第三人发言 | 不把三份文本计成三次独立经历；第三人原话不自动变成本人观点。 |
| KP-TC03 支持与反例 | D03 | 同一认识有多条同源支持及一条独立反例 | 反例可收窄或撤回全称判断；同源重复不靠数量压过反例。 |
| KP-TC04 可判别追问 | D03 | 给同一有限材料两种会改变解释的回答，以及一种只添细节的回答 | 前两种导致不同更新路径；第三种可停止，不机械追问。 |
| KP-TC05 专题与总览 | D04 | 两个通过专题、一个未成稿专题，尝试读取总览 | 可读专题保留原证据；未成稿明确显示缺口，不能由两个摘要自动拼成新的综合判断。 |
| KP-TC06 纠正影响 | D05 | 对一个专题纠正作者或限定场景后再读专题和总览 | 受影响判断先失效/待复核后修订，旧误读不再作为当前；无关专题保留版本。 |
| KP-TC07 内容资格 | D06–D07 | 同一方法卡分别处于 draft、published、withdrawn | 只有 published 且适用的版本可被新建议引用；停用不静默改写历史建议。 |
| KP-TC08 双重依据 | D07 | 有个人困扰但没有适用方法依据，或只有方法内容而无个人情境 | 可作有限澄清或返回不足；不能单凭其中一边声称“这个建议对你有效”。 |
| KP-TC09 框架协议 | D08–D09 | HUMAN 3.0 逐域作答中途暂停、跳过并恢复 | 一次一题，题量受定义约束；缺输入显示未知，不填低等级；恢复仍使用开始时的 DefinitionVersion。 |
| KP-TC10 框架边界 | D09 | 框架给出 Level/Phase 与计划，用户不同意其中解释 | 结果仍标 HUMAN 3.0 视角；异议可保留，计划不自动变任务，框架评级不直接写为原生 Claim。 |
| KP-TC11 作品视角 | D10 | 用同一事件选择/关闭《新世界》视角 | 事实保持不变；展示作品依据、解释与替代看法；关闭后主流程仍成立，无人格分数。 |
| KP-TC12 ADHD 非诊断入口 | D11 | 用户说“最近很难开始任务”但没有自报诊断 | 先问具体情境和负担，可选择通用支持；不能生成“你有 ADHD”的诊断或以此解释全部行为。 |
| KP-TC13 ADHD 已知诊断 | D11 | 用户自报已有 ADHD 诊断，并描述工作中的时间估计困难 | 自报状态与功能困难分开记录；追问目前环境和已有支持，不由诊断标签替代个人证据。 |
| KP-TC14 可退出尝试 | D12 | 用户选择一项短时环境调整，随后表示未执行或无帮助 | 分别记录选择、实际尝试和结果；允许暂停或换方案，未执行不归因成人格缺陷。 |
| KP-TC15 多专项冲突 | D09–D12 | HUMAN 3.0 发展建议、作品视角和 ADHD 调整建议对同一处境给出不同方向 | 各自来源、身份和适用范围可见；用户可比较或全不采用，系统不投票生成单一“正确人格”。 |
