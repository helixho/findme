# 个人理解的输出维度、分析结构与持久信息

> 设计方案。分类与数据语义唯一正文为[DA §3.7](../da.md#37-输出分类与需要持久保存的信息)，应用协作见[AA §3.18](../aa.md#318-从满意样例反推输出方法)。本文说明输出组合、参考方法、实现差距与验收；不表示已实现接口、schema或真实效果，不规定模型与加工引擎。

## 1. 输出应达到什么结果

用户能读懂系统怎样理解自己、依据与适用范围是什么、哪些解释仍有竞争、什么信息会改变判断。表达有启发性和事实忠实分别评价；有用的解释可以保留为候选，不因共鸣或尖锐语气升级为已证实的动机。

Overview的四类提纲覆盖背景、行为、价值与解释，但混合了内容和分析层次，不能直接变成互斥存储枚举。采用DA的独立分类：生活领域用于覆盖，认识内容用于表达，分析作用用于组织本次推理结果；同一认识通过引用进入不同视图。

## 2. 可读输出的组合

| 部分 | 提供的价值 | 输出要求 |
| --- | --- | --- |
| 核心理解 | 少量具体、可质疑的综合判断 | 有依据与范围；不是强制生成一句人格标签 |
| 分项认识 | 呈现背景、目标、状态、模式、价值、资源与限制 | 按相关生活领域展开，不填空白维度、不把高频工作资料当全人格 |
| 关系与解释 | 解释条件、资源、约束、取舍及可能机制 | 张力两端各有依据；不同偏好未必冲突；替代解释并列，不必每次找到隐藏根因 |
| 未知与变化 | 展示反例、未决分歧及修订原因 | 区分本人变化、证据补充、分析纠错和框架变化；不悄悄覆盖历史 |
| 下一步 | 有区分力的问题或用户可选的尝试 | 结果应能改变判断；没有必要时允许结束，不每次强制行动 |

分析结构沿用[洞察分析契约 §10](frameworks-and-insight-analysis.md#10-insight-analysis-profile-contract)：实际问题、问题重构、生活支撑与缺口、张力、解释及替代解释、下一验证。它是可对用户解释的结果结构，不是模型隐藏思维过程，也不要求每次填写每一栏。

报告引用实际使用的认识修订和来源集合；相关修订变化时，当前视图采用新版本，固定报告标待更新或重新生成，不把更换框架的分数变化说成人变了。

## 3. 参考框架各自承担什么

以下是FindMe的设计取舍，不将不同理论合成为一套已验证的测评。

| 参考 | 吸收位置 | 不直接继承 |
| --- | --- | --- |
| HUMAN 3.0 | 四域覆盖、知识/经历/技能区分、跨域影响及发展方向；完整访谈结果保留在独立FrameworkResult | 不将Level/Phase/Metatype变成全局人格字段；不从工作材料推定Body/Spirit低水平 |
| McAdams | 特征与社会角色、目标动机、自传叙事的多层组织，提醒区分行为、自我要求与人生解释 | 不把actor/agent/author视为高低等级或固定评分 |
| SDT | 自主、胜任、联结提供关于需要及环境支持的解释候选 | 不从一次授权要求推出长期需要受挫，不据理论存在确认隐藏动机 |
| COM-B | 检查具体行为的能力、机会与动机条件；外部资源/限制不能遗漏 | 不把未执行自动归因意志薄弱，不默认需要改变用户 |
| 价值理论与可选测量 | 价值取舍可作解释视角；固定量表按对应协议另行使用 | 不从零散会话计算量表分数，也不把理论术语当独立个人证据 |

HUMAN 3.0的Mind可关联认知/情绪，Body关联身体/恢复，Spirit涉及关系/归属与价值/意义，Vocation涉及工作/创造及部分资源条件。这是多对多的界面与检索映射，不宣称概念完全等价。相同原文可供多个框架使用，仍只算同一份依据。

框架内需要保存的领域、等级、阶段、综合结果和版本已有目标契约；跨框架比较仅比较同案解释和实际帮助，不把不同等级换算成一个总分。未运行框架时不生成框架评价。

## 4. 已有能力与需要补充的信息

以下是实现职责映射，具体字段以源码为准。逻辑需求不等于必须新建表。

| 信息 | 已有载体或设计 | 待补部分 |
| --- | --- | --- |
| 稳定认识身份与修订 | `claims`、`claim_revisions`；ClaimKind/Mode/Status；文字scope、修订原因和证据状态 | 不另造画像库；结合后续分类与范围变化维护身份和版本 |
| 来源与证据 | `source_items`、`evidence_spans`、`claim_evidence`已有支持/挑战/背景与独立组 | 复用，不为每个框架复制；继续核对实际语义支持和来源归属 |
| 生活领域 | 诊断domain、知识topic及framework domain各有局部语义 | 固定会话导入已通过claim_revisions.details保存多选领域；普通生成尚未贯通分类版本、关联依据和覆盖投影，不直接套用某个框架枚举 |
| 内容分型 | ClaimKind含background/pattern/value/worldview/life_orientation/interpretation；事件context及专项对象承接部分目标/状态 | 目标、资源、能力、约束、自我叙事的通用结构表达不足；先复用已有对象，必要时补语义分面和校验，不能只随意扩一个字符串 |
| 情境与有效时间 | 来源/经历有时间，认识有文字scope和created_at | 固定导入的details已有有效时段/精度与项目/角色/场景；普通生成及查询仍需接续，created_at不能充当有效时间 |
| 认识间关系 | EvidenceLink已连接证据与认识；报告有nodes/links，设计中已有解释竞争 | 固定导入的details绑定较早的确切修订，并继承来源依赖；尚无通用关系编辑/查询接口，不能把局部关系视为完整图谱 |
| 分析结构 | Insight Analysis设计、诊断/理解报告已有相关字段；Gap承接未决问题 | 将分析中的引用角色与确切认识修订关联，避免报告、对话和专题各自维护判断 |
| 本人反馈 | Core有纠正类型；知识专题有fact_correction/interpretation_disagreement/temporal_change/utility_feedback等局部分类 | 固定导入已表达事实认可、解释认同、启发性、建议效用、异议与未明用途并绑定目标；普通交互尚未统一。用途为导入声明，不自动确认认识，不增加每轮必填问卷 |
| 框架结果 | FrameworkDefinition/Run/Result已有版本、领域、level/phase和综合结构 | 原生认识与框架结果映射、依据引用及失效接续仍需贯通；HUMAN 3.0内部定义仍是草稿，不能当正式测评 |
| 目标与行动反馈 | 领域已有Goal/Action概念，专项路径有建议、尝试和回顾 | 通用跨领域目标/行动到认识的关系尚需贯通，不另做待办系统 |

先补生活领域关联、结构化适用范围、认识关系及反馈用途这四类信息；内容分型按实际样例补足，框架结果优先复用。已落实的固定导入仅增加一个修订details字段，复用来源、认识、证据和反馈表；普通生成、编辑及界面仍按具体功能接续。代码能力见[As-Is §17](../as-is.md#17-固定会话与已有洞察的导入代码)。

## 5. 可公开的结构示例

以下是为解释分类而编写的虚构例子，不来源于本人会话，也不能当作真实模型效果证据。

| 虚构表达或判断 | 分类/分析位置 | 保存方式与边界 |
| --- | --- | --- |
| 某人说本周项目由自己验收、同事决定实现 | 工作领域；角色、目标与局部安排 | 保留本周/项目范围，不自动成为长期控制倾向 |
| 某人在不同任务中反复明确成果后让同事选方法 | 工作领域；候选行为模式 | 一条认识引用各独立事件；标题不同不复制认识 |
| 分析认为细致要求可能是维护授权边界 | 解释与问题重构 | 与所解释行为关联，保留其他解释；不直接当本人认可的动机 |
| 分析先断言害怕失败，后来因反例撤回 | 被撤回解释 | 当前输出停止采用；保留修订关系，不将旧说法重复计证 |
| 某人说这段分析很有启发 | 对分析的效用反馈 | 绑定分析版本；不等于逐条确认全部事实 |
| 建议先完成小样品再决定工具投入 | 下一验证、ActionProposal | 未选择和未执行都合法，不当成人格特征 |

## 6. 方法与存储的验收条件

- 一条认识跨生活领域/框架呈现，认识身份与证据数量不重复增加。
- 一次临时安排保持局部范围，未知生活领域不被填级或诊断为缺陷。
- 观察、解释、本人反馈与建议分别表达；认可启发性不能自动确认解释为真。
- 新反例可收窄或撤回解释，相关关系和视图失效，无关认识保持。
- 相同事实换框架只改变框架结果/分析视角，不改写原始事实，不把方法变化解释成人格变化。
- 每个关键结论可以回到原始输入与确切版本；助手的上轮分析不是独立证据。
- 满意样例用于提炼方法，验证还需新案例与反例，避免把样例结论写进提示词后循环证明自己。
- 内容质量分别看忠实性、范围、解释增益、反例响应与本人效用，不设统一人格准确率或未经标定的分数。
