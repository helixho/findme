# AV 整体理解与统一 App 交付

> **阶段关系（2026-10-30）：** 本文保留既有 AV 全量理解与统一 App 的交付义务。整体愿景按 [ADR D24](../adr.md#d24-赛博分身作为愿景先形成可持续使用的个人理解)，当前先推进[第一阶段持续使用](../delivery/phase-1-personal-understanding.md)。有界基线可以先使用并持续修订；这不取消本文的内容覆盖、未完专题/overall 或框架验收，也不将它们全部作为本人开始使用的前置。

> 已确认的目标与验收契约，不是功能完成声明。业务完成口径以 BA 为准，对象与关系以 DA 为准；本文收口用户界面、交付内容、材料到报告的检查及现有实现的接续方式。代码切片见 diagnostic-product-plan.md，优先级由 Roadmap 管理。

## 1. 固定交付目标

用户打开同一个 FindMe App，即可阅读基于已授权 AV 快照的个人理解总览，进入专题和独立框架报告，回看依据、补充经历，并看到真实修订。用户不必先提出精确问题、理解 L1–L3 或审阅所有中间记录。
“找我”是持续目标，不是从画像转向纯聊天。标签用于组织，画像用于概括，框架提供视角，诊断解释现状，探索检验和修订；理解本身可以有价值，行动不是每次必需的产物。
整体报告完整组织当前有依据的内容与未知，不承诺完整认识整个人，不强制填满固定生活领域，也不把报告正文长度或五条摘要当作覆盖充分性。

## 2. 输入范围与既有产物复用

- 固定快照截止时间、来源版本、允许处理的主体和输入集合；后续新增 AV 不自动属于该批次，也不把数据库总行数当本人表达。
- 复用已核验 L1、L2 索引、原文定位和生成记录；已有 L3 仅用于查找候选主题和待复核命题，不当作新的独立证据。
- 主基线继续排除保留的 holdout 及相关组；留出材料的独立处理不等于主模型已使用。正式打开留出测试前固定评测协议，不用于反复调优。
- 完全处理允许“背景材料”“未知”“排除”“同源复用”“暂未形成认识”等明确去向，不要求每句都生成洞察；不把未处理或无声截断混成这些状态。
- 工作/AI协作可能是主要资料范围，但领域由实际内容决定。不可因旧 Prompt 只写工作，就主动丢弃已有的生活、动机或其他相关本人表达。
- 对压缩遗漏、归属不明、规则变化或来源更正定向回读/重算；不因新界面或新框架再次无差别全量抽取。

## 3. 内容覆盖检查与情境组织

每条源片段记录加工状态；每条原子候选记录主题/情境归属和采用、背景、未知、排除或复用理由。一个材料可以属于多个主题，统计仍以源标识去重，不能多次出现就增加独立证据。
主题从整批内容及用户目标形成，不从“自主性”“完美主义”等预定结论反向筛选。先盘点全体合格候选及未采用范围，再按主题有界分析；不能用几次问题检索覆盖检查的全部职责。
每个主题记录有哪些本人表达、反例、不同情境和时间，哪些只具线索价值，哪些尚未形成判断。对重要未采用材料及归属不确定区域抽查漏检，不只检查已选证据。
L2 会话索引继续保留；跨会话情境连接须明确目标、条件、选择、结果和时间的依据。无法确认是同一次经历时保持分开/待核查，不能按同项目或相似文本自动判同事件。
分组压缩与总览选择保留来源映射和省略理由；总览没展示的主题仍可在专题里访问。加工完成、内容覆盖已检查、个人理解有效性和 App 交付分别验收，定义见 BA §4.10。

## 4. 个人理解基线与旧结果校正

基线是持续维护的报告版本集合：综合总览、主题判断、主题间关系、已有资源及其适用条件、可能的成本、变化和待澄清问题。它复用 Claim/Revision、DiagnosticRun/ReportRevision 与 ProfileView，不新增另一套正式人格库。
总览按重要性组织已有专题，新的跨专题解释必须重新给出合格证据与范围，不能把若干模型报告投票或摘要再摘要当作证实。专题部分允许未完成和不足，但不能把未读区域标为已分析后未知。
旧认识逐条按当前规则核对，保留 unchanged / clarified / expanded / narrowed / weakened / reversed / withdrawn 及理由。兼容条件不再保留成已确认的代价性冲突；没有新判断时可以维持有限认识，不为展示进步强行升级。
系统更新规则不等于历史产物已经更新。基线固定源快照、实际 EvidenceSet、主题/情境映射和处理版本；受影响内容未重评时清楚标记待复核。旧版可回看但不能绕过当前来源排除/删除。
用户纠正一项作者、对象或背景后，依赖专题和总览先失效/待复核，随后重评；其他专题保持原版本。解释异议、事实更正、仅限定范围、时间变化和效用评价分别保存。

## 5. 唯一主入口与内容结构

沿用 `apps/app` 的首页—探索—当前认识主导航，资料管理在二级入口。技术路由可在实现时确定，但验收不能要求用户在多个 localhost 端口、目录或独立 Markdown 中寻找自己的报告。

| 位置 | 默认内容与用户动作 |
| --- | --- |
| 首页「我的当前理解」 | 一段整体判断、重要主题入口、主要覆盖范围与时间、当前最值得澄清的一件事；有材料时不以空白聊天框或数据计数为主体 |
| 当前认识／综合总览 | 当前状态、重要目标与价值取舍、优势及条件、可能的限制与相互影响；具体判断和未知分开，不是只有免责声明 |
| 当前认识／专题理解 | 主题结论、情境解释、支持/反例、竞争解释、范围及待确认问题；主题由材料与关注点组织，不要求填满固定人格维度 |
| 当前认识／框架报告 | HUMAN 3.0 等独立运行，显示协议版本、已完成/缺少输入、结果及发展建议；未运行不显示假分数或假报告 |
| 当前认识／变化记录 | 哪些判断保持、澄清、收窄或撤回，关联新来源/用户更正/规则变化；旧版只读，不把新文案当本人改变 |
| 探索 | 从专题或总览继续，携带目标报告/判断版本和未决问题；补充真实输入、提出反例或质疑后更新相关报告，不另起与历史脱节的聊天 |
| 我的资料（二级） | 导入范围与处理状态、原文与归属纠正、导出与数据管理；诊断里也能直接展开其证据；L1–L3 仅作可选高级视图 |

报告是服务端/运行层持有的版本化结构，App 渲染同一份内容，不在客户端另写一套诊断 Prompt，也不每次打开都重新生成。一级阅读不展开长 ID 和全部证据，点击依据后可到精确片段、必要上下文、作者及有效状态。
“这不准确／仅某情境成立／以前如此现在变化／继续理解”是诊断的直接操作。保存先成功，真实推理另显状态；pending 不能显示为已理解，自由输入不由合成脚本决定结论。
自我理解、放下错误的自我描述、明确当前取舍都可以作为成果；可选发展计划不自动变成任务、打卡或外部操作。

## 6. 完整框架的独立交付

HUMAN 3.0 完整接入继续按 Framework spec 的来源、版本、rubric、逐域访谈、综合解释和发展计划执行，不能被原生局部问答或框架目录占位替代。历史可复用程度按该版本输入协议决定，缺少的关键证据补问；相应协议不允许用历史替代作答时必须按原协议取得输入。
历史辅助初评与原协议完成结果分别呈现；原生基线无需等完整框架访谈完成才可阅读，但不能据此把该框架标为完成。框架内等级允许有明确结论，资料不足则标缺输入，不填低等级；其结果始终是一个视角，不覆盖原生认识。
“有框架入口”“框架定义可用”“完成一次完整运行”和“对用户有价值”分别验证。保留明确的框架交付切片，不通过无限期后置而实质取消已确认方向。

## 7. 数据与接入边界

正式服务继续采用既定主库、对象存储与派生索引分工，见 DA §8 / TA §2.1；不按 L1–L3 另建数据库。基线与专题以既有认识和报告版本为权威关系，JSON/JSONL 用于交换、回放和私有验收，不作为第二套正式个人库。
本人验收入口按 [ADR D23](../adr.md#d23-账号模式云端数据库为唯一运行真源其余运行路径冻结或退役) 走账号模式：已通过专题一次性导入主库，旧本机私有 repository/adapter 冻结，不作为本轮验收入口。私人 JSON 不放进 frontend public、静态 bundle 或 Git；读取时验证源快照、当前用途与版本，缓存不得绕过排除。
过渡期只保留归档快照的只读接口，导入核对一致后退役。账号模式 repository 继续遵守现有报告/反馈契约；UI 不硬编码本机路径，不从浏览器直接读取电脑文件。
正式入库先做映射、幂等与依赖校验；已有候选不默认变为本人已确认，L2 索引不默认变为独立经历。实际迁移、服务切换与部署按明确范围执行，不因正文更新触发。

## 8. 验收关口

| 检查 | 通过条件 | 不能替代它的产物 |
| --- | --- | --- |
| 处理范围 | 截止时间、允许集合、成功/复用/失败与未知记录可回放，计数可对账 | 一个未定义含义的 complete=true |
| 内容覆盖 | 重要主题与未采用材料有可检查去向，抽查漏检和压缩丢失；无声遗漏修复或明确待处理 | 只给已有五条摘要改排版 |
| 情境与基线 | 主题判断、反例、范围和跨主题解释有依据；同源/同项目不冒充独立事件，旧结果按当前规则处置 | 对旧 L3 再做一次风格化扩写 |
| App 真实交付 | 同一主入口读取真实总览和专题；证据可回看，真实补充/纠正触发相关报告更新，刷新可恢复 | 独立 Markdown、多个调试端口、合成页面或仅保存反馈 |
| 框架运行 | 完成度与实际协议输入一致，结果/缺口/计划可回溯 | 框架卡片、默认等级、由原生摘要猜出的整套测评 |
| 价值与修订 | 本人能指出新增理解、误读纠正或未产生价值；无须改变也可结束，结论变化与依据相称 | 模型自评、标题变了、测试数量或用户简单赞同 |

工程覆盖、语义抽查、本人效用评价分别留结果；部分诊断可以先交付并标明范围，但未过的关口不能合并成“全部完成”。验收使用真实 App 流程，测试夹具不含私人正文。
