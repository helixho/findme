## 1. 交付目标

一个没有 AV、没有 Codex、不让电脑常开的用户，也能在手机/电脑登录后开始交流，读取并使用当前个人理解，得到相关解释、支持、建议或诚实质疑。新对话、经历、学习反馈和导入材料能够按来源与情境形成或修订认识，之后的回答与可读视图使用更新后的理解。丰富历史用于减少重复说明和增强理解；零历史路径独立成立。
本人当前交付是：已有 AV 在明确范围内充分组织为个人理解基线，在同一个 App 中阅读总览、专题和独立框架结果，并从真实输入持续修订。完整内容与验收见 [统一 App 契约](av-understanding-app-delivery.md)。
不继续以 L1–L3 浏览器作为主产品，不做多框架投票、统一人格总分或多数据库堆叠。标签与画像不被取消，HUMAN 3.0 完整独立接入亦保留；核心是有依据的自我理解，不强迫每份报告都产生行动。

**本轮指定范围已完成。** CD-01/CD-02职责拆分、CD-11实际依赖链修补及过时内容清理，见维护收尾记录。当时候选的小程序构建/watch、XML 压缩和可选预渲染验证保留为历史证据；这些能力随 D25 独立客户端退役退出，不再要求维护。

### 工作包 2：运行依赖核对与产品差异设计

**接续已完成的指定维护；本工作包核对范围和差异，不直接部署。** 2026-10-31：产品侧中“对话使用当前理解、新输入进入认识、纠正后的使用”三项已按 [ADR D26](../adr.md#d26-对话使用-core-当前认识并自动处理新输入) 在[主链契约](p1-main-chain.md)给出结论；运行侧资源核对、诊断/知识专题衔接与来源容量按本人决定后置，仍未完成。

运行侧只读核对账号 API、App、可用主数据库、推理出口、任务队列、源档存储与域名的实际状态，区分历史配置、可用资源和仅存在的代码。继续现有账号主库/React App/服务端处理方向；旧欠费 Neon 不恢复，不因配额刷新自动启用，不把本机临时测试库或 Mac 常开当作持续运行方案。需要新资源或费用选择时，基于核实的候选给出推荐与取舍，不在计划中预定供应商。

产品侧以 AA/DA 的既有职责作差异设计，明确以下实际落点：

| 设计问题 | 本工作包必须给出的结果 |
| --- | --- |
| 唯一浏览器客户端如何交付 | 仓库已按 D25 退役 `apps/web` 与 `apps/miniapp`，仅保留 `apps/app`；手机 H5 与桌面同代码。核对目标线上入口与 API 组合，保留 App 内部兼容及后端/数据边界，不重新决定两套客户端是否删除 |
| 普通对话怎样使用当前个人理解 | 当前有效认识、相关经历/约束、反例与未决纠正的选择契约；回应固定其使用版本，用户可以换题或结束 |
| 一条新输入怎样进入认识 | 输入先保存，再核对归属、情境与支持关系，形成新认识、修订、保持不变或未知的明确处理结果；失败可续做 |
| 诊断专题与知识专题怎样协作 | 说明各自呈现和加工职责、引用的同一认识版本及更新时间；不先按页面名称机械合并表或新增第二份个人真值 |
| 纠正与知识反馈怎样传播 | 事实纠正、解释争议、情境限定和时间变化分别处理；作品/方法内容与个人回应分开，明确当前判断与后续回答的失效/更新时点 |
| 有限来源容量怎样处理持续积累 | 明确选取/分批和未覆盖去向，保留精确来源与同源身份；不能把完整分页选择等同全部内容已分析 |

**交付。** 一张实际运行组合与待决项表、线上入口切换验证安排，以及以上差异的接口/状态衔接、同一条纵向场景和测试安排。只补现有契约缺口，不扩建通用 Agent、人格图谱或知识平台。质量案例同时准备，不等上线后才定义何为“有帮助”。

### 工作包 3：修复后部署验证现有能力

**进入条件。** 工作包 1 的实际修复完成，工作包 2 已明确可用资源，候选提交与必要迁移/配置匹配。维护项未完成时保持本包 blocked，不先发静态空壳充当可用入口。

按既有迁移方案和运行规程验证已实现路径：正式 App/API 组合、账号登录与持久状态、来源保存/读取、刷新/重进/另一端一致、失败和重试；涉及队列或托管原档的功能，再实际核对投递/恢复与原档往返。保留定时默认关闭决定，不重算全量材料。

先用合成数据检验部署组合，再按已明确的资料范围使用合格历史。模型出口只做有边界的连通和行为测试，沿用任务预算；“能调用模型”不等于“理解正确”。本包产物为实际入口、候选版本、可用功能、失败/未测项和恢复路径的记录。

**入口收敛。** 仓库退役按 D25 已落实，不再设置“先承接全部 Legacy 功能再删”的门槛。部署时验证 `apps/app` 的手机 H5/桌面入口、独立 App 静态配置与无旧 Web 资产的 API Worker，并核对线上旧页面实际退出。AD-11 的在线部分须有运行证据；App 内部兼容、后端、数据、迁移及选定设计不在此次清理范围。

**退出。** 现有功能在目标运行组合上得到证据；AD-01/CD-14 按入口与多端组合的实际验证关闭，不能仅凭目标站点可访问销项。AD-03 的快照退役仍须待真实导入对账和读取等价完成，不因 App 可访问提前关闭。此时接受的是工程运行基础，不是 P1 全部能力。

### 工作包 4：先贯通一条个人理解与持续对话主链

首条主链代码与合成验证已完成；没有真实模型或本人证据，本包退出条件未满足。

**目标结果。** 在同一账号 App 完成“阅读当前理解或零历史起步 → 交流/补充 → 保存来源 → 有依据的认识处理 → 再次相关提问 → 使用更新后的理解”。不另建聊天演示页，也不强制每轮生成完整报告。

| 纵向步骤 | 必须落地的行为 | 验收关联 |
| --- | --- | --- |
| 起步与回应 | 零历史从具体经历或中性问题开始；有历史选择相关当前认识。回应可支持、解释、建议或质疑，必要时才追问 | AC-02、03、06 |
| 保存与处理 | 用户原话、情境和时间可靠保存；保存状态与处理状态分开。有效新来源能形成或修订认识，而非只引用既有 Claim | AC-04 |
| 纠正与版本 | 事实误读、范围限定、解释争议和时间变化分型处理；失效依据立即停止当前使用，未决保持可见；处理失败不丢输入 | AC-05 |
| 后续使用 | 下一次相关回答及当前视图引用更新后的版本；已知错误不再次成为前提，无关认识不被全量重写 | AC-01、04、05 |

优先用一条合成场景验穿：原判断适用范围过宽 → 用户补充“仅在某种情境下成立” → 形成收窄或保留争议的处理结果 → 新一轮回答显式使用当前范围；另设“新信息不改变原判断”反例，避免强制制造更新。工程断言检查实际读取的认识/依据版本，不只检查回复包含某个词。

既有 Core 版本、资格、幂等和失效能力继续复用；系统自己生成的回应不能成为其个人判断的独立证据。先完成这条主链的正式 API、App 与行为回归，再扩展横向专题和内容规模。对应 P1-AC-02–06，实际入口与跨端依赖工作包 3。

### 工作包 5：有限知识反馈与历史增强

**知识辅助。** 先接当前已有且适用的一条来源化内容路径，不扩充完整知识库。作品回应不能只在本次请求回显，需持久保存为个人来源并保留内容版本；行动回顾不应止于“标为待复核”，需进入工作包 4 的修订与后续使用。理论提供解释/做法，个人反馈才提供关于本人的证据。实际采用的路径须通过 P1-AC-07，而不是以另一路径可用掩盖本次承诺未接通。

**历史增强。** 从已支持格式和经复核通过的 U2 专题中选择明确范围，一次性迁入并对账原版本、审核出处、来源根身份、精确引文和重复提交；未审核候选、未成稿专题与 overall 不提升资格。超限分批/选取并显示未覆盖内容，保留无导入路径，不重跑全部语料。只有账号读取等价、对账完成后才退役对应快照路径。

**并行技术验证关联。** TV-01 比较 Hindsight / OpenViking 对多源来源、证据与认识更新的增益和最小接入代价；研究独立开展，**不作为本工作包开工/退出前置**，未有实测与明确选型前不替换 Core、U1/U2 或账号数据模型。

**退出。** 知识回应/实践反馈实际影响后续理解；历史资料能减少重复说明或增加可核验认识，来源遗漏和容量限制可见；同一候选完成 AC-07/08 并复验 AC-04/05。既有 U2 未完专题、旧认识校正与 U4 完整框架保持独立交付状态，不因本阶段有界起步而取消。

### 工作包 6：真实回答质量与本人连续使用

工程用例不能证明回答有用。本包沿用 P1 范围，分别检验支持/建议、可能自我美化、过度自责、模型误读、用户反驳、证据不足以及纠正后再次提问；每例核对个人依据、其他解释、范围、所用版本和未解决问题。用户赞同、语气刺耳或模型自评分都不单独计作通过。

本人在实际入口完成连续使用，记录具体得到的新认识、支持、质疑或建议，以及无用/误判之处；Agent 不代写反馈。采用相关案例的真实模型质量、跨端运行证据与本人实际接受共同更新[接受记录](../delivery/acceptance.md)。失败返回具体能力或方法改进，不用增加语料量或更多框架制造进展。

**第一阶段退出。** P1-AC-01–08 的能力及质量有对应实际证据，P1-AC-09 有本人反馈和具体价值；工程通过、部署成功、业务接受三者分开。实现完整分身、未来 Agent/Skill 形态和外部代理能力仍按后续真实需求评估。

## 4. R0 — 研究与参考诊断（编码前的业务输入）

按 研究协议 的 R0 交付已形成：方法地图与组合建议、参考诊断及同案比较、输入契约。C1 以这些成果做设计评审和原型，不把合成案例的可读性等同真实用户收益，不为每个框架重跑全量 AV。

## 5. C1 — 诊断契约与可读体验

本切片的具体交付、合成演练边界、纠正和可恢复验收见 [C1 诊断预览契约](c1-diagnostic-preview.md)。实现原型不代表已完成在线模型、正式账号或云端同步；自由文字须保留待分析状态，不能伪装成已生成新的个人诊断。

`packages/core/src/diagnostic.ts` 已定义 DiagnosticRun、ReportRevision、分项结果/证据充分性、关键问题、反馈与复评契约；确需框架运行时与已设计的 `framework.ts` 协作，不新建平行认识真值。
`apps/app/src/diagnostic-preview/` 已提供独立合成预览，继续使用既有 App/设计资产；不连接正式 API 或修改原生入口。默认先读核心判断、相互影响、解释与建议，证据按需展开；提供补问、纠正、范围限定和过去/现在变化入口。
可用参考诊断和只读 staging 适配验证，不先迁移全量数据或开发完整框架中心。若使用原始 L1/L2 取证，明确数据授权与本次范围；旧 L3 仅作导航，不能直接扩写。
退出：三个起步场景均能得到可理解的有限报告；unknown 不显示为低等级；无需审核几千条数据；发现缺口时回到输入/方法改进，不用视觉掩盖空洞解释。

### C1 后的真实推理验证

已按 [真实取证与受约束复评](diagnostic-evidence-reasoning.md) 实现独立 Node 入口，覆盖有限原文取证、立场候选、显式复评类型、独立语义复核和可恢复候选输出；它是 C3 推理能力的先行验证，不等于 C2 云端存储或正式在线 UI 已完成。C1 合成页面仍不调用模型，不将脚本回应伪装成真实诊断。

验收同时检查已选材料与遗漏、立场不升级、新输入对旧命题的实际作用、问题与建议是否随结论同步变化，以及审核失败时不发布。保留关键词/词面检索与模型审核的局限，后续根据真实误判和漏检改进，不靠每个框架重读全部 AV 增强信心。

U1 先给可靠去向，再由 U2 整理与综合；U3 可并行开发契约消费，但验收必须使用真实材料和真实修订。U4 的协议整理可并行，完整运行仍单独验证，不因 U3 可用就永久后置。本人可先阅读部分已审核通过的专题报告，但不能把 U1–U4 未过的关口合称全部交付。
不为每个专题或框架重新跑全量 AV；复用成功加工和主题下的合格证据，出现遗漏/规则更正时只重评对应部分。当前受限 runner 的全批指纹属于保守实现，U3/C3/C4 应细化受影响依赖，不能把重新运行成功等同已实现精准增量。
保持用户预览、模拟数据与真实本人数据入口分型；验证 U3 时不删除旧工具或启停服务来掩盖尚未接通。所需源快照/旧结果读写和实际服务切换应按已授权范围执行，正式 DB 迁入与开放第二用户保持独立关口。

## 6. C2 — 云端权威数据与账号基础

C2–C4 的源码已写入，实现见 [C 系列契约](c-series-cloud-runtime.md)；以下保留各切片的退出条件，验证入口见[测试计划](../delivery/phase-1-test-plan.md)。

延续 `schema-core.ts` 和 Drizzle/PostgreSQL，补足片段归属/表达类型/立场的修订、来源外部版本与可用性、诊断运行/报告/依赖关系。表是否合并以检索和事务需求为准，不直接按概念清单建全部表。
利用 `core/identity.ts`、既有认证入口和 identity_bindings 接入账号 principal；处理首次绑定并发、会话失效、多端与租户引用完整性。实际认证 provider 在切片设计时核验，不把 legacy 单口令会话当成每人独立账号。
source-blob/storage 接口：主库保存精确摘录与必要上下文，原始大档案用对象存储（R2）或明确本地引用；授权、可用性、保留与删除分开处理，不自动开通资源。
数据库迁移先生成并在独立测试环境验证，保留 legacy 表和已有数据。运行角色、RLS/显式作用域、跨表关系、对象下载授权、队列/缓存/导出联合测试；主库与对象存储失败采用可恢复状态，不伪装跨系统原子提交。
退出：两个合成账号及各自多端会话不串资料；保存/恢复/过期/冲突正确；不依赖本机目录可读已有证据和报告；迁移/回滚方案可审阅。真实数据迁移、服务重启与部署须另行授权。

## 7. C3 — 在线诊断取证、访谈与报告闭环

C3 既有诊断路径保留；第一阶段还要按 AA 的持续对话职责使用当前个人理解。普通回应无需每轮生成完整报告，只有必要时补问；有价值的新信息进入同一来源、认识与修订链。下列既有处理能力不能单独证明正式持续对话已贯通。

诊断编排与证据选择（相关实现见 `apps/api/src/cloud-diagnostic/` 与 `apps/api/src/diagnostic-reasoning/`）覆盖：零资料引导、历史预填/本轮作答分型、按方法要求取支持/反例/情境、初评、只补关键问题、报告版本和再评。复用 operations、Source/Evidence/Claim 和队列，避免多个模块同时决定当前真值。
A8 只承接确定性量表；A10 执行经确认的外部框架协议；综合报告固定使用哪些方法及结果。研究选出的最小组合先行，不把所有候选都接上、不混算总等级。
正式任务改由个人理解 Agent 执行，既有模型适配和超时/usage/引用/schema 验证及预算按步骤复用；当前 Codex CLI 保留既有研究适配，不作为普通用户安装前置。保存输入不等待推理，异步任务在生成前/发布前复查资格与版本；获取报告不会触发新调用。
App 使用同一云端身份恢复问题/报告，零历史用户可先得到有限初评；台式机关闭后手机可提交新回应并完成报告，不依赖另一设备执行模型。
退出：不用导入也能完整运行；语言、输入模式、未知和框架边界清楚；用户纠正可使过期结果停止当前展示，旧模型回包不能覆盖新状态；同案增益与成本有实测而非自报正确率。

## 8. C4 — 历史增强、持续修订与分发验收

将 `dogfood/layers` 的稳定解析、精确引用和去重能力复用到 Core ingest，先给映射预览/dry-run：来源定位与版本、归属/谈论对象/立场、用途/冲突、时间、同源、留出、人工反馈和依赖一并迁入。不能把自动 L3 候选标为本人已确认，不能把 L2 会话索引标为独立生活事件。
先迁移有限可核验范围并检查幂等、数量与引用、失败恢复，再决定是否完整导入；原始批次保留原貌，主库成为正式运行真源，JSONL 仅作交换/回放。不因需要云端数据就重新让全部原文经过所有框架。
补足反馈到 Evidence/Claim/Report 的影响传播、跨设备版本冲突、选择性重评与复评解释。已排除或删除的来源立即停止读取/生成；不相关诊断不全量重算，报告生成/模型变化不伪装成人格变化。
导出覆盖源摘录、框架作答/结果、诊断版本、反馈、依赖和未包含的本地原档说明；删除同时处理对象、索引、缓存、任务与报告可见性。保留历史不能绕过用户删除要求。
退出：丰富历史相对零导入减少了重复提问或增加可核验认识；同一反例在手机提交后电脑报告正确更新；采集器断开不阻断主流程；用两个合成用户验证账户、查询、队列、缓存、导出/删除全链隔离后才开放第二人。
桌面采集器、更多量表/框架、原生客户端包装、完全离线模式另看实际增益，不是本切片的前置。

## 9. 不可省略的验收与非目标

| 验收面 | 必须观察到 |
| --- | --- |
| 业务价值 | 当前理解能用于支持、解释、建议和有据质疑；新输入和纠正影响后续使用，综合呈现有范围、可回看；不要求用户审核全部中间数据 |
| 方法可复核 | 报告逐项说明采用哪个协议及版本；量表分数不从文本猜测；缺资料不等于低等级 |
| 证据与修订 | 引用可到精确原文及归属；支持/反例/背景分开；纠正生效后旧结果不能恢复当前有效 |
| 多端与身份 | 同一账号不同设备恢复同一状态；离线旧提交不覆盖新修订；不同账号不能猜引用越权 |
| 生命周期 | 托管/仅本地可用性真实；导出范围完整；排除/删除约束主库、对象、索引、队列及快照 |
| 成本与失败 | 分层/逐调用用量可核验，未知保留；任务可停止/恢复；没有输入变化不全量重跑 |

不启动新的数据库/队列体系，不把 RLS 当成已完成隔离，不要求一次实现完整 A1–A10，不做框架 marketplace 或组织管理。必要时收缩默认框架与输出范围，不能降低来源与修订门槛制造通过。
