# AV 本人内测 v0.1

> 适用边界：本机 AV/U2 加工路径已按 [ADR D23](../adr.md#d23-账号模式云端数据库为唯一运行真源其余运行路径冻结或退役) 冻结。以下保留既有加工、恢复和来源语义，供历史核对与显式导入使用；不构成重跑私人材料或恢复旧入口的授权。当前交付与未完项见 Current Status。

## 目标与范围

以已授权的 AgentsView 历史小样本，验证本人表达归属、共享证据加工、跨事件洞察和纠正。先验证本人的收益，不以框架数量、报告长度或用户赞同作为准确性证明。

本轮交付一个可重复运行、可审阅的内测垂直切片。读取 AV 原档只读；批次原文、候选、反馈、运行账本存于仓库外独立目录。内测结果属于 staging，复用 Core 的 Claim/Evidence 语义，不写 production，不建立第二份正式个人真值库。界面复用现有 App 技术和样式；本地内测入口不影响原生在线路径。

不部署、不迁移线上数据库、不恢复 TencentDB runtime、不全量导入、不实现完整 Framework Runtime、标准量表、行动任务或多用户。HUMAN 3.0 保留完整接入方向，但不作为本轮前置。

## 首批样本与隔离

- 初始批次目标为 24 个有人工参与的会话，18 个开发、6 个留出；实际不足须记录，不补造。
- 用只读 SQLite 一致性快照读取；不得为采样启动 AV daemon、sync 或修改原档。
- manifest 固定来源版本、session/message 标识、内容指纹、选择原因、split 和处理版本；原文不提交 Git。首批使用带时区截止时间，避免本次开发产生的新任务污染样本；无可解析时间不能冒充处于已限定时段。
- 优先覆盖本人自述、长转发加点评、引用 AI、项目约束、方案取舍及纠正。长度只能用于抽样覆盖，不是作者判定。
- parent/root、相同 source UUID、重复正文等已知关联必须成组。未能确定底层事件独立性的，标 unknown；不能宣称 holdout 已无语义泄漏。
- 留出内容不得进入开发抽取、缓存、摘要、提示调优或综合；独立事件组人工核查后再用于正式对照。
- 一次性指令、短回复和重复反馈不整类删除；结合必要上下文判断其用途。

## 来源与归属

消息的 role=user 只代表提交者，不代表内容作者、观点持有者或谈论对象。
每条候选证据保存原文片段及定位、内容作者、谈论对象、表达类型、明确立场、相关材料定位、时间/情境、判定主体和版本。作者、对象与表达类型均可纠正，避免错误 quotation 标签成为不可恢复的排除。
表达类型至少区分本人自述/评价/选择、工作要求、引用第三方/AI、系统包装、未知。mixed 消息可拆片段，未采用范围仍可回看。
本批已知长段转发不直接成为本人观点；无标记长段先按引用候选/未知处理，不机械全部删除或认定作者。
肯定一条评论不代表接受全部内容；明确认同与引用本身分别保存。AI 内容可作指代上下文，不作为本人事实的独立证据。
片段必须精确对应原文；外部材料不可通过摘要、重复引用或后续框架结果洗成独立证据。

## 加工与运行契约

1. freeze：只读采样并冻结 manifest/raw，不调用模型；再运行同一批次不得静默覆盖。
2. extract：按开发 split 和显式选定范围，分段生成候选证据及情境。保存精确引用与未知，允许空结果；超预算部分记录 pending，不静默截断成已完成。
3. review：采用、排除、作者纠正、谈论对象纠正、情境补充与解释异议分型；人工纠正可覆盖模型候选但不能重写原始档案。
4. synthesize：只用合格且当前有效的证据，生成少量有范围的观察/假设/张力、反例、替代解释及区分问题；具体版本和失效规则见 t1-r2-cross-experience.md。
5. compare：相同模型和相同开发原文范围对照直接分析与分层分析；保存独立产物，不相互作为证据。
6. replay：插入纠正或新事件，验证依赖失效与范围更新；holdout 只在单独显式评测动作中打开，不能用于继续调 prompt。

原始输入、候选和人工审核分开；自动候选不标为人工已确认。不把模型自报 confidence 作为准确概率。语义支持、作者识别和跨事件独立性需要样本复核，schema/关键词验证不冒充已解决。

## 成本与可恢复

模型只通过既有 M-X2 出口调用。首批策略上限是 30 次 provider 请求、合计 200000 预估输入 tokens、每次最多 2500 输出 tokens；这是内测执行预算，不是模型极限或测量效度。live 命令必须显式 opt-in；默认 dry-run。正式调用前按请求含 prompt 的 UTF-8 bytes 保守估量预留预算，实际 usage 另记，不能把字符估计标为 tokenizer 实测。
本地 Codex CLI 出口可在 API 凭据不可用时用于本人内测；规则和证据资格不变，运行时关闭无关工具与历史记忆。CLI 记录实际可见的 turn usage；次数单位为 CLI execution、底层请求数未知，2500 输出 token 仅为目标而非 API 硬上限，输入估量额外预留固定运行开销。不得将 CLI/订阅用量标成生产 API 费用。
每次实际请求（包括失败、解析失败、SDK 重试）都有账本；必须可限制 timeout/retry/output，避免隐藏重试越预算。记录层级、输入指纹、规则/模型版本、输入/输出/缓存 usage（未知为 null）、耗时、错误类型；普通日志不含正文和 secret。
任务幂等键由 source revision + attribution revision + policy/prompt/model version + 输入集合指纹构成。无变化不重跑；纠正只重评相关依赖。历史回填先完成低层，再集中综合，不逐条刷新全局画像。

## 验收与退出

合成测试覆盖：混合引用、短指代、转发认同边界、谈论第三方、精确定位、同源去重、holdout 隔离、幂等恢复、预算停止、失败 usage、纠正失效、旧结果不能覆盖新版、刷新不调用模型。
真实审核覆盖采用和排除两侧，分别统计错归属与漏检；不得靠全部丢弃获得低误判。解释评价区分范围、依据、反例响应与有用性，不使用单一人格准确率。
先交付数据/候选可审阅，再验证推理价值。留出事件组尚未核查、本人未评价真实洞察时，状态必须是待内测，不得声称效果通过。
线上发布、正式 Core 入库和全量回填不由本契约自动执行；staging 导出必须保持血缘和纠正状态，后续通过 Core 接入边界发布。
