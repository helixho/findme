# 个人理解 Agent 工作计划

> 本文维护实施任务、依赖和完成条件，不保存执行日志、部署提交或测试数字。产品范围沿用 [P1-AC-01–09](phase-1-personal-understanding.md)，详细设计见[个人理解 Agent](../implementation/personal-understanding-agent.md)。文档确认不授权启动服务、执行付费试验或发布；按实际任务范围执行。

## 1. 实施顺序

分两条线推进。产品闭环在现有对话链路上先让一件事能持续谈下去、纠正被可靠接收、各处读同一份当前认识，不等待 Agent；Agent 先把方法写成可执行 skill、通过真实工具完成取证与回复，质量成立后才增加认识写入，并替换现有链路的处理引擎。应用直接运行，不以 Docker 镜像构建或分发工程作为前置；已有运行实例不随文档变更切换。

```text
产品闭环（现有链路）
AG-07a 纠正先保存、续聊与同一份当前认识 ───────────────────────────┐
                                                                      ├─→ AG-08 本人功能验收
Agent 质量                                                            │
AG-01 方法与上下文 ──┬─→ AG-03 pi 承载 ─→ AG-04 只读对照 ─→ AG-05 修订与恢复 ─→ AG-07b 引擎切换
AG-02a 原文与关键词工具 ┘

按需启动：AG-02b 语义检索（出现召回缺口时）、AG-02c 导入重导（材料需要修正版时）
```

AG-07a、AG-01 与 AG-02a 可以立即开始。AG-02b 不是 AG-04 的前置：先用关键词与层级浏览，AG-04 或实际使用中出现关键词召回不到的具体缺口时再启动，与 [TA §2.1](../ta.md#21-正式存储与多端运行分工) 一致。AG-02c 在新案例或历史材料需要修正版导入时执行。AG-04 判定 Agent 暂无增益时，AG-07b 不执行，产品继续使用 AG-07a 的链路。AG-08 在 AG-07a 完成后即开始实际使用和记录，AG-07b 完成后在新引擎上复核。所有任务在现有容器部署上完成；原 AG-06（改为直接运行）已取消，见 ADR D29。这里说明依赖，不预先创建并行 Agent 或要求全部任务同时开工。

### 本轮切片顺序

1. 复用已有数据与方法，先保存实际请求/可见输出及工具往返；普通新信息不再自动综合，明确纠正、停用和按需综合保留。
2. 接入 pi 完整 AgentSession SDK，持续多会话、来源归档和恢复遵循[会话契约](../implementation/personal-understanding-agent.md#会话切分与记忆召回)。不另建相互竞争的个人认识真源，也不禁止 pi 会话作为来源持久化。
3. 接入原文与方法工具，补原生会话读取、邻近问答展开与长会话压缩；完成零模型验证后，按 AG-04 做真实效果对照。
4. Letta 暂不接入；只有适配暴露出大量通用运行能力必须自建、且 Letta 可实际替代时复评。记忆组件按上述召回缺口进入，不预装多个候选。

## 2. 工作任务

| 任务 | 范围与交付 | 完成条件 | 依赖 |
| --- | --- | --- | --- |
| AG-01 方法 Skills 与上下文 | 对照 BA、DA、Insight Analysis 和参考方法，形成十项方法 skill 的正文/参考/合成反例；固定系统指令与任务上下文装配；完整框架只保留接入契约 | 每项有触发、步骤、停止条件、产物、来源、边界和失败例；用户样例结论不被写进通用指令；确定性规则有对应工具或测试归属 | 无 |
| AG-02a 只读领域工具 | 层级浏览、关键词检索、原文片段、原生 App 与导入会话、邻近问答/后续纠正、认识/修订、对话摘要、覆盖和方法读取；复用来源/证据/候选和现有作用域；按[会话切分与记忆召回](../implementation/personal-understanding-agent.md#会话切分与记忆召回)装配每次任务的上下文，交互偏好只取当前适用范围的版本 | 能查到相关材料并展开准确上下文，明确作者/时间/状态；同源不重复计证；导入候选与 current 可区分，撤回内容不作为当前前提；每条认识逐项检查依据资格，部分失效时只返回其余依据并标明（不是只在全部排除时才过滤）；返回分页和遗漏 | 无 |
| AG-02b 召回缺口与语义检索 | 先定位同义表达、跨事件或纠正漏召回的具体案例；比较 MemPalace 原文检索组件与 PostgreSQL 内语义索引的适配、成本和维护负担，再选择实现。来源 ID/版本映射、邻近问答展开和失效检查复用 AG-02a；不以自建完整向量流水线为前置 | 同一失败案例能召回完整原文及其后续纠正；排除/删除内容不再使用；索引可重建；嵌入费用经过闸门；新增依赖、部署或实例变更按具体方案确认 | AG-02a 的检索接口；出现具体召回缺口时启动 |
| AG-02c 导入契约补齐与重导 | 导入格式增加两类信息：选择题回答绑定问题原文片段、全部选项与所选项，可读概括标为派生表达；证据按独立经历分组，不再整批共用一个独立组：分组依据是实际经历而不是话题或消息，同一经历的购买、使用、闲置等多次描述属于同一组，尚未发生的设想（如考虑购买）标为设想而非经历；一条消息可含多个经历，分组落在证据片段上；没有明确归属的证据保持保守的整批共用组，不自动拆成多份独立证据。用现有整理包中的问答上下文与事件分组生成修正版，以新批次导入；“很像”这类对某句描述的认同改为指向该命题的反馈。旧批次来源用可逆的排除处理，不硬删除 | 单独检索任一选择题认识时能看懂问的是什么、选了什么；同一经历的多次讨论只算一个独立组，不同经历分开；修正版导入后逐字段读回（含 details、问答映射、事件分组、反馈目标与旧批次排除状态）；排除后实际验证旧批次的来源和候选不会被检索、引用或经摘要带回，不能只看排除标记；不调用模型 | 无；修正版与本地校验结果就绪后，再确认恢复在用实例与写库；仅在材料需要修正版时执行 |
| AG-03 pi 运行适配 | 锁定 SDK 版本，自定义资源加载器、产品指令、工具、会话与事件；以自定义 provider 接通 OpenRouter 并实现[费用安全闸](../implementation/personal-understanding-agent.md#6-执行恢复与结果)（发送前预留、结束后结算）；接通持续会话恢复及受预算约束的压缩；嵌入调用复用同一闸门 | 不加载开发 AGENTS/skills/记忆/默认编码指令；可完成多轮工具调用；用合成网关验证每操作上限及 Profile 每日操作闸；重试同样经过闸门，结果不明的请求保守计费；持续会话恢复、失败重建与归档同步有数据库往返依据，自动压缩仍需另行接通和验证；不依赖私人 key | AG-01、AG-02a 的契约 |
| AG-04 只读功能与方法对照 | 固定模型和历史截止点，先比较当前 session、session 加历史原文、session 加已有认识，再比较一次检索与 Agent 自主取证；核验实际输入、引用、范围、纠正响应及方法增益；所有对照在同一材料快照上重跑（旧的 19 条材料单次试验只作参考，不作基线） | 合成行为通过且真实样例没有未解决的引用错位、旧判断复活和过度修订；能展示原始回复与不足；同源/新案例分开，成本和延迟可核对；分别回答个人理解是否带来增益、Agent 编排是否带来增益，不要求 Agent 必胜 | AG-01、AG-02a、AG-03 |
| AG-05 候选修订、失效与恢复 | 接现有候选/认识/反馈服务，补通确切版本、相关依赖、会话上下文失效与任务检查点 | 新信息真实影响有关认识；重试不重复创建；纠正/排除/删除发生在生成期间时旧结果不能发布；重启可恢复且不扩大费用；未受影响判断保持 | AG-04、现有领域规则 |
| AG-07a 持续对话与统一理解（现有链路） | 纠正与其他本人输入一样先保存来源再处理，模型不可用或失败时保留原文并可重新处理；明确要求停用某条认识时直接执行，不等待模型；探索停止追问后仍可就同一件事继续交流并得到直接回应，讨论内容由完整对话记录承载，一件事可标为暂缓或结束，恢复入口不只取最近一条；首页整体认识、专题与回答使用同一份当前认识，被纠正或撤回的判断在历史报告中标为失效，不再作为当前内容展示 | 模型不可用时提交纠正，刷新后原文仍在且可重新处理；停用的认识不再进入后续回答和可读视图；停止追问后补充“那件事有进展了”，能接回原话题和已讨论的选择；对话中纠正一条判断后，首页、专题和下一次相关回答一致体现；零历史仍可开始 | 无；沿用现有处理链路与费用上限 |
| AG-07b Agent 接入 App | 将通过 AG-04/05 的 Agent 作为 AG-07a 链路的处理引擎；展示依据、处理状态、候选/有效认识和修订结果 | AG-07a 的完成条件在新引擎下仍成立；失败保留输入可续做；不要求用户执行脚本或选择内部 skill；AG-04 的引用、范围与修订要求不降低 | AG-05；AG-04 判定暂无增益时不执行 |
| AG-08 本人功能验收 | 在正式入口完成连续使用，按 P1 记录实际帮助与无用处，以及为此额外付出的补充背景、纠正和整理；回归具体失败路径 | 工程、真实语义质量、本人效用分别有依据；P1-AC-09 只由本人反馈确认；维护理解的付出超过直接把问题说清楚时，按无效用记录；未通过项回到相关任务，不以部署成功或回答流畅代替 | AG-07a 完成后开始；AG-07b 完成后复核 |

### AG-04 评测标准（试用）

固定模型、材料快照、历史截止点与输出要求。先比较 A（当前 session）、B（当前 session + 历史原文）、C（当前 session + 已有提炼认识）；再比较 B 的一次检索与 D（pi 自主检索、展开上下文及查找纠正）。不为 C 重新生产一批认识。出现具体召回缺口后才增加 MemPalace 对照。不得将关键词未命中解释为原文记忆路线无效。

场景覆盖长会话早期纠正、恢复旧 session、跨会话同义表达、支持与反例并存、短选项绑定、转述归属。原文读取同时验原生 App 与导入来源。验证在 Instabox 隔离测试资料执行；真实模型调用前给出题目、处理/请求上限与费用上限并取得确认。

**题目来源。** 真实题约 12 道，分两组单独判定：
- **同源组（约 6 道）**：来自已用于提炼方法的完整会话（148 条），覆盖项目复盘、方向与状态、获取与使用、委托与信任、反驳与纠正等话题。它只说明方法在原材料上是否成立，不能证明能泛化。
- **新案例组（约 6 道）**：来自未参与方法提炼和 skill 调整的其他本人材料，先经现有导入通道入库；具体选哪段材料，在 AG-04 开始时由本人确认。是否继续以新案例组为准。

合成陷阱题约 20 道，覆盖 [Agent 设计 §7](../implementation/personal-understanding-agent.md#7-验收场景) 的场景。

**连续情境按时间切片。** “先吐槽再追问依据”“你把它心理化了”这类多轮情境，每一轮只开放截至该轮已发生的消息和当时有效的认识版本，之后的撤回、纠正和结论不进入上下文。

| 类别 | 测法 | 门槛 |
| --- | --- | --- |
| 硬错误 | 逐条核对：引用不支持说法、撤回或被替代的判断当作现状、助手推断当作本人陈述、历史说成当前、声称了解未读资料、读到截止时点之后的材料 | 新案例组 0 个；两组都不多于对应材料的单次生成 |
| 纠正与异议处理 | 先判断类别：明确的事实错误必须修改；解释异议须核对依据后给出修订、保留（说明理由）或标为争议之一；无关判断保持 | 处理方式与类别相符且有依据；不以“改口”作为通过条件 |
| 本人效用 | 两份回答随机标为 X/Y，本人不知来源，选更有帮助者或“差不多”，并各打 1–5 分；分别比较“A vs B/C”和“B vs D”，相同题目成对盲评 | 新案例组去掉“差不多”后 D 至少胜 B 2/3，平均分高 0.5 以上；B/C 不胜 A 时，视为本批跨会话材料暂无增益 |
| 速度与费用 | 程序记录 | 中位延迟 60 秒以内；单题不超过费用安全闸 |

硬错误不过，先修 skill 或工具；硬错误通过但新案例组效用不胜，视为 Agent 暂无增益，先简化执行再比较，仍无增益则不执行 AG-07b；都通过才进入 AG-05。个人理解暂无增益时，先查选取与方法，不以扩大语料制造进展。题量只能给出方向性判断，门槛是试用标准，按实际结果由本人调整。

任务按结果交付，不为每个任务额外建立过程报告、交接笔记或新的阶段门。完成状态与证据进入实际执行记录，通用知识和最终设计进入职责所属正文。

## 3. 首轮切片与边界

首轮实施两条线：AG-07a 在现有链路上贯通持续使用；AG-01、AG-02a、AG-03、AG-04 只读数据库材料，运行一个 Agent，按问题检索取证并给出可复核回复。AG-01 先覆盖已有方法，不以下载更多理论或运行完整 HUMAN 3.0 为前置。AG-04 没有真实质量依据前，不因工具链已通就批量产生新的个人认识。

Agent 后续按 AG-05 → AG-07b 接入，AG-08 自 AG-07a 完成起持续记录；AG-02b 依召回缺口选组件，不预先部署向量服务。保留 AG-04 的质量标准，连接 UI 不能降低引用、范围或修订要求。

不包含：恢复 OpenViking、部署 Hindsight、扩大私人语料（为 AG-04 新案例组导入少量既有本人材料除外）、模型训练/人格蒸馏、多 Agent 团队、独立向量服务或图数据库、应用镜像分发和额外客户端。未来具体需求成立后再评估，不由本计划自动取消既有长期目标。

## 4. 验证与执行边界

- 文档与 skill 初稿先做内容、来源、链接及公开边界检查；可确定行为用合成测试。方法的真实效果需要有界模型任务，不能以文件齐全宣称有效。
- 数据库行为使用独立合成库。应用不打 Docker 镜像，不等于要求停用数据库容器；测试在 Instabox 上运行，本机不跑测试。
- 真实模型试验先固定任务、资料范围、provider/model、实际请求上限和总费用；授权仅覆盖对应试验，不作为无限后续调用许可。密钥由运行配置读取，不提交公开仓库。
- 应用运行切换先核对目标实例、原数据、启动配置与回退步骤，具体候选准备好后再执行。文档阶段不修改现用服务。
- 所有公开方法和案例采用通用内容或合成反例。私人会话、原始回复和导入包留在仓库外，不因拆工作计划迁入公开目录。

## 5. 与既有计划的关系

本计划是[原交付计划](../implementation/diagnostic-product-plan.md)中工作包 4–6 的当前实施拆分，并承接运行方式调整；取代其中把固定两段模型生成或旧部署组合视为后续前置的安排。旧 R/C/U 切片继续作为已有资产查阅入口，不重启历史阶段门。

第一阶段 P1 义务继续保留；既有完整 AV 交付与完整框架的未完范围按 [ADR D31](../adr.md#d31-外围交付改为按具体用途启动) 改为有具体用途时再启动。本轮先做有界个人理解 Agent，不宣称全量语料、全部框架或完整赛博分身已完成。
