# 个人理解 Agent 工作计划

> 本文维护实施任务、依赖和完成条件，不保存执行日志、部署提交或测试数字。产品范围沿用 [P1-AC-01–09](phase-1-personal-understanding.md)，详细设计见[个人理解 Agent](../implementation/personal-understanding-agent.md)。文档确认不授权启动服务、执行付费试验或发布；按实际任务范围执行。

## 1. 实施顺序

先把方法写成可执行 skill，再让 Agent 通过真实工具完成取证与回复；质量成立后才增加认识写入并接入 App。应用直接运行，不以 Docker 镜像构建或分发工程作为前置；已有运行实例不随文档变更切换。

```text
AG-01 方法与上下文 ──┬─→ AG-03 pi 承载 ─┐
AG-02a 原文与关键词工具 ┘                  ├─→ AG-04 只读功能对照
AG-02b 语义检索（pgvector）───────────────┤
AG-02c 导入契约补齐与重导 ────────────────┘           ↓
                                            AG-05 修订与恢复
                                                ↓
                                            AG-07 App 连续对话
                                                ↓
                                            AG-08 本人功能验收

AG-06 应用直接运行（独立推进，不阻塞上面的主线）
```

AG-01 与 AG-02a 可以立即开始；AG-02b 需要数据库扩展与嵌入模型，AG-02c 需要改导入代码并重导材料，两者单独推进，完成后才进入 AG-04 的真实题运行。AG-06 只改变应用的启动和打包方式，AG-07/08 可以在现有容器部署上完成；AG-06 的实际切换在其自身验证通过后执行。这里说明依赖，不预先创建并行 Agent 或要求全部任务同时开工。

## 2. 工作任务

| 任务 | 范围与交付 | 完成条件 | 依赖 |
| --- | --- | --- | --- |
| AG-01 方法 Skills 与上下文 | 对照 BA、DA、Insight Analysis 和参考方法，形成十项方法 skill 的正文/参考/合成反例；固定系统指令与任务上下文装配；完整框架只保留接入契约 | 每项有触发、步骤、停止条件、产物、来源、边界和失败例；用户样例结论不被写进通用指令；确定性规则有对应工具或测试归属 | 无 |
| AG-02a 只读领域工具 | 层级浏览、关键词检索、原文片段、认识/修订、对话摘要、覆盖和方法读取；复用来源/证据/候选和现有作用域；按[会话切分与记忆召回](../implementation/personal-understanding-agent.md#会话切分与记忆召回)装配每次任务的上下文，交互偏好只取当前适用范围的版本 | 能查到相关材料并展开准确上下文，明确作者/时间/状态；同源不重复计证；导入候选与 current 可区分，撤回内容不作为当前前提；每条认识逐项检查依据资格，部分失效时只返回其余依据并标明（不是只在全部排除时才过滤）；返回分页和遗漏 | 无 |
| AG-02b 语义检索 | 数据库换为带 pgvector 的同主版本 PostgreSQL 镜像并启用扩展（现用 `postgres:18-bookworm` 不含，数据目录须兼容）；向量表结构（片段/认识、来源版本、嵌入模型与维度、生成时间）；选定支持中文的嵌入模型并经费用闸调用；确定分块（以消息/证据片段为单位）；为已入库材料生成索引；新来源增量生成；排除、纠正、删除、换版本或换嵌入模型时失效与重建 | 合成同义改写用例能被召回而关键词召回不到；被排除或删除的内容不再命中；换模型可整体重建；嵌入费用计入预算且有上限；在用实例的镜像切换按部署变更另行确认，原数据完整 | AG-02a 的检索接口 |
| AG-02c 导入契约补齐与重导 | 导入格式增加两类信息：选择题回答绑定问题原文片段、全部选项与所选项，可读概括标为派生表达；证据按独立经历分组，不再整批共用一个独立组。用现有整理包中的问答上下文与事件分组生成修正版，以新批次导入；“很像”这类对某句描述的认同改为指向该命题的反馈。旧批次来源用可逆的排除处理，不硬删除 | 单独检索任一选择题认识时能看懂问的是什么、选了什么；同一经历的多次讨论只算一个独立组，不同经历分开；修正版导入后逐字段读回（含 details、问答映射、事件分组、反馈目标与旧批次排除状态）；不调用模型 | 无；恢复在用实例与写库在执行时确认 |
| AG-03 pi 运行适配 | 锁定 SDK 版本，自定义资源加载器、产品指令、工具、会话与事件；以自定义 provider 接通 OpenRouter 并实现[费用安全闸](../implementation/personal-understanding-agent.md#6-执行恢复与结果)（发送前预留、结束后结算）；关闭自动压缩；嵌入调用复用同一闸门 | 不加载开发 AGENTS/skills/记忆/默认编码指令；可完成多轮工具调用；用合成网关验证超过任一默认上限的请求不会发出，并发的两个任务合计不超过日上限，重试同样经过闸门，结果不明的请求按预留计费；不依赖私人 key | AG-01、AG-02a 的契约 |
| AG-04 只读功能与方法对照 | 用固定问题及新案例比较直接分析、单次生成和 Agent 自主取证；核验实际输入、引用、范围、纠正响应及方法增益；所有对照在同一材料快照上重跑（旧的 19 条材料单次试验只作参考，不作基线） | 合成行为通过且真实样例没有未解决的引用错位、旧判断复活和过度修订；能展示原始回复与不足；同源/新案例分开，成本和延迟可核对，不要求 Agent 必胜 | AG-01、AG-02a/b/c、AG-03 |
| AG-05 候选修订、失效与恢复 | 接现有候选/认识/反馈服务，补通确切版本、相关依赖、会话上下文失效与任务检查点 | 新信息真实影响有关认识；重试不重复创建；纠正/排除/删除发生在生成期间时旧结果不能发布；重启可恢复且不扩大费用；未受影响判断保持 | AG-04、现有领域规则 |
| AG-06 应用直接运行 | 在现有单节点上设计 Node 构建产物/源码运行、前端产物服务、进程管理与启动/停止/就绪检查；数据库容器独立保留；实现对应脚本/说明 | 不构建应用镜像也可部署、登录和运行任务；退出/重启/实例恢复行为验证；保留原账号、数据库和原档；应用版本回退不破坏数据；已有 Docker 路径在切换前仍可用 | TA 的运行决定；实际切换需候选就绪 |
| AG-07 App 持续对话与统一理解 | 将新 Agent 接入现有账号对话；展示依据、处理状态、候选/有效认识和修订结果；总览与相关回答使用同一数据 | 经 App 输入、补充、纠正后，刷新及后续相关问答使用新版本；失败保留输入可续做；零历史仍可开始，不要求用户执行脚本或选择内部 skill | AG-05 |
| AG-08 本人功能验收 | 在正式入口完成连续使用，按 P1 记录实际帮助与无用处；回归具体失败路径 | 工程、真实语义质量、本人效用分别有依据；P1-AC-09 只由本人反馈确认；未通过项回到相关任务，不以部署成功或回答流畅代替 | AG-07 |

### AG-04 评测标准（试用）

同一材料快照、同一问题分别运行单次生成和 Agent，单次生成与 Agent 都只能看到同样截止时点的材料。

**题目来源。** 真实题约 12 道，分两组单独判定：
- **同源组（约 6 道）**：来自已用于提炼方法的完整会话（148 条），覆盖项目复盘、方向与状态、获取与使用、委托与信任、反驳与纠正等话题。它只说明方法在原材料上是否成立，不能证明能泛化。
- **新案例组（约 6 道）**：来自未参与方法提炼和 skill 调整的其他本人材料，先经现有导入通道入库；具体选哪段材料，在 AG-04 开始时由本人确认。是否继续以新案例组为准。

合成陷阱题约 20 道，覆盖 [Agent 设计 §7](../implementation/personal-understanding-agent.md#7-验收场景) 的场景。

**连续情境按时间切片。** “先吐槽再追问依据”“你把它心理化了”这类多轮情境，每一轮只开放截至该轮已发生的消息和当时有效的认识版本，之后的撤回、纠正和结论不进入上下文。

| 类别 | 测法 | 门槛 |
| --- | --- | --- |
| 硬错误 | 逐条核对：引用不支持说法、撤回或被替代的判断当作现状、助手推断当作本人陈述、历史说成当前、声称了解未读资料、读到截止时点之后的材料 | 新案例组 0 个；两组都不多于单次生成 |
| 纠正与异议处理 | 先判断类别：明确的事实错误必须修改；解释异议须核对依据后给出修订、保留（说明理由）或标为争议之一；无关判断保持 | 处理方式与类别相符且有依据；不以“改口”作为通过条件 |
| 本人效用 | 两份回答随机标为 X/Y，本人不知来源，选更有帮助者或“差不多”，并各打 1–5 分 | 新案例组去掉“差不多”后 Agent 至少胜 2/3，平均分高 0.5 以上 |
| 速度与费用 | 程序记录 | 中位延迟 60 秒以内；单题不超过费用安全闸 |

硬错误不过，先修 skill 或工具；硬错误通过但新案例组效用不胜，视为 Agent 暂无增益，先简化执行再比较；都通过才进入 AG-05。题量只能给出方向性判断，门槛是试用标准，按实际结果由本人调整。

任务按结果交付，不为每个任务额外建立过程报告、交接笔记或新的阶段门。完成状态与证据进入实际执行记录，通用知识和最终设计进入职责所属正文。

## 3. 首轮切片与边界

首轮实施为 AG-01–04：只读数据库材料，运行一个 Agent，按问题检索取证并给出可复核回复。AG-01 先覆盖已有方法，不以下载更多理论或运行完整 HUMAN 3.0 为前置。AG-04 没有真实质量依据前，不因工具链已通就批量产生新的个人认识。

后续按 AG-05 → AG-07 → AG-08 形成闭环；AG-06 处理运行方式，不借机换数据库、清理已有数据或安装新平台；AG-02b 的 pgvector 扩展是同一数据库的扩展，不属于换库。保留 AG-04 的质量标准，连接 UI 不能降低引用、范围或修订要求。

不包含：恢复 OpenViking、部署 Hindsight、扩大私人语料（为 AG-04 新案例组导入少量既有本人材料除外）、模型训练/人格蒸馏、多 Agent 团队、独立向量服务或图数据库、应用镜像分发和额外客户端。未来具体需求成立后再评估，不由本计划自动取消既有长期目标。

## 4. 验证与执行边界

- 文档与 skill 初稿先做内容、来源、链接及公开边界检查；可确定行为用合成测试。方法的真实效果需要有界模型任务，不能以文件齐全宣称有效。
- 数据库行为使用独立合成库；CI 可继续用 PostgreSQL 容器。应用不打 Docker 镜像，不等于要求停用数据库容器；不自动启动本机 Docker。
- 真实模型试验先固定任务、资料范围、provider/model、实际请求上限和总费用；授权仅覆盖对应试验，不作为无限后续调用许可。密钥由运行配置读取，不提交公开仓库。
- 应用运行切换先核对目标实例、原数据、启动配置与回退步骤，具体候选准备好后再执行。文档阶段不修改现用服务。
- 所有公开方法和案例采用通用内容或合成反例。私人会话、原始回复和导入包留在仓库外，不因拆工作计划迁入公开目录。

## 5. 与既有计划的关系

本计划是[原交付计划](../implementation/diagnostic-product-plan.md)中工作包 4–6 的当前实施拆分，并承接运行方式调整；取代其中把固定两段模型生成或旧部署组合视为后续前置的安排。旧 R/C/U 切片继续作为已有资产查阅入口，不重启历史阶段门。

第一阶段 P1 义务、既有完整 AV 交付及完整框架的未完范围继续保留。本轮先做有界个人理解 Agent，不宣称全量语料、全部框架或完整赛博分身已完成。
