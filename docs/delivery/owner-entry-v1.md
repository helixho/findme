## 1. 本轮结果与支持组合（ART-SCOPE）

本轮只交付一个本人可用的账号模式 Web 入口：在生产库启用账号模式，把已独立审核通过的 U2 专题一次性导入同一本人 Profile，部署 `findme-app`，由本人在该入口完成一次“阅读依据 → 纠正 → 看到相关认识修订”的真实闭环。导入核对一致且账号入口可读后，退役过渡用的快照只读接口；冻结路径的代码和数据保留。系统义务和判定方式在本文 §3 定义，实际执行仍按阶段门及具体操作授权进行。

| 维度 | 本轮支持的组合 |
| --- | --- |
| 使用者与身份 | 产品所有者本人；不依赖邮件的本人账号开通，登录后选择本人 Profile；账号/Profile 作用域是唯一运行读写范围 |
| 客户端与环境 | 同一 `findme-app` Web 入口供本人手机和电脑使用；生产云端主库承载权威状态，不依赖本人电脑常开 |
| 导入集合 | 冻结归档中已独立审核通过的 U2 专题版本；目前状态为 3 个。执行前按归档版本、原审核记录及来源指纹固定清单，不按运行时新候选自动扩展 |
| 可阅读和可修改的对象 | 上述合格专题的报告版本、精确依据、审核来源与纠正后的相关认识；未成稿内容明确显示缺口，不拼出假总览 |
| 处理与费用 | 阅读、保存和导入不触发模型；需要付费推理的修订步骤只在另行确认用途、provider 与最大次数后执行 |

本轮不生成 U2 剩余专题或 overall，不运行 U4 本人访谈，不开放第二位用户，不编写自部署指南或开源发布材料，不给本机 U3 私有宿主、dogfood/U2 流水线或 Legacy V1 增加功能。未通过审核的候选、未成稿专题和旧认识处置候选不因导入获得通过或本人认可资格。快照只读接口退役不等于删除其表、归档、冻结代码或数据；实际删除须另行决定。

生产 Neon 恢复、迁移、真实导入、部署、付费调用及新资源创建均需各自的具体授权。本轮 G1 只决定需求基线；迁移设计、测试环境、部署与恢复规程在后续门完成，见 [交付矩阵](../delivery-tailoring.md)。

## 3. 系统需求与验收条件（ART-SYSREQ）

下表的 ID 在本轮内保持稳定；修改承诺时保留旧 ID 的变更记录，不把实现任务当作验收条件。每条以明确的候选、输入版本和环境判断；正式用例及证据映射在 G2–G3 制定，隔离验证与生产观察分别记录。业务判定来源为 [BA §4.8–4.10、§7](../ba.md)，过渡语义来源为 [ADR D23](../adr.md#d23-账号模式云端数据库为唯一运行真源其余运行路径冻结或退役)。

| 需求 | 义务与优先级 | 验收条件：前置、操作、可观察结果 |
| --- | --- | --- |
| OE1-REQ-01 | 本人通过生产账号模式访问唯一运行真源；必需 | **OE1-AC-01**：生产迁移与访问策略完成后，本人用不依赖邮件的方式开通并登录，选择本人 Profile；报告读取和纠正写入均落在该 Profile 的账号模式主库中，刷新后仍可读取。 |
| OE1-REQ-01 | 同上 | **OE1-AC-02**：对未登录、会话失效或不属于该 Profile 的请求，报告、精确依据和纠正接口不返回或修改私人内容；以合成账号及实际运行角色验证，不能仅凭页面隐藏断言通过。 |
| OE1-REQ-02 | 仅一次性导入合格专题，保留资格与证据；必需 | **OE1-AC-03**：导入前冻结并核对源版本、通过审核的专题集合与来源指纹；导入后目标集合与该清单一致，原审核记录、报告版本、精确证据位置和来源指纹可逐项追溯；未通过候选、未成稿专题及 overall 均未被提升为当前通过报告。 |
| OE1-REQ-02 | 同上 | **OE1-AC-04**：对同一冻结输入重复提交或在部分失败后恢复，目标库不出现重复专题、证据或当前版本；失败项保留可核对状态，不能把部分导入标为完成。 |
| OE1-REQ-03 | 在统一 App 阅读同一份权威报告；必需 | **OE1-AC-05**：本人登录 `findme-app` 后可阅读已导入专题、其审核与版本状态，并从判断展开到精确依据和必要上下文；依据与原文、作者、有效状态核对一致，缺失的 overall/专题明确标为未完成。 |
| OE1-REQ-03 | 同上 | **OE1-AC-06**：`app.findme.example.com` 的本人入口在手机和电脑可访问；两端登录同一 Profile 后读取相同的当前专题版本，刷新或关闭本人电脑再打开仍可读取，不要求本机私有宿主在线。 |
| OE1-REQ-04 | 完成一次真实阅读与纠正闭环；必需 | **OE1-AC-07**：本人针对已读判断提交一项事实或解释纠正；系统先可靠保存反馈，刷新后可见原反馈和处理状态，待处理/候选不显示为已通过认识。 |
| OE1-REQ-04 | 同上 | **OE1-AC-08**：按实际获准的处理链复核并发布后，受影响判断的当前版本、适用范围或状态反映纠正；对解释异议可以保留争议并影响后续使用，不强迫翻转判断。修订理由和前后版本可回看；刷新及另一端读取不把已被纠正的旧误读继续显示为当前结论，也不无依据改写无关专题。仅保存反馈不算通过。 |
| OE1-REQ-04 | 同上 | **OE1-AC-09**：本人在同一入口完成阅读、提交纠正并查看修订结果后，记录本次是否带来新增理解、纠正误读或没有价值及原因；这一记录是本人体验证据，不把一次使用写成 H1–H3 对其他人的效果证明。 |
| OE1-REQ-05 | 核对后结束快照过渡；必需 | **OE1-AC-10**：导入集合、报告版本及精确证据与过渡快照逐项核对一致，且账号入口能读取对应内容后，快照只读路由不再提供运行读取；归档表、冻结代码与数据是否删除不在本条件内。 |

## 4. 验证证据与门顺序

G3 前固定可识别的候选、配置与测试输入。G4–G5 在隔离环境用合成资料验证导入、账号、权限、修订与恢复，并记录每条 AC 在该环境的 passed / failed / skipped / not_run；隔离结果不能冒充生产验证。生产账号、真实已通过专题、正式域名和本人闭环所需的结果，须在 G7 部署后另行观察。

G6A 先审阅候选的隔离证据与未覆盖项，**不能将生产条件记为 passed**。若生产专属 AC 尚为 not_run，只有本人在 G6A 对明确范围、替代证据、责任和 G7 复核条件作出 `approved_with_exception` 决定，并在 G6B 单独授权具体生产操作，才可进入 S7；没有该决定则停在 S6。G7 核对生产 AC 与本人体验；任一必需 AC failed 或仍 not_run 时，G7 不关闭，按事先约定的恢复路径处理。G6A 的例外不提前证明本轮产品价值。

G1 只接收本轮范围、支持组合、逐条 AC、排除项和上述证据顺序。**以上任何 AC 均未因 G1 通过而得到运行验证或本人业务接受。**
