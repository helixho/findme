# 第一阶段 — 可持续使用的个人理解与对话

> **当前需求与范围基线：2026-10-30。** 用户已确认以赛博分身为整体愿景，并要求先按可行目标推进第一阶段。本文件规定阶段结果、必需能力与验收；产品定位见 [Overview](../overview.md)，能力规则见 [BA](../ba.md)，设计见 [AA](../aa.md)、[DA](../da.md)、[TA](../ta.md)，安排见 [Roadmap](../roadmap.md)，完成情况只见 Current Status。本文建立目标，不声称实现、真实模型效果或本人使用已经通过。

## 1. 第一阶段要交付什么

在同一个本人可用的入口中，形成一份有依据、能阅读和对话、能纠正、能随新经历与反馈更新的个人理解。用户可以直接获得与自己有关的解释、开导、建议或有依据的质疑；新的交流又能增进后续理解。

这一阶段交付赛博分身的可用基础，并在使用中检验价值。对话、引导、学习、导入和回顾共同服务持续理解；单纯新增资料、增加聊天轮数、生成更长报告都不算阶段完成。阶段完成不表示已经形成完整人格复制、在未知情境中可靠模拟本人或具备外部代理能力。

这里的“个人理解”包含经历与处境、认可与向往、实际选择、条件化模式、当前解释及未知。报告、专题、总览和个人使用说明是它的可读呈现；普通交流也应使用同一份当前理解。用户可以只获得认识，不要求每次接受建议或采取行动。

## 2. 范围与既有交付的关系

| 范围 | 第一阶段采用方式 |
| --- | --- |
| 使用者与入口 | 先服务本人；沿用统一 App 与账号模式的单一权威状态。手机和电脑可持续访问、保存和恢复，不要求本人的电脑常开。 |
| 已有个人材料 | 优先复用已审核通过的来源与专题，并在开始使用时显示覆盖范围、待处理和未知。先固定可核验输入集合，避免重复全量加工。 |
| 零历史与新输入 | 无导入也能从具体经历或中性引导开始；新对话、补充和学习反馈进入同一来源与认识过程。 |
| 学习与方法知识 | 先使用足以支撑本阶段具体问题的有限、来源明确的材料。理论帮助提出解释、问题和可选做法；本人回应另按个人来源处理。 |
| 可读交付 | 用户能先看当前综合理解，再按需进入专题、依据、对话和修订；覆盖不足时给出有界总览，未完成部分明确显示。 |
| 当前设计基础 | 复用来源、证据、认识、反馈、版本及既有 App 资产。未来分身的具体技术形式留待相关阶段评估。 |

原 `owner-entry-v1` 聚焦已通过专题的导入、阅读和一次纠正，其 G1 记录 保留为历史证据。本阶段吸收其有效结果要求，增加持续对话、新来源到认识、知识辅助与后续使用，不以旧范围通过代替新范围验收。

[既有 AV 整体理解交付](../implementation/av-understanding-app-delivery.md) 的未完专题、overall、旧认识校正和完整框架义务继续单独跟踪。第一阶段可以在明确有界覆盖上先形成可用闭环，但不能把它标作全量 AV 或 U1–U4 已交付，也不能无声取消这些需求。

## 3. 必需需求与可观察的验收条件

以下条件按同一候选版本和真实运行路径核对。工程合成案例可以验证状态、恢复与依赖传播；真实模型质量和本人使用价值需要各自的实际证据，三者分开记录。

| 需求 | 第一阶段义务 | 验收条件 |
| --- | --- | --- |
| P1-01 本人入口与持久状态 | 能连续使用同一份当前个人理解 | **P1-AC-01：** 本人经统一 App 读取当前理解、提交一条新输入；刷新、重新进入及另一端读取时，输入、处理状态与当前版本一致。处理失败可见且能续做，不能依赖模拟回应或本机私有宿主。 |
| P1-02 有界个人理解基线 | 综合判断可读，依据、范围与缺口可查 | **P1-AC-02：** 已声明输入集合中的重要内容有去向；当前总览/专题说明主要认识、支持、例外和未知，可回到准确来源。未处理不写成“已了解但无发现”，未完成专题不拼成完整人格报告。 |
| P1-03 主动引导与持续对话 | 不知道说什么也能开始；已有理解能减少重复说明 | **P1-AC-03：** 零历史场景能以具体经历或中性问题开始并获得局部价值；有历史场景中，回答、解释和必要追问使用相关当前认识。用户能补充、换题或结束，开导和建议不被强制变成连续问卷。 |
| P1-04 新信息真实进入认识 | 新对话、经历和导入来源可形成或修订认识 | **P1-AC-04：** 一条有意义的新输入保存后，经归属、情境及支持关系处理，能够补充、收窄、挑战或修订相关认识，并反映到下一次相关回答与可读视图。也允许结论不变或保留未知，但必须说明处理结果；只存文字或引用既有 Claim 不算贯通。 |
| P1-05 纠正能影响后续使用 | 事实错误、适用范围、解释争议及时间变化能被不同处理 | **P1-AC-05：** 对一个当前判断提交纠正，检查依据、判断和相关建议的处理结果，再提出相关问题；已确认错误不再次作为当前前提，未决争议保持可见，无关判断不被重写。旧任务回包不能覆盖新的有效状态，版本变化可回看。 |
| P1-06 支持与诚实挑战 | 结合个人处境给予帮助，并能有依据地质疑 | **P1-AC-06：** 用明确情境分别检查开导/建议、可能自我美化、过度自责和模型误读。回应指出具体依据及必要的其他解释；对用户和模型判断采用一致标准。用户反驳能触发核对，不能被循环解释成“防御”；说得刺耳、用户赞同或模型自评分高均不独立计作通过。 |
| P1-07 来源化知识辅助 | 学术/方法知识帮助探索，反馈回到个人理解 | **P1-AC-07：** 对具体问题使用相关来源明确的知识，说明它提供的解释、提问或做法及适用范围；理论原文不计作用户特征证据。用户的实际回应、经历或尝试反馈可成为个人来源，并按 P1-AC-04/05 影响后续理解；认同一段理论不自动证明本人一直如此。 |
| P1-08 导入与持续积累 | 导入增强理解，同时保持原生使用完整 | **P1-AC-08：** 对明确支持的来源格式完成预览、选择、导入和重复提交核对；作者、谈论对象、时间、立场、来源版本及上下文的已知信息保留，未知或冲突显式标识，AI 转述不变成本人原话。超出处理容量时显式分批/选择并记录遗漏，不静默截断或声称完整；无导入仍通过 P1-AC-03。 |
| P1-09 本人实际价值 | 能说明本阶段解决了什么、哪里仍无用 | **P1-AC-09：** 本人在实际入口完成“阅读或开始对话 → 新输入/纠正 → 查看更新 → 再次相关交流”，记录是否得到新的认识、支持、有用质疑或建议，以及无用之处。系统保存相关版本与处理证据；本人体验不由 Agent 代写，不据一次使用推定长期收益或其他用户效果。 |

这些 ID 是本阶段需求的引用位置，不新增一套平行技术接口或工程门。具体执行用例与数据在对应工作包中确定；通过与未通过均写入执行记录。

## 4. 第一阶段的完成判断

阶段完成须同时具备三类结果：

1. **能力连通：** P1-AC-01–08 对应的正式路径实际贯通，依赖、保存、更新和恢复有可核对证据；旧合成回归只在相同范围与有效版本下复用。
2. **回答质量：** 实际处理能使用当前个人理解、忠实于来源、接纳反例与纠正，并用相关知识改善解释或建议。通用长回复、口吻相似或堆叠理论不能代替这一判断。
3. **本人效用：** P1-AC-09 有本人真实反馈，并有本人认可的具体帮助；新增认识、消除误读、获得支持或澄清取舍均可构成帮助，不要求行为改变。无价值反馈也是有效试用证据，但表示本阶段效用尚未通过；应先改相应能力或收窄承诺，不扩大语料量来制造进展。

未全部满足时，分别报告已具备的代码、已验证的行为和仍待验证的价值，不把“文档完成”“本地测试通过”“有可点击页面”写成第一阶段完成。保留阶段性认识对本人的价值，也保留对它无用的判断。

## 5. 实施接续所需解决的具体缺口

依据当前源码与执行记录，详细事实由 [As-Is](../as-is.md) 和 Current Status 维护；本表定义本阶段必须处理的依赖。

| 缺口 | 对第一阶段的影响 | 处理原则 |
| --- | --- | --- |
| 本人入口、可用数据库和真实推理运行依赖尚未贯通 | 无法证明真实持续使用 | 在方案阶段核对实际可用依赖，保持统一状态；已停用且明确不恢复的生产 Neon 不作为默认恢复路径，不借新愿景重选整套架构。 |
| 普通新来源到认识、跨来源关联和整体理解尚不完整 | 对话与导入只能积累材料，无法持续增进分身理解 | 贯通来源、情境、候选认识与修订，复用已有资格与传播能力；将“保存成功”和“认识已更新”分开。 |
| 知识专题与诊断报告目前有不同语义和处理路径 | 页面上同名内容可能各自维护判断 | 在设计中明确两者如何引用同一当前个人理解，统一用户可见的关系与更新时间，不先机械合并表或接口。 |
| 云端处理的来源数量有界 | 多轮累积或历史导入可能触及容量限制 | 对已支持范围先验证；选择、分批或摘要复用须保留来源和遗漏，按实际覆盖缺口评估改动，不预设无限上下文。 |
| 学习回应、尝试回顾与认识修订尚未完整连通 | 知识或行动停留在孤立记录 | 本阶段至少将所用知识辅助路径的实际反馈作为个人来源进入同一修订链；完整专项和多框架运行按各自契约继续跟踪。 |
| 真实模型质量与本人效用尚无本阶段证据 | 合成流程可通但未必真正了解或帮助本人 | 按 P1-AC-03–09 的具体场景验证，不用大批量重算或泛化准确率替代实际案例。 |

## 6. 后续能力与方案选择

第一阶段不要求完整复现本人在未知情境下的判断和表达，也不要求外部自动执行、声音/形象克隆、全量学术内容平台或一次接入全部框架。这些能力是否进入后续范围，取决于具体需求与已观察到的价值；不据本阶段范围把长期愿景永久缩小。

Agent、人格蒸馏 Skill、模型微调、知识图谱或其他形式仅可能成为方案候选。选择时评估当时技术的实际效果、维护负担和成本，不能把当前示例写成需求、既定架构或必经路线。已有可复用工程继续服务第一阶段，技术变更由具体缺口驱动。

产品“第一阶段”是上述能力与价值范围；Delivery Kit 的 S1–S7 是每次交付的工程过程，两者不是同一个分期。旧范围的 G1 通过记录不覆盖新增 P1 需求。当前文档更新和一致性复核也不替代后续运行、发布或本人效用验收。
