# FindMe — 后续方向与进入条件

> 本文只管理未解决的问题、优先级和阶段进入条件。已有功能由 As-Is 说明，具体功能契约在对应实现文档；不保存测试结果、部署记录或会话交接。

## 1. 当前优先级

**当前产品阶段是“可持续使用的个人理解与对话”。** 整体愿景按 [ADR D24](adr.md#d24-赛博分身作为愿景先形成可持续使用的个人理解)：对话、学习、导入与回顾持续构建赛博分身，支持、自我认识、建议与诚实挑战提供当期价值。当前按[第一阶段范围与验收](delivery/phase-1-personal-understanding.md)推进，先贯通同一入口中的“已有理解 → 对话/新经历 → 有依据的更新 → 下次相关使用”；报告承载综合认识，不再作为所有互动的终点。

### 产品阶段与完成条件

| 产品阶段 | 要获得的结果 | 进入或完成依据 |
| --- | --- | --- |
| **第一阶段：可持续使用的个人理解与对话（当前）** | 有界个人理解可读、可对话、可纠正；新输入与知识辅助反馈能够影响后续理解；本人能连续使用并说明具体帮助 | 以 P1-AC-01–09 的实际证据完成；工程连通、真实回答质量和本人效用分别判断，不以文档或合成演示宣称完成 |
| 后续阶段：更完整、稳定的长期理解 | 扩展经历覆盖、跨情境理解与纵向变化，减少重复说明，提高知识辅助、支持与挑战的适切性 | 第一阶段已有实际价值，并能指出扩大覆盖或深化方法解决的具体缺口；保留无增益时简化的选择 |
| 后续阶段：在具体场景使用分身能力 | 按届时明确的需要，检验分身能否更充分体现本人的取舍与思考，并帮助理解、选择或表达 | 先定义具体场景和可观察效果，再评估当时技术；Agent、人格蒸馏 Skill 或其他形式均不预先锁定 |

这是一条产品演进方向，没有预设日期或永久技术路径。下文 T1–T4 保留为既有能力分区与引用标识；第一阶段组合 T1 及 T2/T3 的必要部分，不要求完成全部 T2/T3，也不把多用户 T4 作为前置。Delivery Kit 的 S1–S7 是交付过程，与这里的产品分期分开。

### 第一阶段的推进顺序

本轮指定代码维护及已确认过时演示清理已完成；仓库已按 [ADR D25](adr.md#d25-直接退役两个独立客户端统一使用-appsapp-浏览器入口) 退役另外两个独立客户端，唯一客户端为 `apps/app`，手机 H5 与桌面同代码；AD-11 的在线切换仍待验证。维护结果见维护记录。后续先核对运行依赖并完成差异设计，再部署验证现有能力和贯通个人理解主链，不扩展为年度治理项目。具体任务、依赖与退出检查统一在[交付计划 §3](implementation/diagnostic-product-plan.md#3-下一阶段的具体工作包与依赖)维护。

| 顺序 | 工作包 | 目的与进入条件 |
| --- | --- | --- |
| 1（本轮已完成） | 维护修复与仓库清理 | 复用已完成结果；新代码/依赖变更按影响重验，不重复拆分 |
| 2（产品侧部分完成，运行侧待做） | 运行依赖核对与产品差异设计 | 核对唯一 `apps/app` 浏览器客户端的可用运行组合及线上入口切换；不再以承接全部旧功能作为仓库删除前置。旧 Neon 不恢复；其余对话/认识差异与固定案例继续准备 |
| 3 | 修复后部署验证现有能力 | 1 的真实修复完成、2 的运行依赖明确且同一候选工程验证通过后执行；先证明账号读写、恢复与实际服务组合，并验证目标入口切换；AD-11 的仓库部分已落实，线上部分在实际退出验证前保持未完成，不把部署成功记为 P1 完成 |

| 5 | 接通有限知识反馈和历史增强 | 个人回应/尝试反馈进入同一修订链；已审核历史有界复用、导入对账、容量/分批和遗漏可查，关联 P1-AC-07/08 |
| 6 | 真实回答质量与本人接受 | 工程、部署、模型质量和本人效用分开；按 P1-AC-01–09 记录实际结果，未通过的具体行为返回相应工作包 |

工作包 4–5 的差异设计与合成用例可以提前准备；新增能力按相同工程验证要求增量发布。这里的“下一阶段”是当前第一阶段内部的实施接续，不是直接进入完整分身或外部代理能力阶段。

### 并行技术验证：TV-01 多来源个人理解引擎

与工作包 2–5 并行开展 Hindsight / OpenViking 技术验证，针对 Agent Session 与非 Session 资料使用同一组场景，比较多源接入、来源/立场保真、证据追溯、增量纠正、认识增益及资源成本。先形成可复现的合成案例和最小集成评估；是否追加真实 AV 资料、启用资源或更改 Core，按执行范围另定。

**本项不改变第一阶段主序，也不阻塞当前 App/Core 开发和部署验证。** 只有结果证明增益且能遵守现有来源、证据、版本与修订契约，才讨论作为工作包 5 / T3 的可选增强；否则保留现有实现，不因候选宣传重建架构。

### 维护收尾的有限范围

维护完成以[债务台账](delivery/debt-resolution.md)逐项证据为准，不采用原始报告未校准的健康分、季度工期或全库任意行数阈值。已完成事项转由维护收尾与仓库清理记录保存，不再列作未来工作。

本轮原三项实际维护已按证据处理，不以全库分数/行数归零继续扩张。依赖版本提示保留具体说明；启用新API或改变父链时重新核对。两个独立客户端的仓库退役已落实，App 内部兼容保留；AD-11 在线切换、实际部署与产品接受仍是独立未完工作，本轮最终工程结果由协调者记录。

“已反证”“明确保留设计”和“待部署验证”不是修复完成的别名，也不能混算完成率。需要取消能力、删除资产或改变既有保留范围的方案应单独提出；本计划不预先代作决定。正式入口可用且历史迁入对账完成后，才按 D23 退役相应快照路径。

**已有资产与未完义务。** C2–C4、Core、账号 App、纠正和连续性回归可复用；仍待完成的 U2 整体内容、旧认识校正与 U4 完整框架保持独立状态。优先处理遗漏、冲突和具体差异，不重跑全部语料。第一阶段有界可用不能冒充全量 AV 或 U1–U4 全部交付；契约见[统一 App 交付](implementation/av-understanding-app-delivery.md)。

**方法与形态。** 复用 R0 的方法研究与输入契约，按真实问题使用有限学术和方法知识。HUMAN 3.0 完整独立接入继续保留，不成为本人开始使用的前置。统一 Web App、账号模式及单一结构化权威数据是现有工程基础；具体资源与未来分身形式在各自方案阶段核验。本文件不据目标描述声称资源已启用。

| GAP-31 正式账号路径的持续对话尚未贯通 | Legacy 聊天或合成原型起步不能代替当前理解参与回答、新输入修订认识和下次使用 | P1-AC-03–06，按 AA 持续对话流程复用同一权威状态 |
| GAP-32 当前处理容量与长期积累存在差距 | 云端处理有来源数量上限；完整分页选择不表示所有累积材料都进入了判断 | P1-AC-08，明确范围、选择/分批与未覆盖内容，再依据实际缺口调整 |
| GAP-33 学习回应与回顾尚未完整回到当前认识 | 作品回应回显或将认识标待复核，不能代替可持久化个人来源和实际修订 | P1-AC-04、07，贯通选定的有限知识辅助路径 |

GAP 编号用于定位仍需处理的问题；实际实现以 As-Is 为准。T1–T4 是保留的能力分区，当前产品分期以 §1 和第一阶段范围为准。技术选择在解决具体缺口时评估，不把重选框架或引入人格图谱作为第一步。

### 本人入口的工程跟进

| 待补行为 | 边界与完成条件 |
| --- | --- |
| 导入专题被纠正后的修订 | 已导入的精确引文只有片段，不能冒充完整原文；处理新回应时，旧报告的支持、反例、争议和范围须有明确去向，发布新版本后不能把已纠正的旧解释继续当当前结论。 |
| 一次性导入对账与快照退役 | 将账号模式中的专题集合、原 U2 版本、审核出处和证据定位与固定归档逐项比对；只有一致且账号入口可读时才允许停用快照只读路由。 |
| 本人建号失败后的续做 | 跨认证库与身份库出现部分成功时，应能识别已建账号和旧本人作用域，安全续做或明确退出；不得自动建出新的空本人作用域。 |

## 3. T1：能够开始、能够澄清、能够纠错的单人垂直闭环

本节定义第一阶段复用的认识形成能力；持续对话、新来源更新、有限知识辅助和实际使用的完整阶段验收统一见[第一阶段范围](delivery/phase-1-personal-understanding.md)。单次探索通过不能替代整体阶段完成。

**业务结果。** 用户没有话题或历史材料，也可以完成一次有用的探索；有少量历史材料时，可以减少重复讲述。系统形成一条有限认识，用户纠正后，下一次相关交互真实改变。

**架构范围。** A1–A5/A7 的最小贯通：来源/片段、必要事件/情境、提问关联、认识版本、反馈与当前视图。可合并物理结构，不一次性实现 DA 全部概念或重写全部客户端。原生路径必须独立成立；历史路径先用小规模、明确来源的结构化样例验证，不建设全量采集平台。

**必须验证。** 零导入；引用归属；状态与模式区分；同源重复；支持与反例；用户事实纠正后旧解释不重现；记录数量不变但内容更新；分析排除在查询和回顾中一致生效。采用题组/角色/解释内容时同步检验固定版本、发布边界和不计分/计分类型；不是先建设完整测试中心或内容后台。合成样例先验契约，后续真实 dogfood 另获授权。

**退出标准。** 一次交互可以以有用整理或明确未知结束；至少能展示一条认识及其可追溯修订过程，而不是只保存反馈。不能做到时先修改引导/语义，不用扩大历史数据量掩盖。

证据评估的 T1 最小范围为用途资格、来源/关系评估版本、支持与挑战分离、同源去重、置信说明及影响传播。不部署复杂评分模型。必须验证仅有评估/关系改变、原始记录数未变时仍更新；误归属被更正后旧模型任务不能再次发布过期结论。

Insight Analysis 可先作为 T1 质量 profile 做合成评测，不要求立即新增 UI：至少覆盖表面问题与 reframe 分离、life-structure 缺口不由“没采集到”臆造、tension 两端都有证据、候选解释保持竞争、不能从意义缺口直接跳到唯一建议，以及反例能让 hypothesis 收窄或撤回。

三观进入 T1 的方式是逐条澄清与分类，不是首次使用就填满三观报告。至少验证：认可与向往分开、感到的要求不默认是真实偏好、受约束行为不直接覆盖自述、选择哲学不筛掉反例。用户可以没有主要视角，发现差异后也可以不改行动。

### 待评估：手机口述单个事件

目标是降低手机输入负担，流程为“口述一个事件 → 查看并修改转写 → 本人确认提交 → 沿用现有探索”。文字输入始终可用，未经确认的转写不直接进入分析；拒绝麦克风权限或转写失败时可继续文字输入，已有草稿不丢失。

在真实使用显示打字明显阻碍记录时进入实现。先判断系统听写能否满足需要，再决定是否增加 App 内转写；实现前明确音频传输、保留方式和成本，本项不包含持续录音、声音克隆或其他分身使用形态；那些能力若有明确需求，在相应阶段单独评估。

验收看是否更容易完成一条真实事件输入、是否能纠正识别错误并可靠提交；不以增加音频数据量作为收益。本项为后续候选，不改变单次探索质量优先的顺序。

## 4. T2：自愿改变与纵向认识

**业务结果。** 用户可从理解转向自己认可的小步尝试，也可只理解不改变；能回顾实际结果，分清模式、状态和解释变化。

**架构范围。** A6 与既有闭环贯通，覆盖 Goal、建议、用户确认、尝试、结果、停止/调整；完善时间范围、反例和 ProfileView 的变化原因。方法建议对接 A9 的独立内容依据，角色和行动模板保留版本；A7 可按证据生成个人使用说明及用户选定的沟通摘要。保留少量可选解释/观察/实践建议，不扩张成独立待办或打卡系统。

**必须验证。** 无完整画像也能提供有限建议；不同意人格解释仍可选择尝试；未执行不被归因成缺陷；一次改善不自动证明因果；尝试结果能修订认识；用户可以退出而不受催促。

**退出标准。** 有具体案例说明建议为何适合当时约束、实际发生了什么、认识或下一步怎样改变。只输出“高杠杆建议”不计完成；没有实际价值时缩小建议范围，不增加督促机制。

HUMAN 3.0 可作为首个 Framework Runtime 的目标内容。Dan Koe 的公开原始资料已足以核验 Mind / Body / Spirit / Vocation、Level / Phase、Lifestyle Archetype、Metatype、Channels 与 adaptive assessment 的总体结构，以及原协议的阶段计划结构（宣传段与输出区间差异见 R01）；进入实现前仍需把具体 DefinitionVersion 的内容引用范围、授权状态、rubric 与问题协议整理成可发布资产。未完成该步时只实现通用 runtime 或 draft definition，不把自拟内容标成 HUMAN 3.0 正式标准。框架计划只有用户确认后才进入 T2 的 ActionTrial。

### T2 可选支线：来源化多角色视角对照

先依据来源可用性选少量角色，完成有限作品集的来源/版本/归属核验、文本主张、现代推演规则与反例审核；老子、孔子、歌德为候选而非现成角色包。用户选定同一个事件即可对照，无需先拥有完整画像。先证明解释和行动取舍确有来源差异，再扩大角色库，不先建设通用“名人蒸馏平台”。

验收使用合成事件：换角色不能改变事实；同一思想内部的限定和不同解释不被抹去；引用可定位且不把戏剧人物当作者；证据不足允许空缺或不输出；用户反驳不被当防御；三个角色的相似回应不计为三份独立证据；用户能形成自己的选择而非只选名人答案。比较单一视角/无角色路径，只有增加实际理解或选择价值时保留功能。

该支线进入目标范围，但不设为每次探索或首个自用可用版的发布前置。当前仍未形成已审核上线的角色包，选定内容和实际模型验证属于后续交付。

## 5. T3：可选历史资产与来源增强

**业务结果。** 有历史会话或旧 L2/L3 的用户少重复叙述、获得新增可核验认识；没有这些资产的用户不受影响。Agents history 对当前所有者有价值，因此契约与样例从 T1 即进入验证，完整 adapter 不成为 T1 的前置工程。

**架构范围。** 依据真实价值选择 adapter，支持批次预览、来源/角色/时间、历史衍生结果、幂等、选择性加工、撤回与增量。Obsidian 只作为可选来源，不承担核心存储或运行编排。可复用旧结果，不恢复旧 TencentDB 依赖。

优先接入能提供渠道信息和稳定原始引用的来源，按 DA 的来源契约落实；先用一小批验证预览、证据回溯与撤回，再扩大接入。不把无出处的画像摘要批量导入后直接当作个人事实。

**必须验证。** 相同事件的原文和旧洞察不重复计证；缺原文的旧结论正确降级；片面工作语料不扩展成全面人格；adapter 失效不影响原生路径；关闭来源后既有认识按证据可用性处理。

**退出标准。** 与无导入路径对照，说明历史资料增加了什么新认识或减少了什么用户负担。若仅生成更长、更像旧报告的文字，停止扩建批量加工能力。

## 6. T4：个人多租户开放

**业务结果。** 第二个人及后续用户拥有完全独立的数据、交互、认识和尝试；不是由所有者管理或评估他们。

**架构范围。** 将 T1 起已明确的 tenant/subject 语义落实为实际认证、数据访问、引用约束、RLS、队列、缓存、索引、导出与数据控制。沿用既有客户端方向，不引入 organization/员工角色。

**必须验证。** 交错并发请求、任务重试、缓存命中、引用猜测、来源映射、导出与删除均不越租户；运行角色和数据库策略一致；认证变更不造成资料串属。测试使用合成租户，既有个人资料的归属迁移另行授权。

**退出标准。** 全链隔离和生命周期验收完成后才向第二个人开放。单用户可以先验证核心价值；多租户不能作为“日后加个 user_id 就完成”的承诺。

## 8. 验收设计与观察指标

优先用固定的合成反例验证契约：引用 AI 文本、同源重复、不同状态下不同表现、反向自我评价、纠正后再次提问、无证据的深析要求、没有执行的尝试、旧来源撤回、跨租户读写。每个案例检查事实忠实、范围、修订及权限，不只看 JSON 通过。

真实使用阶段在用户授权范围内检查：开启一次探索的负担；产生具体澄清的实例；未被引导预设的新增信息；误判被修正的过程；有用/无用建议及停止原因。少量新事件保留作形成认识后的检验，不为了迎合既有解释去选择样本。

### Exploration Quality Eval

Core reliability / API tests 证明写入、版本、幂等和依赖传播，不证明“这道问题值得问”或“这个解释足够克制”。进入跨事件综合前，单次探索需要一套与工程回归分开的固定质量评测集；真实 dogfood 用来发现遗漏，再把问题抽象成合成 fixture，不能直接把 owner 私人原话提交进 repo。

| 评测维度 | 合格表现 | 不合格表现 |
| --- | --- | --- |
| Ask / Stop | 有会改变理解的明确 uncertainty 才继续；已足够或只会增加细节时停止 | 为了“深入”机械追问 |
| Uncertainty targeting | 问题直接命中当前最大未知，答案分支会改变解释、范围或是否形成认识 | 顺着用户提到的词继续闲聊 |
| Information gain | fixture 中不同回答对应可说明的不同更新路径 | 无论怎么答结论都不变 |
| Redundancy | 不重复已回答问题；多选/混合答案被真正吸收 | 换句话重复问同一件事 |
| Unsupported inference | 一次经历不跳到稳定人格、隐藏动机、诊断或因果 | 语言连贯但证据跨级 |
| Scope discipline | claim 与时间/情境/证据覆盖一致，反例能收窄 | 从局部直接扩到“总是/本质上” |
| Traceability | Ask/Stop/Claim 能回到 EvidenceSet、policy/prompt/model/validator/input fingerprint | 只有最终文案，无法解释处理版本 |
| Latency | Save、Planner、Final Synthesis 分段测量，保存不被模型耗时阻塞 | 用一个总 spinner 掩盖保存与推理 |

这套评测的对象是策略、Prompt、模型与执行链，不是给用户打“认识准确率”。第一版先建立稳定 fixture 和回归差异，再依据 dogfood 决定是否需要数值门槛；模型自报 confidence 不作为通过依据。

数值预算、样本量、交互时长与成本上限在具体阶段依据试用和运行测量确定。当前不宣称统计效度，不设置“导入几千条”“准确率达到某数值”这类无依据门槛。

### 证据与修订的首批验收样例规格

以下是阶段设计需要选择的验收场景，不构成每次改动必须运行的全量测试清单。每项需要给定输入版本、操作顺序、期望状态/输出边界和不得出现的行为。

| 案例 | 必须观察到的结果 |
| --- | --- |
| 同一“喜欢某学派”的原话支撑不同认识 | 可支持表达过喜好，不直接证明稳定实践或外部主张为真 |
| 引用误认后用户校正作者 | 原文版本保留，不成立的本人观点关系撤销，依赖认识重评 |
| 同一事件的多轮、摘要和多角色重复 | 不增加独立事件数，不靠重复提升证据贡献 |
| 可靠反例与大量同源支持共存 | 全称断言收窄或撤回；频率性观察按场景复核，不做简单票数平均 |
| 过去成立/现在改变，与过去误读 | 分别更新适用时段或纠正旧解释，不把两者混成来源不可靠 |
| 未核验旧结论、缺时间、未知归属 | 明确保留未知，不填假原文/时间/中值分数；用途资格按所评估论断判断 |
| 用户置顶、偏爱角色或表达强烈情绪 | 关注顺序可变化，不据此调高/调低事实可靠性 |
| 调整评估/规则而不改记录数量 | 版本指纹与受影响认识/视图更新，无关范围不全量重算 |
| 生成中更正、排除与重试交错 | 旧任务不能覆盖新状态；排除立即约束后续读取；重试不重复发布 |
| 用户反对模型解释 | 可记录争议和不同解释，不能以反对作为防御证据；数据排除选择不等待模型赞同 |

### 待复核的历史体验决定

旧 ADR-030/031 的五目的地与道家文化底层不再作为新 App 的实施前提。品牌与界面基线以 ADR D14 为准，产品与架构以 D11/D15 为准。

保留的后续问题是实际使用中的导航、信息密度和内容适用性，而非重新决定已选品牌。道家属于自愿选择的视角，不预设用户三观或整体人格；具体标准工具、主题顺序和量化验收预算按实际价值决定，不恢复旧 P0–P6 排程。

## 9. 暂不展开

不优先重选前端、重建部署、建立通用会话归档、全量心理知识库、人格图谱、外部自动执行、组织管理或商业化后台。语音、多媒体、向量检索、OWL/图推理和更复杂推荐仅在具体缺口证明需要时进入下一项设计。

开发、实际数据处理和部署按具体任务授权推进，不因目标描述自动触发。
