# FindMe — 技术架构

> To-Be 技术响应。业务与语义由 [Overview](overview.md)、[BA](ba.md)、[AA](aa.md)、[DA](da.md) 决定；保留既有工程资产，先响应[第一阶段个人理解与对话](delivery/phase-1-personal-understanding.md)，不因文档更新执行迁移或部署。配置查找方式由 Commands 说明，本文不保存运行快照。

## 1. 保留基础与技术取舍

赛博分身是产品愿景，持续理解、可用的支持与建议、诚实挑战、知识引导及纠正后真实更新是技术需要满足的结果。第一阶段选择带 harness 的个人理解 Agent，方法论与质量标准以 skills 执行；具体职责见 [AA](aa.md) 与 [Agent 设计](implementation/personal-understanding-agent.md)。此方法蒸馏不等于人格蒸馏、微调或完整分身；这些未来形式尚未选定。后续具体方案按当时可用能力、效果、成本与实际缺口选择，现有实现不自动成为长期技术承诺。

沿用现有 monorepo、TypeScript、React 19 + Vite 浏览器客户端、Hono API 与 Drizzle/PostgreSQL。个人理解任务通过 pi SDK 承载的 Agent 执行，既有模型适配按具体步骤复用；不另建 Agent 服务集群。运行方式保持单节点，应用构建产物由宿主 Node 与 systemd 运行，PostgreSQL 保持原容器与数据（ADR D29）。应用 Docker 打包延后到确有分发需求时，不作为开发、CI 或功能验证前置；PostgreSQL 容器与应用打包独立，既有数据库无需因此迁移。部署脚本见[单节点部署](../deployment/standalone/README.md)。这里只说明拟复用的技术基础，不重复运行资源 ID、服务状态、模型版本或实时限额。

正式产品默认是账号制云端服务，手机与电脑消费同一 Core API、对话、个人理解、证据和诊断状态。唯一客户端为 `apps/app` 浏览器单页应用（SPA），手机 H5 与桌面同代码，不是原生安装包。独立 `apps/web`、`apps/miniapp` 及 Taro 工具链按 [ADR D25](adr.md#d25-直接退役两个独立客户端统一使用-appsapp-浏览器入口) 退役，不以迁移全部旧功能为前置；App 自身 native/private/diagnostic-preview/dogfood 兼容分支保留。Android/Capacitor 包装工程与 APK 构建链已退役。AV/Codex CLI/本机查看器仅为可选采集和研究工具，不要求普通用户安装、登录开发工具或保持电脑在线。

第一阶段复用来源、认识、会话、报告和任务机制，以持续多会话和跨会话原文读取为主，按需形成或修订认识。pi 会话也是数据库归档的来源，来源与运行状态的分工见 [Agent 设计](implementation/personal-understanding-agent.md#会话切分与记忆召回)。旧资源名或模型供应商不构成新需求的前提。

本地开发与验证使用测试运行器创建的临时 PostgreSQL；不把常驻本机数据库或旧 Box runtime 恢复为本人正式入口。FindMe 与其他应用保持独立的数据和密钥边界。

## 2. 从业务需求到技术响应

| 架构要求 | 技术响应 | 暂不做 |
| --- | --- | --- |
| 一套认识逻辑、多种客户端 | 核心在应用模块，客户端只消费契约与呈现；已有 API 工程内逐步实现 | 不在各端复制 prompt/画像逻辑，不重写客户端框架 |
| 主动探索与低负担响应 | 用户输入先持久化；必要的小处理同步，较重检索/生成可异步；会话状态可恢复 | 不承诺任意固定响应时间，不把每轮拆成多 Agent 流水线 |
| 对话与综合呈现使用同一理解 | 按意图读取当前认识、相关来源和最新纠正；回应、总览、专题与建议共用版本及失效规则 | 不另建聊天记忆真源，不要求每轮都产生新认识或完整报告 |
| 轻量本体及修订链 | 关系键、类型、版本、约束与受校验 JSONB；可重建投影视图 | 不默认图数据库、OWL reasoner、向量平台或新数据库 |
| 多源 adapter 可选 | 核心接入契约与端口；来源解析/导出格式在 adapter；核心校验不外包 | 不让 vault 路径、AgentsView schema、旧数据库运行影响主链路 |
| 纠正后不重现旧误解 | 认识版本、依赖失效和集合指纹；缓存/任务检查版本与使用范围 | 不以记录数量判断所有内容都没变化 |
| 个人多租户 | 服务端身份映射、数据访问作用域、数据库防护、任务与导出归属 | 不引入组织/员工模型，不把认证插件等同于数据隔离 |
| 可解释、可复核 | 来源定位、逐认识证据、生成元数据、反例和反馈回归 | 不记录模型隐藏推理，不以日志囤积私人全文 |
| 独立判断与有据支持 | 个人解释与学术/方法依据分开；质量检查同时覆盖迎合、无据批评及忽略纠正，保留未知与替代解释 | 不以语气冷静、批评尖锐或模型自评分数证明客观 |
| 认识形成策略可执行 | 版本化 Epistemic Policy；Deterministic Gate → Semantic Planner/Synthesizer → Deterministic Validator；生成记录保存 policy/prompt/model/validator/input fingerprint | 不把产品硬规则只写进 Prompt，不为此新建通用规则引擎或图推理平台 |
| 可选结构化验证 | 版本化工具/作答/规则；纯确定性计算与 LLM 解释分离；固定样例验证缺答、边界和重算 | 不让模型计分，不预选疾病主题或擅自变更标准题目 |
| 内容及角色可还原 | 版本化内容清单、发布/撤回检查、角色/prompt/模板引用可解析；先用小规模文件或现有存储实现 | 不以完整 CMS、embedding 或外部知识库在线作为前置 |
| 可携带的认识 | 完整个人数据包与范围可选的沟通摘要分开，明确覆盖对象、版本和未包含外部内容 | 不把三张业务表的 JSON 自动称为全部个人数据 |

业务模块先在现有应用内分职责，不直接扩展为微服务。源档存储职责按下节确定；具体供应商、桶、配额和迁移在对应交付核验，不默认采购新服务或要求多媒体输入。

### 2.1 正式存储与多端运行分工

**`owner-entry-v1` 历史系统上下文（原 G1 基线，ART-CONTEXT）。** 以下保留原范围对账号、专题读取和纠正的技术映射，供已有实现复用和差距核对；其中指定的 Neon、DeepSeek、零预算及一次性归档导入条件不自动成为新第一阶段的完整方案或当前状态。新范围增加持续对话、新来源与知识辅助，按[第一阶段范围](delivery/phase-1-personal-understanding.md)补齐相应读写、处理与恢复关系；实际资源及启用状态以实例配置核对为准。

| 边界对象 | 与 FindMe 交换的内容和方向 | 原 owner-entry-v1 的责任与边界 |
| --- | --- | --- |
| 本人／浏览器 | 本人向 App 提供登录、Profile 选择和纠正；App 向本人返回专题、精确依据、处理状态与当前版本 | 浏览器只持会话与草稿；服务端决定身份和作用域，不信任客户端填写的 owner |
| 单节点应用（Node） | 向浏览器提供页面和 API；接收经认证的读取、保存与处理请求 | 当前唯一运行入口；部署状态查询实例，不由本表推断 |
| 进程内执行器 | 从任务表领取带租户、目标版本与预算的任务并回写结果 | 异步执行与重试不能自行扩大模型调用上限；阅读和导入不排队调用模型 |
| 节点本地原档目录 | 服务按权限写入、读取和清理原档文件；主库保存来源、校验和生命周期状态 | 浏览器只经鉴权接口下载，不直接访问文件 |
| PostgreSQL | 读写账号、Profile、来源、证据、报告、反馈、版本与应用设置；管理员角色建表并应用访问策略 | 账号模式是唯一运行真源；默认同节点容器，可改为外部库 |
| 模型出口（兼容 OpenAI 接口） | 只有本人获准的处理任务才向模型发送有界上下文并接收候选；审核后方可发布当前版本 | 服务商、密钥与预算在 App 模型设置中配置，默认关闭、预算为 0；不把模型输出直接当已通过认识 |
| 邮件服务 | 本轮不交换注册或验证邮件 | 尚未配置，不作为本人账号开通前置；开放第二人前另行决定 |
| 归档快照只读接口 | 过渡期间向本人返回既有归档报告与依据；账号模式从合格归档版本一次性导入 | 导入核对一致且账号入口可用后退役读取路由；归档表与数据的删除不属于退役 |

| 位置 | 保存与负责 | 不承担 |
| --- | --- | --- |
| 云端 PostgreSQL 主库 | 账号/租户、来源版本、精确证据与必要上下文、经历/情境、认识修订、诊断运行/报告/反馈、任务与引用关系 | 不按 L1/L2/L3 分数据库，不把关键归属/版本藏进无约束大 JSON |
| 对象存储 | 用户授权托管的原始导出、附件及大档案；主库记录对象键/版本/校验/生命周期 | 不维护独立个人画像；不允许客户端凭任意对象键绕过权限 |
| 派生检索索引 | 由主数据构建的元数据/全文检索，必要时使用 pgvector | 不成为事实源；未生效或已排除材料不能通过检索绕回 |
| 设备本地 | 草稿、缓存、待同步操作、可选仅本地原档 | 不承担唯一权威业务库，不各自重算一套诊断 |

对象存储通过小型接口接入，可优先评估与现有平台兼容的实现；接口定义不表示已开通资源。先使用主库关系/元数据/关键词检索，只有实际召回缺口才启用 pgvector；不预设独立文档库、向量服务、图数据库或 Redis。

服务端从账号导出个人租户，手机和电脑共享同一对话、当前个人理解、诊断及操作状态。写入使用幂等键/版本前置条件，离线初版只承接草稿与待同步操作，不承诺完全离线诊断或引入 CRDT。已同步证据和原生新输入不能依赖桌面常开；未同步本地原文回查失败需明确降级。

### 已有专题的过渡接入

按 [ADR D23](adr.md#d23-账号模式云端数据库为唯一运行真源其余运行路径冻结或退役)，本人验收直接走账号模式：已通过专题一次性导入 §2.1 的主库，不再以本机私有报告 adapter 作为验收入口（该 adapter 冻结）。账号模式可用之前，只保留归档快照的只读读取作过渡，导入核对一致后退役。任何路径都不得将 corpus 或报告复制进前端公共资源、认证前公开路径或 Git；现有模型、来源资格和版本检查不因统一界面被绕过。

这条路径处理既有合格专题的迁入，不覆盖新阶段的全部输入。新对话、经历、学习反馈及后续语料按同一来源、认识与修订契约进入账号模式；所需运行资源在第一阶段方案中确定，旧专题可迁入不等于新阶段已经可用。

### 2.2 对话、认识修订与诊断任务的一致性

持续对话、认识修订与个人发展诊断复用 M-X2 和既有队列/operation 机制，短事务保存输入与运行状态，模型在事务外执行。任务固定认证导出的租户、本次意图、相关认识和内容版本、输入协议及 EvidenceSet 指纹；发布前重查资格和版本。对话可直接使用当前理解，新的来源或纠正只触发受影响判断、回应上下文和视图的更新，不每天全量重读语料。

保存成功、回应完成、候选认识形成和当前版本更新是不同结果。生成失败不丢失输入或已生效的纠正；继续对话时使用当前可用认识并明确尚未完成的更新。普通支持与解释不强制创建 DiagnosticRun；需要综合诊断时才使用相应方法/框架与报告契约。

内容和文件的事务不能假装跨数据库/对象存储原子完成：上传/校验/可用状态明确，失败可恢复，删除和重建有可核验结果。运行角色的数据库访问和对象存储访问均受租户约束；缓存、下载、导出和任务消费一起验证。

正式产品采用不依赖用户个人 Codex 登录态的服务端模型出口；当前 CLI 能继续做私有评测与开发，不打包或代用所有者凭据给其他用户。云端 provider 的能力、计量和恢复另行实测，不把 CLI 用量当 API 成本。

## 3. 个人多租户的技术约束

目标租户从已认证账号在服务端解析，不信任客户端提交的 owner/tenant 字段。所有个人读写、来源映射、证据查询、任务消费、缓存、导出和可能增加的检索索引带作用域；跨租户引用需在服务端及关系约束层拒绝。

账号模式已用 Better Auth 的 email/password 与 PostgreSQL 适配接入（实现见 [C 系列契约](implementation/c-series-cloud-runtime.md)），尚未在生产启用；微信等其他 provider 仍是候选，在多用户阶段另行验证。个人租户不需要 organization 插件模拟。static 固定访问方式不能用于第二位用户的隔离证明。

数据库设计采用显式租户过滤及 RLS 防护，运行角色与迁移角色分离。RLS 的表所有者/特权绕过行为必须被纳入验证，不能只检查“有 policy”。身份、行隔离、业务权限和引用完整性是不同检查面。依据见 PostgreSQL 官方 Row Security 文档。

连接池场景不依赖跨请求的会话变量保留；租户上下文在事务内设置，并用交错请求验证不会串租户。事务保持短小，模型调用不持有数据库事务。

涉及私人结果、纠正后读取及 RLS 上下文的缓存，必须证明键/作用域隔离和失效正确；未证明前相应读链路不启用共享查询缓存。

## 4. 任务、模型与一致性

保留已有异步任务和队列资产，按新契约增加必要语义而非重建通用任务平台。任务至少知道租户、目标对象/版本、输入指纹与处理版本；重试不能重复创建认识或重复计算同源证据。

处理开始与发布前复核使用范围和输入版本。生成耗时期间发生纠正、排除或删除时，旧结果不能未经检查重新发布为当前。更新认识版本、标记被替代版本和安排视图失效应有可验证的一致性方案。

Agent 是待对照验证的候选实现：按[工作计划](delivery/agent-work-plan.md)通过 AG-04 质量对照后才替换现有处理链路，没有增益时保留现有链路。采用时，Agent 通过可替换模型适配调用 Provider，客户端不拼私人人格 prompt。pi SDK 采用应用自有上下文、资源加载器和领域工具，关闭默认编码工作区资源的继承；具体版本和运行契约见[Agent 设计](implementation/personal-understanding-agent.md)。模型选择和上下文装配在对应方案中按当时能力确定，不能把某个当前 provider 固化为赛博分身的定义。采用结构校验、引用校验、语义质量检查及可降级输出；模型自评 confidence 只作元数据。结构化测评的确定性分数独立于模型输出；角色、规则、内容和 prompt 的版本必须能还原实际使用内容，不能仅有一个无法解析的版本字符串。

### 认识推理分级与决策血缘

探索和认识生成采用三段式执行：**Deterministic Gate → Semantic Planner / Synthesizer → Deterministic Validator**。Gate 先执行租户、来源用途资格、版本、question lifecycle、预算/hard cap、幂等与已知重复等可确定条件；Agent 在这些边界内调用工具和模型比较候选解释、识别关键 uncertainty、生成有限 scope 与自然语言；Validator 再检查结构、evidence 引用、scope、重复、stale version、Ask/Stop/发布前置条件。任何一层失败都不能把模型候选直接升级为当前认识。

该分工用于当前工程的可核验执行，普通对话按回应意图使用相应检查，不要求每轮经过完整诊断或主动补问。未来替换模型或执行方式时，需要保持来源忠实、独立判断、修订传播和可恢复等结果要求，不要求沿用同一技术形式。

Epistemic Policy 应使用可解析版本，并和 prompt/model/validator 分开记录。GenerationRecord 或等价元数据至少能还原 `policy_version / prompt_version / model_route / model_version / validator_version / input_fingerprint`。Policy/Prompt/Model 更新属于系统处理变化；若它改变既有认识，需要以重评/新版本表达，不能覆盖旧历史后声称用户本人改变。为复核保留决策输入/输出和理由字段，不保存或展示模型隐藏 chain-of-thought。

错误和审计日志默认只有必要元数据。为复核保留的来源和生成信息留在受租户约束的业务存储，不进入普通日志；不回显密钥、访问串或完整私人语料。

### 评估版本与选择性重评

将 DA 的来源/关系评估作为现有业务存储中的受校验、可追溯状态实现，不新增通用评分平台。规则定义、评估结果、模型自评和用户校正可区分；用于排序的数值须有语义和版本，不作为未标定的概率暴露。资格校验先于向模型提供上下文，也先于权重排序。

影响范围以明确引用和版本关系定位，输入/缓存指纹含来源评估、关系评估和规则版本，而非只看内容条数。更正或排除与相关待复核标记须有一致性边界；慢速生成在发布前比较所用版本，过期结果不可覆盖新状态。具体事务、幂等键、并发更正处理及依赖索引须在首轮 task Solution Design 中确定，再以合成竞争时序验证；不把文档描述当作已实现的保证。

初始评分规则先满足可复核的等级与不变性案例，不以精确权重公式、概率校准或新增模型作为开工前提。未来只有确定的预测目标、评估集和校准方法就绪后，才考虑概率化表达；更换规则造成的变化必须与用户真实变化分开。

## 5. 质量、成本与数据控制

成本以单次有效探索、认识更新和有用结果衡量，不以更多蒸馏调用代表更好。对重复材料选择性加工，按问题构建 EvidenceSet；模型/上下文预算在固定回归任务上验证后确定，不在文档里猜测价格或调用阈值。

按个人自用项目进行与改动影响相称的验证：文档改动只查结构、引用和语义；界面改动检查实际效果；局部逻辑只运行相关检查；保存、修订、鉴权或删除改动验证对应数据行为。完整回归不是每次提交或部署的默认前置条件，只有共享契约/schema、大范围流程变化或具体失败扩大影响面时才运行。必要检查通过即停止，后续修改只重验受影响部分。

真实模型评测通常运行一轮；有明确修复才复测，不为追求全绿反复调整样例或 Prompt。测试代码与验收条件分开：长期正文不累计运行次数、通过数量、耗时、日志、Agent 分工或发布流水；有交接价值的结果进入统一任务记录，实际产品缺口提炼进 Roadmap。

数据库测试只能使用显式独立测试库与合成案例，完成后清理合成数据；不能因测试连接可用而写入 production。文档验收不运行会连接数据库、生成 seed 或启动服务的脚本。测试通过只证明其覆盖的契约，不证明新的认识质量或租户隔离。

另维护 **Exploration Quality Eval**，与 API/reliability tests 分开：固定合成 fixture 检查 Ask/Stop、uncertainty targeting、答案是否可能改变理解、重复问题、无依据推断、scope discipline、反例处理和 evidence traceability；运行测量另记录 Save / Planner / Final Synthesis 的延迟分布。语义评测给策略/模型回归用，不生成“人格准确率”，也不把模型自报 confidence 当质量指标。真实 dogfood 用于发现 fixture 未覆盖的问题，私人原文需抽象后才能进入 repo 回归集。

第一阶段同时检查同一纠正能否改变后续回应和综合呈现，已知背景是否减少无谓重复，支持与质疑是否各有依据，以及引用学术内容时能否区分普遍方法与个人解释。迎合用户和为了显得深刻而无据批评都属于需要识别的问题；客观性不按批评次数或语气强度计分。工程检查通过和本人感受到实际帮助分别记录，不能互相代替。

数据控制涵盖源记录、派生认识、索引、缓存、任务、导出和备份。迁移/删除前必须有明确授权、可恢复方案和结果核验；托管数据库不自动等于恢复流程已验证。备份存在与可恢复能力需按具体任务核实，不在长期正文保存过期状态。

### 三观与角色对照的实现约束

复用现有应用、内容发布和 Agent 内的模型适配：角色资产作为受版本管理的声明式内容装配，按同一输入情境分别调用，不要求增加独立服务、Agent 网络、知识库 runtime 或图数据库。角色输入不授予任意工具执行权限，也不能覆盖来源/租户/输出契约。

对照的缓存与任务键包含租户、输入材料及版本指纹、角色发布版本和处理版本；纠正或来源撤回必须使旧结果可识别为过期。共用角色定义不等于共用私人上下文。允许少量角色、选择性检索、按需生成和局部失败，调用数量/延迟预算由后续验证决定。

### 开发与运行边界

密钥只在后端 secret 或本机忽略配置中提供，访问串不进入 query、前端 bundle 或日志。未经明确授权，不批量读取、迁移或加工真实历史私人语料；文档、示例和测试不包含所有者真实经历或健康信息。corpus 位于仓库外，不提交 Git，也不作为 Obsidian vault；原始记录删除仍遵守现有 delete-guard、引用保护与审计约束。

不恢复已退役的 Box/阿里云 FindMe runtime、旧常驻本机 PostgreSQL 运行链或旧 TencentDB 抽取链作为本人正式入口；临时开发与合成验证按 §1 的现有方法处理。不因 FindMe 工作影响其他应用、共享 PostgreSQL 或 sing-box。旧模式接口、任务队列和旧表已随单节点化移除；删除以实际引用为据，不按文件年代判断。

## 6. 后续实现的触发条件

个人理解 Agent 的语义召回使用同库 pgvector 索引（见[Agent 设计](implementation/personal-understanding-agent.md#会话切分与记忆召回)），因为中文同义表达无法靠关键词可靠召回；不另建向量服务，向量仍是可重建索引。其他场景的向量检索只有在元数据/关键词/关系检索无法满足召回或成本时引入。若用于编辑内容，只召回适用且已发布的内容证据片段，返回出处及版本，支持无结果；这项发布过滤不等于要求私人原生表达先由内容编辑审核。图存储或语义推理仅在具体多跳查询、约束或互操作需求证明有益时评估，不能因 DA 启用本体就自动引入。

离线工具只服务可选历史输入和开发研究。普通用户应能在线完成主流程，不能由用户承担脚本、目录同步和人工 schema 映射。各 adapter 的错误不传播成原生功能不可用。

存储职责和云端多端边界沿用已确认设计；具体资源、模型与可选适配在交付时核对，文档更新不恢复停用服务。当前 Agent 与方法 skills 的实现按[工作计划](delivery/agent-work-plan.md)推进；方法资产、运行框架和模型彼此可替换。先以[第一阶段范围](delivery/phase-1-personal-understanding.md)贯通可用的个人理解与对话；[既有产品代码计划](implementation/diagnostic-product-plan.md)提供可复用切片，当前优先级由 [Roadmap](roadmap.md) 管理。更复杂的分身表达、模型适配或代理形态，待相应需求进入方案阶段后评估当时技术，不据当前方法 skills 的选择预先指定人格蒸馏或微调路线。
