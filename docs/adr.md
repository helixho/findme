# FindMe — 架构决策

> 本文只记录持久选择、理由与取舍，不维护日常变更日志。用户已确认的需求边界与本轮依据需求提出的设计选择分别标识；设计进入文档基线，不等于效果已验证或代码已实现。

## D1 以可校正的自我认识及自愿改变为产品主线

**当前关系（2026-10-30）。** 本决定的可修订认识与自愿选择继续有效；整体愿景、核心价值、方法及交付形式按 D24 分层，避免把本阶段用途限定为长期产品终点。

**来源：需求已确认。** 用户需要有依据的批判、主动引导以及尝试改变的支持，不要求擅长自由分享。产品不再以“积累足够原始资料后生成完整人格报告”作为启动与成功标准。

**决定。** 覆盖真实经历、情境、观察、候选解释、反例、纠正及后续结果；建议和尝试可选，不强制每次交互走完整链路。画像是阶段性呈现。

**取舍。** 放弃对唯一、永久真我的承诺，换取具体、有限、可被现实修正的认识；允许系统在证据不足时只整理或保留未知。业务标准由 BA 定义。交叉检查确认，旧目标已有多入口、候选假设和行动验证；本决定是重新收敛与强化该方向，不把旧设计整体描述成仅有原始语料蒸馏。

## D2 BA 先行，AA 与 DA 共设计，保留客户端工程资产

**来源：需求已确认。** 优先业务能力、应用功能和信息语义，不以客户端技术选型消耗设计优先级。

**决定。** BA 定义业务价值及过程；AA 划分应用职责与契约；DA 规定概念、关系及生命周期，两者互校；TA 响应技术约束。保留小程序/Web 工程资产；Android/Capacitor 包装工程与 APK 构建链按用户明确要求退役，手机使用统一 Web App；默认账号制云端多端形态按 D21，不再把某客户端的验证身份当作长期产品限制。

**取舍。** 客户端确实可能影响权限和交互，但不改变核心认识语义。本轮不重选前端、不重建部署，不按当前页面或数据表限制新设计。

## D3 使用轻量领域本体，暂不引入形式化推理平台

**来源：本轮架构设计选择。** 来源归属、事件、状态、解释、反例、修订和尝试之间需要稳定语义，纯标签摘要不足以表达这些区别。

**决定。** 在 DA 明确概念、关系、问题与约束，重点描述认识形成和更新；关系数据库和类型化契约优先。概念不逐一对应表，模块不逐一对应服务。

**取舍。** 获得一致语义和可扩展关系，但不承担通用人格本体、图数据库、RDF/OWL 或 reasoner 的当前成本。未来只有具体查询/互操作需求证明价值时才升级；术语形式化不能证明人格推断正确。

## D4 核心与所有外部来源解耦

**来源：需求已确认；接入契约为本轮设计。** Obsidian、AgentsView、离线脚本及历史数据库不能成为核心运行条件。

**决定。** 原生交互在线独立闭合；外部系统通过可选 adapter 进入统一接入边界。adapter 转换格式与保留来源，核心验证归属和使用方式，不让 adapter 直接写入“已验证人格”。

**取舍。** 当前所有者可继续利用历史会话优势，但普通人无需具备桌面预处理条件。来源可不可用，不改变产品能否基本运行。文档存放位置与产品运行依赖是两个问题，不能把旧文档在 Obsidian 内误写成运行时依赖已获证实。

## D5 多用户是个人多租户，不是组织管理

**来源：需求已确认。** 每个人是独立个体，使用工具理解自己。

**决定。** 目标每人一租户、一个本人主体；Account 与租户/认识主体概念区分。私人源记录、认识、反馈、任务、缓存和导出全链归属。具体隔离机制在 TA 设计并在开放第二人前验证。

**取舍。** 不引入 organization/员工角色，不提供管理员代看或管理他人 profile，不实现跨人共享人格或身份去重。现有单用户不因为文档出现 Tenant 就已完成多租户。

## D6 复用历史认识，但不把衍生结果洗成原始事实

**来源：历史资产复用需求；分级方案为本轮设计。** 有价值的旧 L2/L3 不应因换系统一律作废，也不应无需核验直接成为真值。

**决定。** 按实际语义而非 L 层编号接入。可回溯结果保留证据映射；只有结论的保留为有出处的未验证历史认识。允许复用、局部补充或按需重算，不要求全部原始历史重做。

**取舍。** 接受有价值的不完整来源，但明确缺什么。同一来源的原文、摘要和再总结不构成独立证据；用户认可可以保留，不代替原文核对或事件独立性。退役 TencentDB 运行依赖不等于丢弃其已有知识资产。

## D7 批判依赖证据与纠正，不依赖固定锋利语气

**来源：需求已确认；质量机制为本轮设计。** 产品需要真实的批判声音，而非讨好、羞辱或证明模型比用户更了解用户。

**决定。** 同时挑战自我辩护、自我否定和 AI 解释；区分事实错误、解释异议、范围改变及风格偏好。逐条论断保留依据和替代解释，用户纠正影响后续认识。

**取舍。** 允许直接指出矛盾、提供建议，不保留“不许使用差距/应该等词”的机械禁词。不得以不同意解释作为防御证据；不得强填隐藏动机或消耗性循环。临床疾病诊断与治疗不属于产品能力，不因自用而把疾病标签当画像内容；D20 的个人发展诊断是有范围、可修订的评估与解释。

## D8 repo 内新八文档接管有效基线，旧权威入口一次退役

**来源：文档重建任务已授权；有效文档收口方案为本轮决定。** 新编写及旧基线退役需要在可访问且可版本管理的位置完成，不能让外部知识库访问决定核心设计能否推进。

**决定。** 当前有效正文为 docs/overview.md、ba.md、aa.md、da.md、ta.md、as-is.md、roadmap.md、adr.md。AGENTS 作为唯一 Agent 入口指向它们；旧入口和旧正文不维持平行规范，不另建 archive 副本重复维护。

**取舍。** 旧规则保留在 Git 历史；外部原件不作为平行正文，也不因文档整理自动删除。仍有效的设计应归入对应职责文档，不另建 archive 副本重复维护。

## D9 目标完整描述，实施分阶段，运行事实不改写

**来源：本轮范围已确认。** 不涉及代码、配置、schema、真实数据处理或部署。

**决定。** Overview/BA/AA/DA/TA 描述目标；As-Is 只记录源码和既有证据；Roadmap 管理差距与 Transition Architecture；AGENTS 只作索引；配置与运行状态查询实际来源，执行交接记录独立管理，不在设计正文相互复制。

**取舍。** 新基线可以覆盖完整业务过程，但不一次性实现全部实体、adapter 或租户机制。执行须另行形成阶段需求；文档验收不启动会访问个人数据的构建、测试、导入或模型脚本。

## D10 旧基线交叉检查与有效设计回收

**来源与范围。** 已完整读取用户提供副本中的 `L3-notes/Projects/helix-findme/` 八文档（正文标注更新于 2026-07-14/15），以及 `L3-notes/Methodology/本体论应用：findme 案例.md`（标注 2026-08-10）。这些是历史文档来源，不是当前运行证据；未读取该副本中的原始 sessions，不提取其中案例作为个人运行数据，也不修改副本。

**需要纠正的判断。** 旧 Overview/BA/AA 与 ADR-029 已明确多入口、候选解释、验证路径和行动闭环；旧 As-Is 同时承认实现仍是记录—探索—洞察。当前实现的短板不证明旧 To-Be 都过时，重建正文也不构成遗漏既有需求的理由。

**决定。** 新主线、个人多租户、adapter 边界和可修订认识模型保持；补回可选结构化验证、确定性计分、编辑内容独立证据链、角色与方法版本、个人使用说明及可控摘要导出。不恢复测试优先、疾病主题首发、固定八维、固定周期保证、组织模型或旧运行方案。

### 方法论笔记的采纳与修正

采纳以 competency questions 驱动语义设计、原文定位、候选实体/解释不冒充事实，以及 Agent runtime 包装和引用需要识别。记录量、个人案例数字和旧目录引用仅是历史说明，不带入现状或新数据。

不采纳两个捷径：有 session_id/原话只证明可定位，不代表完整证据链或语义支持；prompt-quality、短指令或重复表达既不能直接评人格，也不能机械反转成正向人格结论。应核对实际上下文，区分工具限制、情境和用户选择，无法判断就保留未知。

### 证据边界与实施影响

As-Is 对旧 prompt 快照、全量导出和题组计分声明做了源码核对；旧运行状态不覆盖实际配置与平台。新 AA 增加 A8/A9 是补全目标职责，不授权建服务、CMS 或上线临床主题。实现仍从 Roadmap 的引导—认识—纠正垂直闭环开始，所采用内容只建立必要版本与发布边界。

## D11 三观是持续探索的输出，视角偏好不能预填真实自我

**来源：用户已确认。** 用户认可以世界观、人生观、价值观作为 FindMe 重要产物，并同意把自述、向往与实践的差异视为需要理解的过程，而不是由 AI 裁决哪一项才是真我。

**决定。** 分开维护本人认可、向往、感到的要求、实践观察与系统解释；三观是当前认识的可修订视图。哲学选择是可选探索偏好，可不选、可更换，不能作为推断真我或筛选证据的前提。事实性信念仍可核验，价值取舍不由系统评分。

**处理差异。** 先查归属、情境和系统误读，再考虑理想尚未实践、现实约束、多价值冲突或认识变化。用户可继续理解、调整行动/环境、修订原则或保留未决，不自动启动价值一致性矫正。

**替代关系。** “先选择主要价值观，让系统按它理解用户”不作为实施原则；改为“视角是输入，三观是输出，两者有来源关联但不相互证明”。自我差异和价值研究仅提供概念参考，不等于 AI 已具备识别自欺或客观真我的测量能力；研究说明见 methods。

## D12 有来源的多角色视角对照，不做历史人物复活或多数裁决

**来源：用户已确认功能方向；角色资产结构与审核流程为本轮设计。** 支持对一个事件、行为或对话，比较老子、孔子、歌德等由著作整理的思想视角，以及可能的态度、行动与取舍。

**决定。** 先共用情境事实，再按角色的来源及版本生成有限的现代诠释。保留原典/转述/情境推演的区别、必要假设与未知；不声称本人一定怎样做，不将作品中角色台词直接当作者信念。角色之间可重合、可分歧、可无足够依据，不为视觉差异强造相反答案。

**应用与数据边界。** A9 提供声明式 RoleDefinitionVersion/role skill，A1/A4 组织调用，A5 检查，A7 对照，A6 仅接续用户选择。复用既有模块和模型出口，不新增独立角色平台。公共角色资产与私人事件/回应分离；角色意见不是个人证据，用户被提示后的认可不成为独立验证。

**取舍与交付。** 自主选择和证据质量优先于人设逼真。该能力是可关闭的增强路径，不要求三观先定型，也不是每次探索的必经流程。未实际蒸馏、审核或发布任何候选人物；相关时序与验收在 Roadmap T2，不以已生成概念图宣称完成。

## D13 来源质量、证据贡献与认识置信度分开，并可沿依赖修订

**来源：用户已确认原则；分层职责与具体语义为本轮设计。** 不仅最终认识，材料的来源判断、证据作用和置信说明也需可修订。一个统一 confidence 或永久来源权重不足以表达这些差别。

**决定。** 来源质量评估原文/归属/上下文；证据作用针对特定认识、情境和版本，区分支持、挑战和仅供背景；认识置信说明综合证据、覆盖、反例与未决解释。先检查使用资格，再评估贡献；检索排序、本人认为重要和角色偏好均不等于证明力。未知不伪造分数，模型自评不当已标定正确概率。

**修订与控制。** 原始载荷及历史不静默覆写，允许通过版本/注记更正归属、转写、时间与使用方式；更正沿来源—关系—认识—视图/任务传播。权限排除立即执行；认识异议、确证错误和真实变化分别处理，不为保护旧结论压低反例，也不将单条证据失效等同于全盘为假。

**取舍。** 首版用状态、限定范围与可读理由完成最小机制；不引入评分服务、统一衰减公式或人格准确度。具体物理契约、评估等级及不变性样例在首轮实施设计中收口；本文不是代码实现或方法校准验收。语义权威见 DA §5.4–5.6，开工缺口见 Roadmap。

## D14 B 方向「交叠椭圆」作为品牌与界面基线

**来源：用户已确认。** 用户在三个方向中选定 B 的配色与整体风格，并确认品牌标志随之采用 B，原话见[方向确认](../design-demos/direction-approved.md)。完整页面结构见[信息架构](../design-demos/information-architecture.md)。

**决定。** 标志为三个开放、交叠的椭圆，表示多个专题共同解释同一情境、视角之间保留修订空间。界面以深墨绿与浅黄绿为主题，另提供跟随系统的浅色主题。标志的实现真源是 `apps/app/src/FindMeMark.tsx`；配色、字号与组件以[完整原型](../design-demos/full-prototype/index.html)的样式为设计参考，接入正式 App 时转为 App 的 token。品牌 slogan 保持“看清自己。 / See Yourself Clearly.”；“从真实经历出发，持续修订对自己的理解，做更自主的选择。”保留为产品价值说明，不与 slogan 混用。UI 默认 Sans；依据、反例、未知、待核验与修订用文字和标签区分，不只依赖颜色。

**版本边界。** 目前没有版本化的 B 品牌资产包，标志的光学精修与独立的小尺寸版本尚未制作。`apps/app/public/` 的应用图标已换成 B 标志：深墨绿底、浅黄绿线条。

## D15 目标产品架构优先，现有 V1 仅作为 legacy 数据源与迁移参考

**来源：用户已确认。** 后续实现不受当前线上页面、旧 L1/L2/L3、八维画像、现有 API 或表结构约束；这些资产不能反向决定产品的理想形态。

**决定。** 新实现从目标领域模型出发：个人归属 → SourceItem / SourceAssessment → EvidenceSpan → Experience → Claim / ClaimRevision / ClaimEvidence → Exploration / Feedback。来源质量、证据作用、认识置信与修订传播直接进入核心模型，不再通过旧 raw_records / light_extracts / insights 的兼容字段模拟。

**实施方式。** 在同一 repo 内建立独立 @findme/core 领域契约和新的 core schema；旧 V1 代码可继续存在直至切换，但只承担 legacy 运行和未来 adapter/migration source 的角色。新 Web/API 以目标体验和目标契约开发，达到可用与验收门槛后再决定迁移、切换和旧链路退役，不做逐页面/逐接口兼容。

**取舍。** 接受一次结构性重构成本，换取长期语义一致性；不为了复用旧代码牺牲三观、可修订认识、证据分层、多角色视角和自主改变等核心产品能力。运行迁移与数据导入另行授权，不由本决策自动执行。


## D16 本体表达与认识形成策略分层，确定性规则不埋进 Prompt

**来源：Purposeful Exploration 的真实 dogfood 问题、2026-09-22 对本体/AI 原生方法文章的定向复核，以及现有 D3/D13 的证据与修订原则。** 外部文章作为工程启发，不构成 FindMe 产品效果或本体正确性的证明；阅读边界见 方法研究 S29。

**决定。** 轻量本体继续回答“系统允许表达什么对象、关系、状态和版本”；另引入逻辑上的 **Epistemic Policy**，回答“在什么条件下可以继续问、停止、形成 observation/interpretation、扩大或收窄 scope、保留 unknown 或发布 ClaimRevision”。二者不合并成一套 Prompt，也不要求新增通用规则引擎。

**执行分层。** 能确定执行的资格、权限、版本、问题预算、hard cap、question lifecycle、幂等、引用存在性和 stale precondition 由代码/规则执行；LLM 只承担关键 uncertainty、候选解释、替代解释与有限自然语言表述；模型结果必须经过确定性 validator 才能创建问题或发布认识。Prompt 是版本化实现资产，不是产品规则的唯一真源。

**可追溯与评测。** 生成活动需能还原 policy/prompt/model/validator/input fingerprint；系统规则变化与用户真实变化分开。认识质量优先通过固定回归 fixture、反例和真实 dogfood 评测，不以模型自报 confidence、生成长度或更长推理链代替。评测通过说明满足当前契约，不等于事实绝对正确。

**取舍。** 不照搬企业本体的 OBR 十一模型，不因动态语义需要就引入图数据库/RDF/OWL reasoner；不展示模型隐藏 chain-of-thought；没有已校准预测目标前，不把 LLM confidence 数字化成“人格准确率”。未来只有具体查询、互操作或规则复杂度证明需要时再升级基础设施。


## D17 外部框架作为版本化 Lens 完整运行，不并入原生自我本体

**来源：用户已确认，并以 S30 的 Dan Koe 原始公开资料校正框架内容。** FindMe 可以完整引入 HUMAN 3.0 等外部框架，但这些框架用于提供一种可选择、可回溯的观察方式，不替换 FindMe 基于个人证据形成和修订认识的原生模型。

**决定。** 新增逻辑上的 FrameworkDefinitionVersion、FrameworkRun、FrameworkResult，并由 A9 治理公共定义、A10 负责私人运行。一个框架可以保留自己的维度、等级、提问顺序、adaptive follow-up、报告和发展计划；运行开始后固定具体 definition version，不静默切换。首个目标框架为 HUMAN 3.0，并按 Dan Koe 原始公开版本保留 Mind / Body / Spirit / Vocation、Level / Phase、Lifestyle Archetype、Metatype、Channels 等定义及该版本实际输出的阶段计划，不把 Vocation 简化成单一“经济象限”。宣传段与实际计划区间的差异按 R01 核验，不以二手摘要替代原协议。

**语义边界。** “标准框架”表示框架协议完整、版本固定、结果可还原，不自动等于经心理测量学验证的标准测评。HUMAN 3.0 的 Level / Phase 只在对应框架内部解释；S30 已提供可核验的原作者公开框架与 Assessment prompt，但具体内容复制、改编和产品内再发布的授权边界仍需确认，未完成前只发布 draft/needs_review 定义。

**与原生认识的关系。** 框架回答与结果共享来源血缘，不重复计证；FrameworkResult 始终标为 framework-scoped，不能直接覆盖 Current Understanding。只有经 A5 按证据、反例、范围重新验证的候选解释才进入 Claim/ClaimRevision。框架计划先进入 ActionProposal，用户接受后才成为 ActionTrial。

**取舍。** 接受 A8 结构化测评与 A10 框架运行并存，换取方法边界清晰和未来可插拔扩展；不建设“超级统一人格模型”、框架 marketplace 或跨框架总等级。

## D18 洞察分析采用可复核的 Reframe–Structure–Tension–Hypothesis Profile

**来源：本轮对 FIRE 案例及高质量评论分析过程的产品抽象，并延续 D7 的证据化批判与 D16 的认识形成策略。** 有价值的部分不是某个具体结论，而是从表面问题重新定义、整理生活结构、发现内部张力、提出竞争假设，再用追问或现实体验区分解释的过程。

**决定。** 在 A4/A5 现有 Epistemic Policy 中增加 Insight Analysis Profile。标准可见产物为 presented problem、problem reframe、life-structure gap、tension、candidate hypothesis、alternative explanations、discriminating question，以及可选 experiment candidate；每项需绑定依据、范围、反例/替代解释和 change condition。

**持久化。** 不新增平行的 Insight 真值库。通过 validator 的 reframe/tension/hypothesis 仍写为 Claim/ClaimRevision；未决解释进入 KnowledgeGap；现实验证候选进入 A6；LifeStructureView/TensionView 只是当前认识投影。GenerationRecord 保存结构化结果、版本和输入指纹，不保存模型隐藏 chain-of-thought。

**边界。** Life Structure 是从真实生活长出的开放结构，不预设统一人生清单；Tension 必须有两端证据，不代表缺陷或必须消除；分析不能从“可能缺某种意义来源”直接跳到唯一行动处方。区分力不足时优先保留未知或设计验证，不用更强措辞制造洞察感。

**取舍。** 这套 profile 提升原生 FindMe 的分析 intelligence，而不是引入另一套理论体系；其质量通过 reframe 忠实度、替代解释、反例响应、范围纪律和验证价值评测，不以文案深刻感或模型自报置信度验收。


## D19 AV 本人内测验证归属与修订，不作为永久产品主线

**来源：用户已确认执行。** 以已有 AV 人工交互材料开始本人内测；长段粘贴转发不直接视为用户创作或观点。接受共享抽象策略，借鉴 TencentDB 的分层与增量而不恢复旧运行链。

**决定。** AV 内测先分清作者、谈论对象、本人立场和情境，再建立共享证据，由原生洞察与后续框架按需消费。该验证策略继续保留；后续已授权的全量加工按对应契约限定，当前诊断研究与产品化优先级由 Roadmap 统一管理，不再由小批内测决定长期排期。

**执行边界。** 首轮在仓库外独立 staging 保存冻结原文、候选、审核、调用账本和可重建视图；只读 AV，不改线上数据或启动旧服务。staging 不是平行正式个人模型，进入 Core 需保留来源与修订并经过接入规则。样本规模、操作和验收由 AV 内测契约单点定义。

**验收。** 归属错误和证据失效属于需修复的基础错误；解释合理性、遗漏、反例响应、有用性与成本分别评估。本人认可不等于独立证实，模型判断不替代真实内测 verdict，留出材料不用于调优。


## D20 以个人发展诊断为产品出口，先建立方法论选型基线

**适用范围更新（2026-10-30）。** 以下保留当时收敛为可读综合判断的理由与决定。D24 将个人发展诊断明确为赛博分身的一种交付形式；综合判断、方法质量与修订责任保留，“诊断优先”不再统领所有对话、学习或长期定位。

**来源：用户已确认。** 用户需要综合理解现状、优势、关键张力与发展方向，不应被要求先阅读或审核 L1–L3 才获得价值。

**决定。** 诊断优先，证据按需展开，原生探索与关键追问服务诊断和修订。以方法谱系、共同矩阵和同案对照形成方法论地图、方法组合决策、参考诊断与输入契约；具体研究成果及局限以 R0 文档为准，不把研究建议当作真人效度或默认框架已获验证。HUMAN 3.0 完整独立接入方向保留，是否默认及适配方式由比较决定。

**取舍。** 不采用多框架投票、统一人格总分或摘要不断再摘要；零/少量/丰富历史都要有用。发展诊断与临床诊断明确区分，评级与证据充分性分开；无需改动是合法结论。已有研究复用，后续新方法先做增量差异评估，不持续重开主线。

## D21 云端权威数据与账号多端为默认产品形态

**来源：用户已确认。** 产品需要可分发且不依赖所有者常开的电脑、AV 原档或个人 Codex 登录。

**决定。** 正式结构化业务数据以云端 PostgreSQL 为主库；大原档按授权托管到对象存储或保留本地，已同步证据与未同步原档的可用性分开；检索索引可重建，设备用于缓存、草稿、待同步操作和可选采集。手机/电脑共用服务端诊断、版本与反馈，L1–L3 不对应三套数据库。

**取舍。** 保留现有技术栈和客户端工程，不优先引入独立文档库、向量服务、图数据库、完全离线同步或自托管发行版。本机 CLI 继续作为私有研究出口，但不能成为普通用户使用前提。原档只保留本地时不能承诺随时全文回查；关键诊断需基于已授权可用证据。

**执行边界。** 本次只更新文档和代码计划。实际账号 provider、对象存储资源、迁移/恢复和正式模型能力在切片中核验；不自动创建资源、迁移私人数据或上线。


## D22 保持找我目标，以整体个人理解与统一 App 验收已有 AV 交付

**当前关系（2026-10-30）。** 整体理解、内容覆盖与统一 App 的交付义务保留；第一阶段可在有界覆盖上先形成持续使用，不得据此把本文未完成的全量 AV 与框架义务标为已完成。整体定位及阶段关系见 D24。

**来源：用户已确认。** 需要把已有 AV 充分加工为可直接阅读、追问和修订的个人理解；不接受用分层数据、少量局部诊断或多个调试入口替代最终产品。

**决定。** “不只打标签”是明确标签/画像/框架/诊断/探索的分工，不是取消画像、等级报告或转向纯聊天。自我理解本身可有价值，不要求每次行为改变。全量固定输入快照与用途，先查内容覆盖和重要遗漏，再组织有来源的情境、专题和总览，对旧结果按当前规则校正，最后在现有 App 主导航呈现并接真实修订。

**完成口径。** 加工覆盖、内容覆盖、理解基线、App 闭环及真人效用分别验收，定义见 BA §4.10；一个 complete 标记、五条汇总、样例通过或模型审核不证明全部完成。保留未知，但不以未知掩盖未处理。

**框架与数据。** HUMAN 3.0 继续完整独立接入，框架入口或历史适配不冒充完成原协议。正式主库、多端和原档职责不变；本人验收的运行路径由 D23 确定为账号模式，不打包私人语料进静态站点，也不将临时文件视为正式云端真源。

**取舍。** 优先承接已有加工、研究、诊断契约和复评能力，不再优先扩展演示或无差别重算全部原文。新方法只按真实缺口评估，局部未知不阻断有依据的部分交付；实际源码顺序在代码计划、已实现状态在 As-Is，真实迁移/部署仍单独执行。

## D23 账号模式云端数据库为唯一运行真源，其余运行路径冻结或退役

**来源：用户已确认。** 同一份个人理解曾分散在 Legacy V1、本机 dogfood/U2 流水线、本机 U3 私有仓储、Neon 归档快照与账号模式中，各自有读取、修订和生命周期代码；单人内测只需要一条可验证修订确实生效的路径。

**决定。** 账号模式（`schema-auth`/`schema-platform`/`schema-diagnostic` 及同库 Core 表，经 Profile scope 与运行角色访问）是唯一运行真源，承接阅读、回应、复评修订、框架、导入、导出与删除。原生单次探索的 Core 表在同一数据库内经同一 scope 使用，不另立真源。

- **已通过的 U2 专题一次性导入，不重新生成。** 新增一次性导入通道，把已独立审核通过的专题版本连同原审核记录、精确证据与来源指纹写入账号模式；导入版本标明来自 U2 审核，不冒充在账号模式内重新审核。未通过的候选、未成稿专题与 overall 不随导入提升资格，后续在账号模式内按正常处理链完成。
- **快照只读接口为过渡。** `archive-runtime` 及其路由只在账号模式本人入口可用之前提供阅读；导入完成并在账号模式核对一致后退役，两张归档表随后纳入统一导出/删除或另行处置。
- **本机 U3 私有仓储、本机 dogfood/U2 流水线与 Legacy V1 冻结。** 冻结指保留代码与既有数据、不再新增功能或接入新入口；需要的产物只经导入进入真源。冻结不等于删除，代码、表或数据的实际退役各自另行授权。

**取舍。** 选择功能最完整且符合 D21 的路径，代价是生产库须首次应用账号模式迁移与访问策略、本人账号须有不依赖邮件的开通方式，以及新写一段导入代码。放弃“重新生成”以避免模型费用、DeepSeek 凭据依赖和结果漂移；放弃以快照或本机仓储长期运行，以免修订只在某一条路径上生效。

**执行边界。** 本决定只更新文档。生产迁移、导入执行、服务恢复与部署、旧路径的实际删除均按具体范围另行确认。

## D24 赛博分身作为愿景，先形成可持续使用的个人理解

**来源：用户于 2026-10-30 本轮对话明确确认并要求更新仓库。** 理想未来是另一个硅基分身：持续了解本人，判断不受情绪、面子或讨好驱动，能开导、建议，检验自欺、自我美化与过度自责，并结合学术知识帮助本人认识和引导自己。对话、学习与导入语料是构建过程和方法；具体技术方案留待下一阶段依据当时能力评估。

**决定。** 赛博分身为整体愿景；持续深入、可纠正的个人理解是基础；自我认识、支持、建议与诚实挑战是贯穿各阶段的核心价值。个人发展诊断、报告、专题、总览和个人使用说明是交付与使用这份理解的方式。保留 D1/D11/D22 的认识、三观与完整交付要求，不把积累语料、模仿口吻或生成报告本身作为成功。

**判断要求。** 了解本人不等于认可本人所有解释；依据充分时可直接指出矛盾和可能的自我辩护，也应检验过度自责和系统误读。理论提供解释与探索方法，不自动证明个人隐藏动机。客观性以事实忠实、对称检验、反例响应和可纠正性验证，不以“硅基”“没有感情”或用户赞同宣称已成立。

**技术与架构。** Agent＋人格蒸馏 Skill 仅是用户举出的可能形式，不构成需求、架构冻结或必经路线。复用当前来源、证据、认识、反馈、版本和统一 App 资产；未来技术选择由具体需求、当时能力和实测效果决定，不因愿景澄清重建技术栈。

**第一阶段。** 按[范围与验收](delivery/phase-1-personal-understanding.md)贯通有界理解基线、持续对话、新信息更新、有效纠正、支持/挑战、有限来源化知识和本人实际使用。它是可用基础，不宣称完整分身已经形成。既有 AV 整体理解和 HUMAN 3.0 等未完需求保持独立可追踪；不把全部后续能力作为第一阶段前置。

## D25 直接退役两个独立客户端，统一使用 apps/app 浏览器入口

**依据。** 2026-10-31，用户明确决定“直接把另外2套先清理；app支持H5/浏览器”；这里另外两套为 `apps/web` 与 `apps/miniapp`。这是真实的新决定，不沿用原报告评分或工期。

## D26 对话使用 Core 当前认识并自动处理新输入

**来源。** 2026-10-31，本人对下一轮建议的两项产品语义选择了推荐方案：对话怎样使用当前理解（决策 5）、新输入处理是否自动调用模型（决策 6）；同时确认本轮只做设计与主链代码，不部署，运行资源后置。

**决定。** 普通对话以 Core 当前有效认识为唯一个人认识来源，按相关性有界选取，并显式带上已撤回或失去依据、不得作为前提的项目；诊断报告和知识专题只作为呈现与导航，不作为第二个回答依据。账号模式下对话处理与纠正自动执行，不需逐次确认；限制为每次操作的尝试上限，以及每个 Profile 滚动 24 小时的操作上限，该上限默认 0（关闭），只有服务端推理总开关打开且显式配置后才生效。

**取舍。** 单一来源避免报告和对话各自漂移，代价是已审核的报告正文暂时不直接参与回答，需要等工作包 5 再评估引用方式。自动处理减少确认负担，代价是费用由服务端上限而不是逐次确认来约束；超限时不调用模型，已保存的输入不受影响。云端诊断任务保留原有逐任务确认，不受本决定影响。

**边界。** 设计与实现契约见[第一阶段主链](implementation/p1-main-chain.md)。本决定不选择运行资源，不授权部署，也不改变 P1 接受状态。

## D27 单节点运行、单一结构定义与本人输入统一保存

**决定。** 应用只以单节点方式运行：一个 Node 进程提供网页、API 与进程内执行器，数据库为任意 PostgreSQL（默认同节点容器）；旧的静态/会话/私有模式与 Cloudflare/Neon 专用路径移除。表结构只保留一份当前定义 `packages/db/schema.sql`，只在空库建表，已有库结构不符时部署停止，不保留变更历史。模型服务商、密钥与预算是存于数据库的应用设置。本人输入只在 `source_items` 保存一份，各功能引用来源编号；登录身份与实例网址无关。

**取舍。** 运行与数据的位置单一，换节点只需带走数据库与原档目录；代价是本版本不自动转换旧库，结构变化时需另行处理已有数据。

**边界。** 不选择外部加工引擎，不改变 D23 的账号模式真源地位；运行入口见[单节点部署](../deployment/standalone/README.md)，当前实现见 [As-Is](as-is.md)。
