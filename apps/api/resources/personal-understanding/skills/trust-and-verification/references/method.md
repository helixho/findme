# 信任、验证与再次确认

## 何时使用
用户询问该信任哪个结果、是否再换Agent检查，或讨论反复确认。若出现实际新失败、承诺未满足或安全/业务风险，先处理证据问题。

## 步骤
1. 固定原结论及其承诺范围，不把“完成”扩成整项目可靠。
2. 搜集现有证据：来源、版本、执行者、测试真实覆盖、未测层和报告范围。区分亲自看过的原始结果、工具摘要、agent自评。
3. 对照当前怀疑列出缺口。新检查必须说明将增加什么信息，以及结果会改变哪个决定；合理独立复核可以提供异构视角，但“异构”本身不证明正确。
4. 如果发现具体缺口，做与风险匹配的一次定向验证；若没有新增证据，只是不安重新出现，说明现有证据和未知，避免生成“再保证一次”的结论。
5. 结论按对象/版本限定：支持、部分支持、未验证、被反例推翻。新agent发现的问题逐条验证，既不盲信，也不因切换身份自动重审全部。

## 停止条件
承诺范围已被相称证据覆盖、没有新的失败迹象且剩余不确定不改变当前决定时停止追加复核。高影响风险仍有实际缺口时，不能以“停止确认”代替解决。

## 输出
原承诺；实际新增证据；其覆盖与局限；对具体结论的更新；还会改变哪个决定的未解问题。不给全局人格诊断。

## 来源与边界
- BA §4.3–4.4、§7；DA §3.4、§5；REVIEW.md的风险相称和具体路径证据要求。
- 临床研究提到的重复确认机制只是某些情形的候选解释；没有频率、困扰/功能损害和专业评估时不诊断，不劝停合理工程验证。
